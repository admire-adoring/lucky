# Lucky-Y 架构总览

> 本文档由 2026-11-03 全量重构梳理生成，描述当前工程的模块划分、依赖方向与分层契约。

## 一、技术栈

| 层 | 技术 |
|---|---|
| 桌面壳 | Tauri v2（`src-tauri/`，Rust） |
| 前端 | React 19 + TypeScript 6 + Vite 8 |
| 样式 | Tailwind CSS v4 + 手写 CSS 令牌体系 |
| 数据 | TanStack Query v5（服务端状态）+ Zustand v5（客户端状态） |
| 路由 | React Router v7（HashRouter） |
| 后端存储 | rusqlite（bundled SQLite）+ 本机钥匙串（凭据） |

## 二、目录结构与职责边界

```
lucky-jarvise/
├─ src/                        前端
│  ├─ api/                     数据访问层（invoke 只出现在这里）
│  ├─ hooks/                   TanStack Query 钩子（组件只读这里）
│  ├─ pages/                   路由页面（workspace/ 下为九域工作区）
│  ├─ components/              UI 组件（按功能域分子目录）
│  ├─ stores/                  Zustand 客户端状态
│  ├─ data/                    派生函数 + UI 常量 + 演示种子 + 静态内容
│  ├─ lib/                     纯工具（env/cn/theme/filter/server-view…）
│  ├─ types/                   全局类型定义
│  └─ styles/                  CSS 令牌与样式
├─ src-tauri/                  Rust 侧
│  ├─ src/main.rs              桌面入口（6 行，调 lucky_lib::run()）
│  ├─ src/lib.rs               命令层（61 条命令转发 + ApiError）
│  ├─ src/config.rs            配置读取（config.toml）

│     ├─ store.rs              Store（SQLite 连接池）
│     ├─ db.rs                 迁移（include_str! 引用 design/sql-design/）
│     ├─ error.rs              Error（code: db/io/notFound/conflict/invalid）
│     ├─ srv/                  服务器台账域
│     ├─ project/              项目域（含 account/bug/html 子模块）
│     ├─ task/                 任务域（含 item 子模块）
│     ├─ doc/                  文档域（local_md 正文 + 索引）
│     ├─ work/                 工作域（contact/meeting）
│     ├─ user/                 用户域
│     └─ app.rs                本机数据汇总

├─ docs/                       本文档目录

├─ documents/                  文档正文（.md 落盘）
```

## 三、分层契约（依赖方向）

```
pages/components ──→ hooks ──→ api ──→ invoke ──→ Rust 命令层 ──→ 领域层 ──→ rusqlite
      │                  │       │                                     │
      └── stores         └── data/derive, data/meta（派生/常量）        └── 不 import tauri
```

**硬约束（已有 grep 门禁）：**
- `invoke(` 只出现在 `src/api/` —— 组件不直接调 invoke。
- `use tauri` 只出现在 `src-tauri/src/lib.rs` 与 `src-tauri/src/config.rs` —— 领域层 `src/server/` 不 import tauri。
- `rusqlite` 只出现在 `src-tauri/src/server/` 内。

**data/ 层的定位（不是纯 mock）：**

`src/data/` 是混合层，分三类：

| 类别 | 文件 | 性质 |
|---|---|---|
| 派生函数 | `derive.ts` | 合法 —— 被 `api/projects.ts` 与组件共用，把后端原始行转成展示形态（日期三写法/剩余天数/到期文案） |
| UI 常量 | `meta.ts` | 合法 —— 状态色/优先级/可见性等枚举映射，跨层共用 |
| 导航配置 | `workspace/nav.ts`、`workspace/tabs.ts`、`workspace/shell-nav.ts` | 合法 —— 路由表与分区注册表 |
| 演示种子 | `projects.ts` | 浏览器回落 —— Tauri 不可用时 `api/projects.ts` 用它走通 UI |
| 静态内容 | `workbench-content.ts`、`ai/*`、`content-pool.ts` | 无后端支撑的功能（AI 助手/工作台磁贴）的内容源 |

## 四、双路数据分派

`api/*.ts` 的每个函数按 `isTauri()` 分两条路：

- **Tauri 窗口**：`invoke('cmd')` 打真实 SQLite 库，经 `call()` 统一错误封装成 `ApiError`。
- **浏览器**（vite dev / dist 预览）：回落 `data/` 演示种子，带 260ms 模拟延迟，UI 整页走通。

判据在 `lib/env.ts`：`'__TAURI_INTERNALS__' in window`。

## 五、错误协议

```
领域层 Error::code()          ──→  壳层 ApiError { code, message }  ──→  TS ApiError
(db/io/notFound/conflict/invalid)   (#[serde(rename_all="camelCase")])   (api/error.ts)
```

- `api/error.ts` 的 `call()` 把 invoke 拒绝统一换成 `ApiError`。
- `errorText()` 从任何错误值取展示文案（组件统一用这一条）。
- 页面按 `code` 分支：冲突不关弹窗、找不到退列表、invalid 提示输入。

## 六、设计令牌体系

三层令牌，各管各的命名空间：

| 文件 | 命名空间 | 职责 |
|---|---|---|
| `design-tokens.css` | `--c-*`、`--radius-*`、`--transition-*`、`--brand-solid` | 状态色/圆角/动效/品牌实底（主题相关） |
| `index.css` (@theme) | `--color-*` | Tailwind 主题色（brand/ink/scope 三域色） |
| `module-workspace.css` | `--mw-*` | 九域模块色（每域 accent 三档 + strong + line） |
| `prism.css` | `--fg/--bg/--ok/--warn/--bad/--info` | 主题反解（亮/暗色文字色按底衬对比度解出） |

CSS 文件内硬编码的 hex 值是**令牌定义本身**（定义处），消费侧统一走 `var()`（2406 处引用）。

## 八、循环依赖

经检测，`src/data/` 内部互引无环，`api/ → data/` 单向，`hooks/ → api/` 单向，`components/ → hooks/ + data/` 单向。无循环依赖。
