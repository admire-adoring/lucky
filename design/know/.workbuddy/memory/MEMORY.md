# 项目长期约定（知识库模块 / Jarvis 个人系统原型）

## ⛔ 工作区硬约束（2026-09-26 用户要求，永久生效）
1. **不做截图验证**（不启浏览器、不读回像素、不做像素级验收）。
2. **不加额外说明**（不写"我做了什么/依据是什么"的解释段、不写引导语与收尾语）。
3. **不写、不跑任何测试**（不建测试文件、不跑 jsdom / 回归、不执行校验脚本）。
- 冲突处理：skill（`html-ds-delivery-verify` 等）要求截图/测试/验收报告时**在本工作区跳过**，直接交付。
- 边界：只约束**验证与说明**环节，不豁免"改完要同步 `knowledge_features.html`"这类**内容一致性**要求。

## 分区与三级菜单（已落地）
- 一级分区（`knowledge_index.html`）：**笔记 / 收件箱 / 主题 / 标签 / 图谱 / 归档**。
- **谁配三级**：判据三条全过才配 —— ① 有一根"找东西前会先想的那一刀"且 **≥3 类**；② 点下去**内容真的换**；③ **每项可数**。
- 三级项**永远不能是"某一个具体对象"**：主题三级是"组"，标签三级是"状态"，不是 42 个主题名 / 96 个标签名。
- **两种实现别混**：同一份数据的子集 → 行上 `data-*` + `row.hidden`（主题 `data-group` / 标签 `data-state` / 收件箱 `data-status`）；**换一份内容** → `.sub-view[data-view]` + `.active`（图谱 7 种看法）。用错的症状是"点进去面板空白"。
- 加三级分区的**三件套**：① `children`（带 `view` + `count`）；② `setXxxView()` + 计数表；③ `syncSectionView()` 的 `APPLY` 表与 `setSection()` 复位清单各补一笔。
- ⚠️ **复位值必须是合法 view key**：图谱没有 `all`，写 `setGraphView('all')` 会让所有 `[data-view]` 失去 `.active`、**面板空白且不报错**。要回退到默认项。
- 计数要**能对账**（分组之和 = 全库数）；示例只列一部分时给两个数：`技术组 17 个 · 示例 3 个`。
- **分区 vs 筛选的判据**（2026-09-27）：能写成一行查询 = 筛子。收藏 `starred:true` → 已降级为「笔记」内视图；标签 `tag:X` 按此**也该降级，但用户选择「先不动」**（代价：标签分区要真做治理台）。归档 / 主题不是筛子 —— 归档**换池子**（不参与检索/图谱/统计），主题是**实体**（有正文、子主题、可被双链引用）。

## 笔记三层（记录 / 加工 / 生产）
- **不做成三个分区**（互斥：一条笔记会跨层）。三层 = 同一条笔记的**成熟度状态**，纯派生、不新增字段：
  记录 = 还在收件箱 → 加工 = 已归类 + 0 条入链 → 生产 = 有入链。
- 三个症状 = 三个可数断裂点：漏 = `stage=record`；懵 = `stage=process`；调不出来 = `link_in_count>0 / 总数`。
- 落地三处：行上 `.stage` 徽标（`--warn-*` 暖色=未走完 / 主色=已沉淀）· KPI 四卡 · 详情弹窗首段「成熟度 + 差什么才进下一层」。
- 归档行不标成熟度（已冻结）。**不要在知识库加"加工"分区**；加工的动作属于学习/工作模块。

## 两个「笔记」的归属
- 学习模块的笔记 = **过程库**（随来源失效，要复习到期 / 掌握度，升级后移出）。
- 知识库的笔记 = **沉淀库**（脱离来源仍成立，挂概念下，只进不出，用归档代替删除）。
- 分流三问（任一"是"→ 知识库）：删掉来源还成立吗 / 三个月后还会被引用吗 / 它回答"我知道什么"而非"我正在学什么"。
- **复习（SRS）属于学习模块**；「升级为永久笔记」按钮也属于学习模块，不该出现在知识库详情里。

## 用户已确认的两个前提
1. **双链是核心用法** ⇒ 图谱分区保留、必须做链接建议 / 孤儿巡检 / 黑洞巡检。
2. **笔记量级上千条** ⇒ 检索是主入口；列表要游标分页 + 排序 + 多条件筛选；图谱只画局部、全库只出统计；归档要有自动出口。

## 数据模型（`knowledge_model.html`，v1 草案）
7 实体：`note` / `link` / `topic` / `tag`+`note_tag` / `stage_log` / `archive_rule`+`archive_candidate` / `attachment`。
关键决策：① 收件箱 = note 的一个状态，不建独立表；② `stage` 与两个 link 计数存**冗余列**（单一写入路径 + 每日校验兜）；③ `link` 一行 = 一条**有向**边，不存反向行；④ 主题只允许一层父子；⑤ 标签靠合并（`alias_of`）+ 淘汰（`last_used_at`），不做层级，一条 ≤3 个标签；⑥ 归档规则**只产候选、不静默执行**；⑦ 检索是主入口（`tag:` `topic:` `stage:` `has:inlink` `has:nolink` `source:` `before:`）；⑧ 知识库不存复习状态。

## 配色口径：界面色与数据编码色**分开**
- **界面色** = 令牌层：一个域色（知识库 teal `--m-*` / `--mw-m-main`）+ 状态色 `--warn-*` + 中性灰。**不许为"多分组可区分"另开色相。**
- **数据编码色**（图谱节点 / Louvain / 主题 / 标签 / 时间轴色点）= **多色**，取参考件六组模块色：紫 `#D946EF` / 橙 `#F97316` / 青 `#14B8A6` / 绿 `#10B981` / 黄 `#F59E0B` / 蓝 `#6366F1`（暗色各抬亮）。落成 `--kg-c1..c6`，JS 用 `cssVarOf` **现取**（不复刻色值）。另有 `--kg-c-orphan`(红) / `--kg-c-hub`(橙)。
- 三个主题组固定映射：**技术 = 青 / 产品与系统 = 蓝 / 生活 = 绿**（只用于全局图的「主题组」着色模式与时间轴色点）。
- **局部图：颜色 = 主题**（`topicColor()`，按 `TOPIC_GROUP` 固定顺序轮转六色），**半径 = 被引用次数**，
  **不做浓淡**（成熟度不进图，留在右侧详情与笔记列表）。
  - ⚠️ 2026-09-29 从「主题组 + 满色/半色」改过来：主题组只有 3 个，而示例 28 条里 22 条属技术组
    ⇒ 整张图读成一片青，用户看截图说"这一样吗"。参考件的「文件夹」是 6 项，同粒度的是**主题**（9 个）。
  - ⚠️ 更早还用过「空心 = 加工层」—— 同样牺牲主视觉，用户发火。**两次教训是同一条**：
    别把"多表达一个维度"的代价压在整张图的观感上。
- 局部图的图例**只列这张图里真的出现了的主题**（按固定顺序）⇒ 图上颜色与图例永远一致，图例不会有空项。
- ⚠️ **2026-09-28 23:04 我把六色压成 teal 明度阶梯是过度修正**：用户说的「主题色偏离」指的是**模块主色的值**（原型 `#0D9488` vs 应用 `#14B8A6`），**不是"不许用别的色相"**。
  ⇒ 判据：**"主题色对齐"只约束界面色；数据编码色本来就该多色 —— 两件事别混。**
- 唯一例外：`#B91C1C` 危险红（删除按钮 / `.nav-p-badge.warn`）= "危险动作"语义色。
