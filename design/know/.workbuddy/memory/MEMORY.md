## 模块菜单分层的判据（2026-09-25 讨论确认）
1. **互斥**：一条笔记的归属不能有两个默认答案（状态类除外）。
2. **同层同质**：一级分区只装一种性质 —— 内容归属 / 视图 / 状态，不能混排。
3. **有入口承载已有数据**：界面上出现的数字必须有地方承接（如"待整理 5 条"要有收件箱）。
4. **项数按认知负荷定，不按几何定**：圆盘几何上限约 10 项（R_MIN=52 时容器 78px ≤ 218 预算），真正上限是 7±2。
5. **每项可数**：菜单项要能显示计数。

## 笔记三层（记录 / 加工 / 生产）在知识库的体现（✅ 2026-09-25 已落地）
参考图：记录层（解决「漏」· 不加工=抄板书）→ 加工层（解决「懵」· 不链接=用不上）→ 生产层（解决「调不出来」）。
- **不做成三个分区**（违反互斥：一条笔记会同时落在两层）。三层 = 同一条笔记的**成熟度状态**，由现有三个标记机械推导：
  - **记录** = 还在收件箱（未归类）→ 落「收件箱」分区（5 条）
  - **加工** = 已归类 + 0 条双链 → 落「笔记 · 未链接」视图（12 条）
  - **生产** = 有 ≥1 条双链 / 标记永久 → 落「笔记（永久 42）」+「图谱（双链 348）」
- 反过来说：**三个症状 = 三个可数断裂点** —— 漏 = 收件箱 5；懵 = 未链接 12；调不出来 = 双链覆盖（286 条里 12 条没入链）。
- 落地形态（三处）：① 笔记行/inbox 行挂 `.stage` 徽标（`stage-record/process/produce`，暖色=未走完、主色=已沉淀，令牌 `--warn-*`）；② KPI 四卡 = `漏 5 / 懵 12 / 调不出来 274÷286 / 永久 42`；③ 详情弹窗首段显示「成熟度 + 差什么才进下一层」。
- 推导逻辑写在 JS：`NOTE_STAGE` 表 + `decorateStages()`（**不新增数据字段**，纯派生；归档行不标 —— 已冻结）。inbox 行的点击由 JS 绑定，行内动作按钮必须 `event.stopPropagation()`。
- 方法论只进机制、不进菜单：康奈尔/大纲/速记/图表 → 收件箱的来源类型；概念图/思维导图 → 图谱 + 主题；费曼重写/渐进总结 → 「编辑 + 归类」动作，产物是永久笔记；卡片盒 → 双链；常青笔记 → 永久笔记；PARA → 主题 + 归档；子弹笔记 → 收件箱 + 待办。
- 「加工」这一步的**动作**属于学习/工作模块（费曼重写挂在课程/书下面），知识库只显示加工**结果**（未链接 = 没走完）。**不要在知识库加"加工"分区。**
- 校验：jsdom 52/52 PASS（含徽标推导、KPI 数值、弹窗成熟度段、stopPropagation）。

## 知识库一级分区（✅ 2026-09-25 已落地到 `design/know/knowledge_index.html`）
**笔记 / 收件箱 / 主题 / 标签 / 图谱 / 归档**（顺序 = 使用频率 × 任务类型，默认落在「笔记」）。
- **收藏**已降级为「笔记」分区内的视图，与 全部 / 最近编辑 / 未链接 并列（`chips` + 4 个 `.note-view`），并已删除死 CSS `.favorite-*`；收藏的 3 条示例数据搬进了视图，未丢失。
- **圆盘三级子项 = 分区内的视图**：`section.children[].view` + `syncNoteView()`，环上选「收藏」列表就切到收藏 —— 让"收藏是视图不是分区"在交互上可验证。
- **收件箱**是唯一流程入口：5 条待整理，**三级子项 = 全部 / 未归类 / 待补全 / 待提炼 / 待判断**（各带计数），切换靠行上 `data-status` + `row.hidden` 过滤（不复制行，`setInboxView()`）；行内动作 = 归类到主题 / 退回来源；面板内附「整理规则（三问定去向）」，两周未动 → 自动归档。
- **未链接的笔记**（12 条）放在右侧轨 —— 因为它是健康度指标而不是分区；同一数据在「笔记」分区里是视图。
- 笔记详情弹窗的动作已从「升级为永久笔记」改为「归档」（知识库只进不出）。⌘K 里分区 6 项 + 笔记视图 4 项（`data-goto="view:star"`）。
- **搜索 ⌘K / 新建 / 导入剪藏 / 随机回顾**属全局动作，不占圆盘。
- 主题 vs 标签的边界：**能往里"补充说明"的是主题**（人工策展、少、可嵌套双链）；**只能回答"它属于哪类"的是标签**（自发涌现、多、平铺、不做层级）。

## 谁配有一层子菜单（✅ 2026-09-25 已落地，5 配 1 不配）
判据三条，**全过才配**：① 有一根"用户找东西前会先想的那一刀"，且这一刀下来 **≥3 类**；② 点下去**内容真的换**；③ **每项可数**。
| 分区 | 那一刀 | 类数 | 三级项 |
|---|---|---|---|
| 笔记 | 视图 | 4 | 全部 / 最近编辑 / 收藏 / 未链接 |
| 收件箱 | 为什么还没走完 | 5 | 全部 / 未归类 / 待补全 / 待提炼 / 待判断 |
| 主题 | **分组** | 3 | 全部 42 / 技术 17 / 产品与系统 12 / 生活 13 |
| 标签 | **治理状态** | 4 | 全部 96 / 高频 23 / 沉睡 55 / 待合并 18 |
| 图谱 | **看什么** | 4 | 局部图 / 全库统计 / 孤儿巡检 12 / 黑洞巡检 3 |
| 归档 | 阶段 | **2** | ❌ 不配（两块在面板里并列堆叠） |
- **两条容易搞反的**：① 三级项**永远不能是"某一个具体对象"** —— 主题有 42~上百个，三级只能是"组"；标签三级是"状态"不是 96 个标签名。② **"枚举 → chip、对象 → 三级"这条旧规则已作废**：标签三级是纯枚举、图谱四项是"四种看法"，都不该被它否决。判据要按**用户行为**（会不会先切那一刀）定，不按内容类型定。
- **两种实现别混**：同一份数据的子集 → 行上 `data-*` + `row.hidden`（主题 `data-group` / 标签 `data-state` / 收件箱 `data-status`）；**换一份内容** → `.sub-view[data-view]` + `.active`（图谱 4 种看法）。
- **加三级分区的固定三件套**：① `children`（带 `view` + `count`）；② `setXxxView()` + 计数表；③ `syncSectionView()` 里的 `APPLY` 表补一笔 + `setSection()` 的复位清单补一笔。
- ⚠️ **复位值必须是合法 view key**：图谱没有 `all`，统一写 `setGraphView('all')` 会让 4 个 `[data-view]` 全失去 `.active`、**面板空白且不报错**（已踩）。要回退到默认项。
- 计数要**能对账**：分组之和 = 全库数（3 组 = 42；23+55+18 = 96）。示例只列一部分时文案给两个数：`技术组 17 个 · 示例 3 个`。
- 校验：jsdom 47/47 PASS（6 分区 `data-has-children` 真值、主题 9→3→9、标签 19→6→5、图谱 4 种看法与默认项、巡检条目可开详情、切分区复位、归档不下钻、图标去重、下方栏与笔记视图无回归）。

## 两个「笔记」的归属判据（2026-09-25 讨论确认）
- 学习模块的笔记 = **过程库**：随来源（课程 / 书 / 项目）结束而失效，挂在学习对象下，要复习到期 / 闪卡 / 掌握度，升级为永久笔记后**移出**。
- 知识库的笔记 = **沉淀库**：脱离来源仍成立（结论 / 经验 / 产出），挂在概念下（主题 / 标签 / 双链），要能被引用 / 检索 / 归档，**只进不出**。
- 分流三问（任一"是"→ 知识库）：① 删掉来源后还成立吗？② 三个月后还会被引用吗？③ 它回答的是"我知道什么"而不是"我正在学什么"？
- **复习（SRS）属于学习模块，不进知识库**：到期与掌握度绑在学习目标上，与"内容归属"无关；知识库只保留无状态的"随机回顾"。
- **「升级为永久笔记」按钮属于学习模块**，不应出现在知识库的笔记详情里（永久笔记的归宿就是知识库，语义自相矛盾）。

## 用户已确认的两个前提（2026-09-25，影响所有后续设计）
1. **双链是核心用法**（不是点缀）⇒ 图谱分区保留；「加工层 = 0 条双链」判据成立；必须做链接建议 / 黑洞巡检 / 孤儿巡检。
2. **笔记量级上千条** ⇒ 检索是主入口、浏览是次要入口；列表必须游标分页 + 排序 + 多条件筛选；成熟度必须自动推导 + 批量处置；图谱只能画局部（中心 N 跳），全库只出统计；归档必须有自动化出口（否则"只进不出"堆积）。
   ⇒ 由此**作废**两个早期假设：主题 42 个平铺（上千条下应到上百个，要一层分组）、标签点一下就筛（几百个标签要先治理）。

## 数据模型与分流规则（v1 草案，✅ 2026-09-25 产出 `design/know/knowledge_model.html`）
7 个实体：`note` / `link` / `topic` / `tag`+`note_tag` / `stage_log` / `archive_rule`+`archive_candidate` / `attachment`。
**8 个关键决策（含判据，别推翻前先读理由）**：
1. **收件箱 = note 的一个状态**，不建独立表（id 全程不变，否则双链/附件/历史全断）。
2. **`stage` 与两个 link 计数存冗余列**，由规则重算（上千条下要按 stage 筛排分页；代价用"单一写入路径 + 每日校验告警"兜）。
3. **`link` 一行 = 一条有向关系，不存反向行**（存两份必然出现单向幽灵链接）。
4. **主题只允许一层父子**（`parent_id`），禁止无限层级（会变成第二个标签体系）。
5. **标签靠合并（`alias_of`）+ 淘汰（`last_used_at`）治理**，不做层级；软约束一条笔记 ≤3 个标签。
6. **归档规则只产出候选清单，不静默执行**（例外：收件箱可自动归档，但必须在顶部留"已自动归档 N 条 · 撤销"）。
7. **检索是主入口**，v1 谓词语法：`tag:` `topic:` `stage:` `has:inlink` `has:nolink` `source:` `before:`。
8. **知识库不存复习状态**（只留 `last_viewed_at`），SRS 归学习模块。
状态推导（可直写 SQL，见文档 4.2）：`archived_at` 非空 → 归档；`topic_id` 空 → 记录；`link_in_count=0 且非常青` → 加工；否则 → 生产。
三个断裂点口径：漏 = `count(stage=record)`；懵 = `count(stage=process)`；调不出来 = `count(link_in_count>0)/count(*)`。

## 置信度分层（2026-09-25 用户问「这些合理吗」时给出的诚实分层）
**A 类 · 判据推导，可放心按它做**（换了领域也不变）：
- 三层成熟度不做分区（互斥）；收件箱是唯一捕获口（有入口承载已有数据）；主题 vs 标签的边界；收藏降级为视图（同一概念不出现两次）；复习/SRS 属于学习模块；知识库只进不出、用归档代替删除。
**B 类 · 我的任意选择，随时可改且改起来便宜**：
- 6 个分区的具体项与顺序、配色（teal）、示例数字（286/42/96/348）、KPI 文案（"漏 / 懵 / 调不出来"）、示例笔记文本。
**C 类 · 必须用户输入才知道，我无法替他定**：
1. 他到底用不用**双链**（决定图谱分区是否白占 1/6 圆盘，也决定"加工层 = 0 条双链"这条判据是否成立）；
2. 真实**笔记量级**（286 是编的；若只有 80 条，42 个主题就不合理）；
3. 归档是**手动还是自动**（"两周未动自动归档"是危险默认，会静默丢内容，目前只是文案）。
**明确不建议**：在 C 类未定之前，把 30 条功能当成"最终形态"去实现 —— 该阶段成本最高的是数据模型，不是界面。
