知识库模块 · 功能说明书

知识库模块 · 功能说明书

这份说明对应原型 knowledge_index.html。逐项给出每个功能的作用、 适用场景、操作步骤与注意事项。 每条都标注状态：已实现 能在原型里真的点出结果； 仅界面 只有视觉，未接数据； 演示提示 点了会弹一句占位提示。

定位：沉淀库 6 个一级分区 27 项功能 纯色令牌 · 亮/暗双主题 单文件 HTML · 零依赖

1模块定位与模型

先定边界，再谈功能。这一章回答"什么内容该进知识库"，后面所有功能都是它的实现手段。

01

知识库 = 沉淀库（不是过程库）

定位
作用

存放脱离来源仍然成立的结论、经验、产出，让其在三个月后还能被引用与检索。

适用场景

课程结课后仍要用的结论；项目结项后脱敏的通用经验；跨模块复用的一句话判断。

与「学习模块的笔记」的分界（分流三问，任一「是」→ 进知识库）
  1. 删掉来源（课程结课 / 项目结项 / 书读完）后，它还成立吗？
  2. 三个月后还会被引用吗？
  3. 它回答的是「我知道什么」，而不是「我正在学什么」吗？
注意事项
  • 同一条笔记只能存在一处：两边各存一份就要两处维护，必然漂移。
  • 「复习 / 到期 / 闪卡」属于学习模块（状态绑在学习目标上），知识库不做 SRS，只保留无状态的「随机回顾」。
  • 「升级为永久笔记」这个动作属于学习模块；在知识库里对应的动作是归档（只进不出）。
02

成熟度三层：记录 / 加工 / 生产

已实现
作用

把「漏 / 懵 / 调不出来」三个症状变成三个可数的指标，并让每条笔记自带成熟度。

适用场景

判断"我的库是不是健康的"；决定今天该整理收件箱还是该去补双链。

状态如何推导（不新增数据字段，由现有三个标记推出）
状态判据落点
记录还在收件箱（未归类）收件箱分区 · 5 条
加工已归类，但 0 条双链笔记 · 未链接视图 · 12 条
生产有 ≥1 条双链 / 标记永久笔记（永久 42）+ 图谱（双链 348）
注意事项
  • 三层不能做成三个分区：一条笔记会跨层，做成分区就违反「互斥」，菜单会出现两个正确答案。
  • 「加工」这一步的动作（费曼重写、渐进总结）属于学习 / 工作模块，知识库只显示加工结果（未链接 = 没走完）。
  • 归档行不标成熟度 —— 已冻结，标了反而误导。

2全局外壳：随时可用的 6 项

这些功能不属于任何分区，任何界面下都可操作。它们的共同职责是"让人在系统里定位与跳转"。

03

顶栏一级模块胶囊

已实现
作用

9 个模块的总入口，当前模块用实底胶囊标出；标题带待办徽标（任务 5 / 工作 2 / 项目 4）。

适用场景

需要跨模块跳转，或想确认"我现在在哪个模块"。

操作步骤
  1. 鼠标悬停胶囊 → 自动展开该模块的二级清单（超级菜单）。
  2. 点「知识库」→ 回到本模块并把内容复位到「笔记」分区。
  3. 点其他模块 → 弹出提示，不切换。
注意事项
  • 只有知识库能承载内容；点其他模块不改选中态、不换色、不重建圆盘，避免顶栏指着一个没有内容的模块。
  • ≤1140px 时非当前项只留图标；≤900px 连侧栏一起隐藏，二级改从超级菜单进。
04

超级菜单（二级下拉）

已实现
作用

列出当前模块的二级清单，并高亮"你正在哪一项"；是最快跳分区的方式。

适用场景

窄屏（侧栏已隐藏）时的唯一二级入口；也知道某模块下都有什么。

操作步骤
  1. 悬停任一模块胶囊（≤900px 改为点击）→ 面板展开。
  2. 点面板里的分区名 → 直达该分区并高亮。
  3. 点「全部 ›」→ 跳到该模块的第一项。
注意事项
  • 面板必须挂在顶栏容器上（导航条是横向滚动容器，放进去会被裁）。
  • 非本模块的条目点了只提示，不改变当前状态。
  • 面板位置会按触发项居中，并夹在顶栏范围内（末项「设置」不会越界）。
05

面包屑与页级动作

已实现
作用

显示「知识库 / 分区（/ 视图）」路径，并给两级返回；右侧放两个页级动作。

适用场景

下钻到三级视图后想退回分区；或从任何地方快速搜 / 新建。

操作步骤
  1. 点路径中非末段的 chip（如「笔记」）→ 返回二级。
  2. 点 ⌘K 搜索 → 打开命令面板。
  3. 点 + 新建笔记 → 目前弹演示提示。
注意事项
  • 末段是当前项，不可点（点了什么也不该发生）。
  • 页面大标题不写在这里：分区内容自带标题，再写一遍同一个词会在一屏出现三次。
  • 路径下方那行是「义」（一句话说明），而侧栏头部给的是「量」（条数）——两处各说一件事。
23

命令面板 ⌘K

已实现
作用

键盘直达任意分区、任意笔记视图，以及 8 个其他模块（提示用）。

适用场景

手不离键盘；或忘了某个分区叫什么名字时按名字搜。

操作步骤
  1. 按 ⌘K（或点顶栏左上角 J、放大镜图标）打开面板。
  2. 在「知识库 · 一级分区」组里选分区。
  3. 在「知识库 · 笔记视图」组里直接进「收藏 3」这类视图（它不占圆盘，但必须可达）。
注意事项
  • 视图选项会先切到「笔记」分区再切视图 —— 视图依附于分区，不能单独存在。
  • 面板里出现的每一条都必须能真跳到目标，否则不如不放。
24

键盘导航

已实现
作用

不用鼠标走完整条导航链路：切分区、下钻、返回、关浮层。

适用场景

批量整理时反复在分区之间来回；无障碍操作。

按键一览
按键行为
← →在圆盘上前后移动，同时切换内容（不需要再按一次确认）
Enter二级：进入当前分区的下一层；三级：返回二级
Esc / Backspace三级 → 二级
Esc关闭浮层（命令面板 → 笔记弹窗 → 超级菜单，按序各关一层）
⌘K开关命令面板
注意事项
  • 焦点在输入框里时，方向键与 Esc 让位给输入，不劫持。
  • 「Enter 下钻」只对有下一层的分区生效；对无下一层的分区，按了不会有任何变化（不假装有）。
25

深浅主题切换

已实现
作用

整套令牌在亮 / 暗两套实色间切换，选择记忆在本地。

适用场景

夜间整理；给评审看两种底色下的可读性。

操作步骤
  1. 点顶栏月亮 / 太阳图标切换。
  2. 刷新后保持上次选择（也可用地址栏 ?theme=dark 强制）。
注意事项
  • 没有半透明材质、没有模糊、没有 color-mix：所有颜色都是成对的实色令牌，实测对比度分别达标（文字 ≥4.5:1，图形 ≥3:1）。

3圆盘侧栏：定位与切换

侧栏是知识库的"骨架"。展开态是圆盘，收起态是图标列，两者同一份数据，只是排列不同。

06

圆盘（分区导航）

已实现
作用

6 个一级分区的唯一主入口。当前项会沿半径向外"咬合"5px 并带脉冲圈，一眼看出在哪一格。

适用场景

每次切分区；也是"我在库的哪个位置"最直观的读数。

操作步骤
  1. 点环上任一图标 → 只切换内容，不下钻。
  2. 再点当前这一项 → 下钻到它的视图（如「笔记」的四个视图）。
  3. 悬停 → 图标放大并出底色，同时下方名称条显示"名称 · 计数"。
注意事项
  • 6 个分区的顺序是「使用频率 × 任务类型」：日用在前（笔记 / 收件箱），周用居中（主题 / 标签），偶尔用在后（图谱 / 归档）。
  • 每个分区必须有自己的图标：圆盘上只剩图标，缺一个名字就会静默落回同一个兜底图形（6 项全一样）——原型里已加警告与断言防复发。
  • 环半径与图标尺寸由项数推导（6 项时 52px / 36px，容器 160px，上限 218px），加分区前先算，别只凭感觉塞。
07

中心门与分段刻度弧

已实现
作用

中心门 = 进入当前分区的下一层 / 返回上一层；外圈刻度弧 = 「共几格、走到第几格」，已过的段填实色。

适用场景

想看某分区的视图清单（如"未链接的笔记"）；或确认自己在第几格。

操作步骤
  1. 在二级点中心门 → 进入当前分区的视图层。
  2. 在三级点中心门（或按 Esc）→ 返回二级。
注意事项
  • 只有真有下一层的分区才显示底部小圆点，也才允许下钻：笔记（4 个视图）、收件箱（5 个状态）有；主题 / 标签 / 图谱 / 归档没有。
  • 刻度弧的未填充格是纯装饰，不承担对比度门槛；已填充格代表"走到第几格"，口径写在 arcStops() 里。
08

悬停名称条（带计数）

已实现
作用

悬停图标时，在圆盘正下方显示「名称 · 计数」，解决"只有图标认不出"和"值不值得点"两个问题。

适用场景

不熟悉图标含义时；判断"收件箱现在堆了多少"。

操作步骤
  1. 把鼠标移到任一图标上（或用 Tab 聚焦）。
  2. 读名称条：如「收件箱 · 5」「笔记 · 286」。
  3. 移开即消失，不占布局。
注意事项
  • 名称条固定在圆盘正下方一条，不做沿角度外推的气泡：极坐标定位必然让宽名字在最左 / 最右与图标叠压或被侧栏裁掉。
  • 显隐只用透明度与位移，任何时候不改变其他元素的尺寸（否则会连累几何验收）。
09

收起态图标列（rail）

已实现
作用

侧栏收成 64px 后仍能切分区：图标竖向排列，悬停出带计数的提示，激活项左侧有指示条。

适用场景

屏幕窄、或正文需要更多横向空间时。

操作步骤
  1. 点侧栏底部收起按钮 → 圆盘换成图标列。
  2. 悬停图标看提示（含计数）。
  3. 点当前项也能下钻 —— 收起态看不到中心门，所以这个动作必须在这里也能做。
  4. 再点底部按钮展开。
注意事项
  • 提示要浮到侧栏之外，因此这一层不能裁切；也不能给图标列加滚动（一加滚动就会把提示切掉）。矮窗口靠压缩图标节奏容纳。
  • 展开态与收起态共用同一份数据与点击逻辑，避免"两种形态看到的内容不一致"。
10

侧栏头部（模块名 + 量）

已实现
作用

常显「知识库」+ 当前分区的量，如「286 条笔记 · 12 条未链接」「5 条待整理」。

适用场景

每天扫一眼就知道该不该整理；不用先点进分区。

注意事项
  • 这里只给「量」，「义」（一句话说明）放在页头副标题 —— 两处各说一件事，否则侧栏、面包屑、副标题会同时出现"笔记"。
  • 收起态下头部整块隐藏，信息不丢（名称条与提示里都有）。
11–14

圆盘下方栏：今日 / 最近 / 快捷

已实现 快捷按钮仅界面
作用

圆盘下面三个 tab，各回答一个问题：现在该做什么（带计数，可点直达）、刚做过什么（浏览历史）、把东西收进来。

适用场景

打开知识库的第一眼（默认落在「今日」）；整理完收件箱后顺着"未链接"继续补双链。

三个 tab 的内容与去处
tab内容操作
今日（默认）收件箱未整理 5 / 未链接的笔记 12 / 归档候选 37点一行 → 分别直达收件箱分区、笔记 · 未链接视图、归档分区（候选清单在那一屏）
最近4 条最近打开过的笔记（浏览历史）点条目 → 打开笔记详情（浏览历史，与「最近编辑」视图不是一回事）
快捷新建笔记 / 新建主题 / 归类收件箱 / 随机回顾 / 导入剪藏 / AI 助手点按钮 → 目前是演示提示
注意事项
  • 不放资产统计：KPI 数字在圆盘计数、侧栏头部、主区四卡已经出现三次，再放第四次就是噪音。原来那个「KPI 槽」因此被删（也顺手修掉了"主区与侧栏两套数字"的隐患）。
  • 每个计数必须能点进去，否则它只是装饰（判据：可数且可达）。
  • 默认 tab 是「今日」而不是「最近」：这块的第一职责是提醒今天该处理的事。
  • 「今日」是今天该面对的三类待办的口径（收件箱 / 未链接 / 归档候选都是存量队列），不是"今天创建"或"今天到期"。若要按真实日期口径算，这三行得换成带时间范围的数字（如"今日新增 3 条待整理"）。
  • tab 上这个「最近」= 浏览历史（我刚打开过哪几条），与笔记分区里的「最近编辑」视图（内容最近被改过）不是一回事 —— 两个"最近"靠所在位置区分，不要当成同一个。
  • 切 tab 只切换本块内容，不改变"我在哪个分区"；侧栏收起时整块隐藏。
  • 标签改短后三个 tab 合计约 145px（侧栏内容宽 218px）：还能再放一个二字标签，四个字以上就会被挤到横向滚动。

4六个分区：内容都放在这里

分区的划分只有两种性质：内容归属（笔记 / 主题 / 标签）与流程状态（收件箱 / 归档）；图谱是唯一的关系视图分区。分区的"视图"一律不占圆盘。

谁配有一层子菜单（圆盘三级）

三条判据，全过才配：① 该分区的内容有一根"找东西前会先想的那一刀"，且这一刀下去 ≥3 类；② 点下去内容真的换（不是只换高亮 / 面包屑）；③ 每项可数。逐项判定：

6 个分区的判定结果
分区那一刀是什么类数结果
笔记视图（全部 / 最近编辑 / 收藏 / 未链接）4✅ 有三级
收件箱为什么还没走完（未归类 / 待补全 / 待提炼 / 待判断）5✅ 有三级
主题分组（技术 / 产品与系统 / 生活）3✅ 有三级
标签治理状态（高频 / 沉睡 / 待合并）4✅ 有三级
图谱看什么（局部图 / 全库统计 / 孤儿巡检 / 黑洞巡检）4✅ 有三级
归档阶段（已归档 / 候选清单）2❌ 不足 3 类，两块在面板里并列堆叠
四条硬约束
  • 三级项永远不能是"某一个具体对象"：主题有 42~上百个，把主题名塞进环上就废了 —— 所以主题的三级是分组，不是"某个主题"。同理，标签的三级是"状态"而不是 96 个标签名。
  • 两种实现别混用：同一份数据的子集 → 行上 data-* + row.hidden（主题分组 / 标签状态 / 收件箱状态）；换一份内容 → .sub-view[data-view] + .active（图谱的四种看法）。用错的症状是"点进去面板空白"。
  • 三级项数上限 7±2（圆盘几何上限约 10），超过就合并同类。
  • 离开分区时视图要复位，否则从"收件箱 · 待补全"切走再回来会停在过滤态，像丢了数据。⚠️ 复位值必须是该分区合法的视图名：图谱没有"全部"这个视图，复位值要落到默认的"局部图" —— 否则四个子视图会被一起关掉、面板全空（已踩过一次）。
15

笔记（主库）

已实现
作用

库的主体（286 条）。四个视图都是同一列表上的筛选：全部 286 / 最近编辑 / 收藏 3 / 未链接 12。

适用场景

找一条已知笔记；看最近改了什么；专门找"该补双链"的那批。

操作步骤
  1. 在筛选行点 全部 / 最近编辑 / 收藏 / 未链接 切换视图，右侧计数文案同步变化。
  2. 或用圆盘：点「笔记」→ 再点一次 → 环上出现四个视图，选哪个列表就切到哪个（两处状态互相同步）。
  3. 点任意笔记行 → 打开笔记详情。
注意事项
  • 「收藏」是视图，不是分区：它原来是圆盘上的一个独立分区，同时又是"笔记"的子项 —— 同一概念出现两次，用户每次都要猜点哪个。降级后数据没丢，仍能一键切出。
  • 筛选行与圆盘三级必须同步，否则"收藏是视图"这句话在界面上就是假的。
  • 搜索框目前只是界面，输入不会真的过滤（见第 6 章占位清单）。真正可用的检索入口是 ⌘K。

收件箱（唯一捕获口）

已实现
作用

所有新捕获先落这里（5 条），整理之后才进主库；三级按"为什么还没走完"过滤，行内直接处置。

适用场景

每天固定清一次收件箱；批量处理"待补全"这种同一类活。

操作步骤
  1. 切到「收件箱」→ 看到全部 5 条（计数文案明说"未参与检索"）。
  2. 用筛选行把它缩到一类：全部 / 未归类 1 / 待补全 2 / 待提炼 1 / 待判断 1（切到哪一类，计数文案就跟着变）。
  3. 在行上点 归类到主题 或 退回来源。
  4. 点行本身 → 打开详情，读"缺什么才进下一层"。
注意事项
  • 未整理的笔记不参与检索，这条规则要写在界面上（已写进计数文案），否则用户会以为"存进去就能搜到"。
  • 行内按钮与"点整行开详情"是两件事：按钮必须阻止事件冒泡，否则点按钮会顺带弹出详情（已修，并写了断言防复发）。
  • 面板里的「整理规则（三问定去向）」是判定口径；"两周未动自动归档"是规则说明，原型不执行。
  • 筛选是按行上的状态过滤，不是把同一批行抄成 5 份 —— 状态是会变的行属性，抄多份必然出现两套真相。

主题（人工策展的容器 · 三级 = 分组）

已实现
作用

全库 42 个主题、分 3 组；示例列出 9 个，各带笔记数（42 / 36 / 28 / 24 / 18 / 16 …）。主题是"能往里补充说明"的容器。

适用场景

沿一条主线读一批笔记；给刚整理的笔记找归属；主题多了以后先按组缩范围再看。

操作步骤
  1. 切到「主题」→ 看到全部 9 个（计数文案：全部 42 个 · 示例列出 9 个）。
  2. 再点一次「主题」（或点圆盘中心门）→ 环上换成三级：全部 / 技术 17 / 产品与系统 12 / 生活 13。
  3. 选「技术」→ 列表只剩 3 条，计数文案变成 技术组 17 个 · 示例 3 个，面包屑变 知识库 / 主题 / 技术。
  4. 点某个主题 → 打开主题详情（说明 + 笔记列表）。
注意事项
  • 三级是"分组"，不是"某个主题"：42 个（将来上百个）主题名塞进环上就废了 —— 一级圆盘只有 6~7 格。
  • 只分一层：分组可以嵌套一层（父主题），但不再往下 —— 两级以上就会退化成第二个标签体系。
  • 主题与标签的分界：能往里"补充说明"的是主题（人工策展、数量少、可嵌套双链）；只能回答"它属于哪类"的是标签（自发涌现、数量多、平铺）。
  • 分组是行属性（data-group），过滤靠 hidden，不复制行。

标签（自发涌现的属性 · 三级 = 治理状态）

已实现 点标签本身未接筛选
作用

全库 96 个标签，示例 19 个，字号代表使用频次。这个分区不负责浏览（浏览靠检索），它负责降熵。

适用场景

定期治理：清理再也不会用的、合并"同一个概念被起了三个名字"的。

操作步骤
  1. 切到「标签」→ 19 个标签按字号显示频次。
  2. 再点一次「标签」→ 环上出现三级：全部 96 / 高频 23 / 沉睡 55 / 待合并 18。
  3. 选「沉睡」→ 只剩 6 个（示例），它们是 last_used_at 超过 90 天的淘汰候选；选「待合并」→ 5 个疑似同义标签。
  4. 点某个标签 → 目前只显示可点状态（未接筛选）。
注意事项
  • 标签平铺、不做层级：一旦给标签建层级，它就和主题重复了。治理手段只有两个 —— 合并（留一个名字、其余记 alias_of）与淘汰（last_used_at 太久没用）。
  • 三级给的是状态而不是标签名：96 个标签名塞不进圆盘，也不该塞。
  • 三个状态是互斥的（一个标签只落一档），所以计数加起来 = 96，可以在界面上对账。
  • 标签数量会持续增长，所以它不该进圆盘一级（圆盘项数按认知负荷定，上限约 7±2）—— 但它本身是 6 个分区之一，这没矛盾：进圆盘的是"标签"这个分区，不是 96 个标签。

图谱（关系视图 · 三级 = 看什么）

已实现 图内节点点击未接
作用

四种"看法"：局部图（以中心节点 1 跳）· 全库统计（6 个数字）· 孤儿巡检 12 · 黑洞巡检 3。

适用场景

沿关系走一段（局部图）；判断"整库链接够不够密"（统计）；专门收拾两类坏点（巡检）。

操作步骤
  1. 切到「图谱」→ 默认局部图，读图例（实底 = 中心节点，描边 = 关联笔记，连线 = 双向链接）。
  2. 再点一次「图谱」→ 环上出现三级：局部图 / 全库统计 / 孤儿巡检 12 / 黑洞巡检 3。
  3. 选「全库统计」→ 六个数字：286 笔记 / 348 双链 / 平均出链 1.2 / 零入链 12 / 孤儿 12 / 黑洞 3。
  4. 选「孤儿巡检」或「黑洞巡检」→ 列出具体笔记，点一条能打开详情（详情里写明它为什么被命中）。
注意事项
  • 这是唯一允许占分区的关系视图：它不是"同一列表的筛选"，而是另一种导航方式（沿关系走）。
  • 上千条时只画局部：286 个节点同屏只剩一团毛线，全库层面只出统计。这也是把"图"和"统计"分成两级的根本原因。
  • 四种看法是四份内容（不是一份数据的四个子集），所以用 .sub-view 换块 —— 与主题 / 标签的 hidden 过滤是两套实现，别混。
  • 为避免"每次刷新图都不一样、标签叠字"，节点位置用固定百分比 + SVG 直线，不依赖力导向布局；连线用非缩放描边保持 1px。
  • 两个巡检的判据不同：孤儿 = 入链和出链都为 0 且 >30 天；黑洞 = 被引用 ≥3 次但出链为 0。前者是"没人知道它"，后者是"只进不出"。

归档（只读）

已实现
作用

12 条已归档笔记 + 37 条候选的归宿；用归档代替删除，保留历史且不打扰检索。

适用场景

判断一条笔记以后不会再用，但删了又不放心。

操作步骤
  1. 打开任意笔记详情 → 点 归档。
  2. 到「归档」分区 → 第一块是已归档，第二块是归档候选 37 条（12 个月无入链且无标签 24 + 收件箱 14 天未动 8 + 已被取代 5）。
  3. 候选区只列清单不自动执行；同一条被忽略 3 次就不再提示。
注意事项
  • 归档没有三级：它只有 2 类（已归档 / 候选），不足 3 类 —— 两块在面板里并列堆叠更省一次点击。这也是"不是每个分区都该有子菜单"的例证。
  • 归档的笔记不参与检索与图谱；归档行也不标成熟度（已冻结，标了反而误导）。
  • 知识库"只进不出"：笔记可以归档，但没有"删除"按钮。
  • 候选是建议不是动作：自动归档等于自动把内容从检索里拿掉，必须留人工确认。

笔记详情弹窗

已实现
作用

适用场景
