### 「我为什么不直接去看 git 提交记录」→ 拆列回答 + 去掉手填入口（10:35）

用户的质疑：「那我也需要手填啊，增加复杂度了，我为什么不直接去看 git 的提交记录」。

**一半对，一半不对。** 用"把每一列分成 git 有没有"来判：

| 列 | 来源 | git 有吗 |
|---|---|---|
| 版本 | 发布包 | ✗（git 是提交，不是版本；一次发布常含多个提交） |
| 提交 / 变更说明 | git | ✓ **该自动取，不该手填** |
| 部署人 / 服务器 / 耗时 / 结果 | 那次部署会话 | ✗ |
| 回滚 / 回滚自 / 原因 | 那次部署会话 | ✗ **git 里根本没有"回滚"这个事件** |

⇒ 结论：**不该手填**（用户的点对了），但 **git 替代不了它**（git 回答"代码改了什么"，它回答
"这台机器上现在跑的是哪个版本、谁上的、成没成、回滚过没有"）。

**改了两处**
1. 运维页发布记录卡头的「+ 记录」按钮（页面上唯一的"人工录入"入口）**删掉**。三张卡里另两张有主按钮
   （+添加 / +新建文档），这张没有 —— 这本身就是"这里不能手填"的表达，不必配解释。
2. 部署面板收尾状态行补「· 已记入发布记录」（成功 / 失败各一条）。**在产生端声明，不在只读清单上写解释**。
   `已中止` 那条**不加** —— 没发生的事不入账。

**没做的一件事（说明理由）**：没有让部署面板真的往 `ops-release:<host>` 落一条、运维页读出来。
原因是原型里"这次要发的版本 / 提交"没有可信数据（部署页只有本地构建产物 `pay-api.jar`，没有提交号），
硬凑一个 `v2.3.2 + 手写的变更说明` 恰恰会复刻要被去掉的那个问题（假数据 = 另一种手填）。
等接真数据时这条链自然成立。

核对：两页 HTML 结构平衡、CSS 括号差 0、令牌缺 0、JS 语法通过、`记录发布` 二页清零。

### 追加：按平台分组 + 筛选条（平台胶囊 + 搜索）

**四条实现要点**
1. **平台胶囊从数据现算**（"全部" + 真用到的每个 + 条数）—— 平台由自己输入，这排必须跟着数据走。

### 追加：复制图标坏掉 —— `.main` 类名撞车（用户截图问"复制图标怎么了"）

**现象**：凭据行行尾第一个按钮变成一个**白底、1px 描边、圆角大约 20px 的大方框**，
图标小小地浮在中间，其余（铅笔 / ⊘ / 垃圾桶 / 箭头）都正常。

**根因不是图标，是类名。** 上一轮我给这个按钮写的是 `class="ac-act main"`（想表达"主按钮"），
而 **`.main` 是外壳的滚动容器类**：

```
.main { flex: 1; overflow-y: auto; padding: 24px; background: var(--bg-card);
        border: 1px solid var(--border-card); border-radius: 20px; }
```

我写的 `.ac-act.main { color: var(--text-secondary); }` 与 `.main` **同特异性** ⇒ 后定义者赢
只覆盖了 `color` 一条，**其余六条全部落在按钮上**：24px 内距 + 白底 + 描边 + 20px 圆角 + `flex:1`
⇒ 就是截图里那个大方框。（`flex:1` 还把它撑开，把另外三个图标挤到右边。）

**改法**：类名带页面前缀 ⇒ `class="ac-act ac-lead"`，规则 `.ac-lead { color: … }`（写在 `.ac-act` 之后）。

**判据（已写进 MEMORY）**：**新类名先和全页既有类求交集** —— 外壳那一堆**不带前缀**
（`main / app / detail / card / tab / badge / btn / field`…），页面自己新增的一律带前缀。
短词最危险：`main`、`app`、`detail`、`card`、`list`、`head`、`body`。
⚠️ 这也是"静默失效"的一种：不报错、不警告，只是某个元素被远端一条规则顺带命中。

**可机械执行的对策**：拿到新类名后，在全页 CSS 里搜 `(?<![\w-])\.名字(?![\w-])`，
命中条数应为 0（或全部是自己写的）。本轮按这条清过一遍：
`ac-lead / ac-note / ac-filter / ac-search / ac-empty / chip-n / ac-detail-item` 全部只命中自己的规则。
