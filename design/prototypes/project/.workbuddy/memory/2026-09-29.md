## v8.5：修表格把手错位（用户「错位了」+ 截图：把手跑到表格右上角）

**根因：同一个函数里混用了两种坐标系。**
`edTbMove` 里当初存了两个"相对差"：
```js
const left = rect.left - base.left;   // 差值
const top  = rect.top  - base.top;
```
然后有的式子减 `left`（差值）、有的减 `base.left`（绝对值）—— `zone.at - left`
≠ `zone.at - base.left`（只有 `rect.left == 2 * base.left` 时才碰巧相等）。
⇒ 把手整体被推向右上方；而**指示线那两处写的是 `base.xxx`**，位置是对的
⇒ 用户看到的是"**线对、按钮错**"（那条竖线正确地画在列 1 右缘）。

**修法：换算只留一条出口。**
```js
const px = (v) => v - base.left;
const py = (v) => v - base.top;
```
`edTbMove` 里 7 处位置表达式（5 颗把手 + 2 条指示线）**全部**改成"拿视口坐标进来、
出去只经 `px()` / `py()`"，并删掉那两个相对差局部量 —— 留着它就会有人再减错。
注释里写清：这要求 `.ed-preview` 与叠加层**同原点**（无 padding/border），
哪天给它加内距要一起看。

**另一条教训**：这次复核时我用 `grep "a\|b"` 查残留，macOS 的 BSD grep **不支持 `\|`**，
于是空结果被我当成"已清干净"（假阴性）。查多个关键字要用别的方式（本仓早已遇过一次）。

复核：`node --check` OK；CSS 花括号 892/892；脚本区无 HTML 注释；7 处位置全过 px/py；

## v8.6：列把手对齐基准（用户「列的还是错位」+ 截图：＋− 停在列 2 中间、线在列 2 右缘）
