## 筛选 UI 统一：两组筛选合成一个组件（2026-09-26 深夜，用户「现在状态和类型是两种搜索UI，统一重构」｜用了 ui-ux-pro-max skill）

类型 = 一行 `.facet` chip。同一件事（用某个条件筛掉一些行）配两种长相。

  `.filter-group-label` 标 `aria-hidden` —— 不标会把组名念两遍）。

**代码上也是"一套"**（这是"两种 UI"在代码里的样子）：

## 两组快捷筛选：状态 × 类型（2026-09-26，用户要求「添加快捷筛选…还需要类型筛选」）

原来只有一组（状态 = KPI 四块，可点即筛），类型是工具栏里的一个「领域」下拉。改成**两组**：

| 组 | 形态 | 位置 | 项 |
|---|---|---|---|
| 状态 | 4 张 `.card.ov-kpi-card`（大数字 + 副行） | `.ov-kpi` 裸栅格（第一块） | 全部 / 进行中 / 风险阻塞 / 已完成 |
| 类型 | 一行 chip（`.facet`，胶囊 + 沉槽底 + 描边） | 工具栏卡 `.card.toolbar-stack` 的**第一行** | 全部 / 生活 / 工作 / 学习 |

- 两组**形态不同是有意的**：状态那组同时是"读数"（大数字 + 副行），类型这组只是筛选。
  做成一样重，控制区会吃掉半屏。chip 比 `.seg`（视图分段）小一号：分段是"换一种看法"，
  chip 是"筛掉一些行"。

**核心口径：筛选项上的数字必须是 facet 计数（= 点下去会剩几条）。**
`facetSet(group, k)` = 在**另一组 + 关键词已应用**、**本组自己的选择不应用**的条件下过滤。
不做这一条，数字会撒谎：类型选「学习」之后状态卡仍写「进行中 3」，点下去只有 1 条。
"不应用本组"不会形成循环依赖（算 A 组时只看 B 组）。

- **侧栏 KPI 槽**改为吃 `listSlotRows()`（当前筛选结果），不再吃 `projStats()`。

所以"只能在看板里显示"不成立：卡片那条比看板的大得多；缺的是表格。

**判据：条的可用长度决定放不放条。** 条能分辨的差异大约是条长的 2~3% ——
卡片 233px ⇒ 可分辨 ~1%、Hero 72px ⇒ ~4%、看板小条 ~100px ⇒ ~3%；
表格那一列只有 64px ⇒ 1px ≈ 1.6%，条会退化成"空/半/满"三档的装饰，
反而不如右对齐的数字准。**所以表格不加条**，正确解法是数字本身：
右对齐 + `font-variant-numeric: tabular-nums`。

顺手修掉的真错（都在表格的进度列上）：
- 那一列原来借的是 `.task-quad-tag`（四象限的象限标签），而窄屏那条

  看起来不报错、只是列没了。已换成自己的类 `.proj-progress`（右对齐 + 等宽数字），
  并把那条窄屏规则与整条 `.task-quad-tag` 规则（已无挂载点）删掉。

## 项目类型定为 3 种（2026-09-26，用户问「应该分为几种，已知工作/个人」）

**结论：3 种 = 工作 / 生活 / 学习。**「个人项目」是筛选口径（生活 + 学习），不是第四个类型。

三条判据：
1. 类型绑的是**分区模板**：7 格里「运维」「账户」只在工作项目成立（`visible: () => curPool().servers.length > 0`）。
2. 类型同时是**数据域键**：`POOL[scope]` 的 tasks/documents/bugs 文案按域取，生活（机票/签证/酒店超订）
   与学习（读书笔记/闪卡/mini-runtime）合并会让示例数据两边都不对。
3. 要与上层模块**同名**：侧栏 / 设置→模块 / 任务模块的域都是 生活/工作/学习 三档，否则跨模块聚合要另建映射表。

诚实区分：**只看分区模板的话 2 类就够** —— `life` 与 `learn` 两池的 `servers`/`accounts` 都为空，
裁出的分区集完全相同（5 格）。3 的第二个理由不是结构，是数据域 + 命名一致。

排除：2 类（个人内部语义不成立）／4+ 类（字段集无差异，退化成标签）／用户自定义类型
（新增类型 = 新增分区模板，属设置模块配置面）⇒ 固定 3 类 + 自定义标签。

录入判据（自上而下短路）：有外部交付对象 → 工作；无、目标是认知/技能/可发布作品 → 学习；其余（住/行/身体/家庭/财务）→ 生活。
单选，跨域靠标签，不做多类型。

## 抽出「项目详情」单独原型：`项目-项目详情-index.html`（2026-09-26）

  「抽出页」的既有惯例（面包屑式：`工作-项目-项目详情-运维-index` 那一族），本文件的
  根模块就是「项目」，所以是 `项目-项目详情-index`。
- **保留整套导航壳**（v5 顶栏 + 侧栏圆盘/图标列/三槽/超级菜单/命令面板/主题/收起）——

  三视图 / 页头）+ 只服务它们的 CSS（`.ov-kpi*` `.proj-*` `.facet*` `.page-*`
  `.task-row*` `.task-due*` `.task-group*` `.progress-bar/fill` `.progress-mini`

- 三处**行为**与源文件有意不同（都写在文件里）：
  ① 首屏直接是详情（源文件首屏是"全部项目"列表）；
  ② 默认打开**工作域正在推进**那个项目（7 格分区最全），其余项目用 `?p=p1`…`?p=p8`
     打开 —— 分区栏是"由数据裁"的（生活/学习项目没有运维/账户），只给一个项目就验不了；
  ③ 点顶栏「项目」胶囊 / ⋯「← 全部项目」不再切列表，而是诚实回一句
     "返回全部项目（列表层不在本文件）"—— 域根是另一个文件，假装切过去只会得到一个空内容区。
- 做法（可复用）：**不手抄**。三步机械手术，每步都断言命中数：
  ① 按标记切块（列表 DOM 整块丢、详情 DOM 逐字保留 —— 收尾比对过，正文 DOM 与源文件一致）；
  ② 死 CSS 规则用"选择器里每个 class/id 都要在标记+脚本里找得到消费点"判据批量删
     （字符区间删除 + 括号配平断言 + "区间必须等于一条完整规则"断言）；
  ③ 随规则一起死的**注释**逐条手改，并收拾空白（`\n{3,}` → `\n\n`）。
- 两个坑（下次直接用）：① 解析 CSS 时所有偏移都必须是**全文偏移**，用 slice 局部偏移去

  `from`/`to`/`0%`/`html, body` 这类**没有 class/id 的选择器**必须算活，否则 `@keyframes`
  会被整块删掉。JS 里拼出来的类名（`k-` + kind）要手补进白名单。
