## 1. 数据模型

### 1.1 `task` 表

> 原型里这些字段已经**补上了**：`task_index.html` 的 `TASK_FIELDS` 台账 +
> `hydrateTasks()` 启动时按标题写进各视图元素的 `data-*`（`data-created` / `data-updated` /
> `data-due` / `data-startAt` / `data-completed` / `data-inboxAt` / `data-project` / `data-est`）。
> 那是**原型专用机制**（真实实现里同一条记录被四个视图查询，不需要水合），
> 但它换来"同一任务在四个视图里读数一致"这件事可验证。

| 字段 | 类型 | 必填 | 说明 | 原型里的对应 |
|---|---|---|---|---|
| `id` | uuid | ✓ | | — |
| `title` | text | ✓ | | `.list-text` / `.kanban-card-title` |
| `scope` | enum(`life`/`work`/`learn`) | ✓ | 领域 | `data-scope` |
| `prio` | enum(`high`/`mid`/`low`) | ✓ | 优先级 | `data-prio` |
| `state` | enum(`todo`/`doing`/`done`) | ✓ | | `data-state` |
| `due_at` | datetime? | | 截止时间；"今天到期""本周"全部由它算 | 时间 chip 文案 |
| `estimate_min` | int | | 预估时长（分钟），默认 30 | `data-est`（小时 → ×60） |
| **`scheduled_start`** | datetime? | | **排期落点**，时间轴用它定位 | 原型缺 ← 必须补 |
| **`completed_at`** | datetime? | | 完成时刻；已完成分区、周节奏用它 | 原型缺 ← 必须补 |
| `source_kind` | enum(`todo`/`idea`/`ref`)? | | 收件箱的"类型" | `data-kind` |
| **`inbox_at`** | datetime? | | 进收件箱的时刻（"停留超过 3 天"要用） | 原型缺 |
| **`project_id`** | fk? | | 弹窗里有「关联项目」下拉，但没有字段 | 原型缺 |
| `created_at` / `updated_at` | datetime | ✓ | 详情里写了"更新于" | 原型缺 |

### 1.2 ⚠️ 以下**都不是字段**，是派生值，不要落库

`data-today` · `data-overdue` · `data-when` · `data-filter` · `data-group` · `data-count` ·
以及 `hydrateTasks()` 这个机制本身 —— 全部是原型为了让视图能查询、能演示而存在的。
照抄进表会得到一堆永远不同步的冗余列。
（`data-est` 是**例外**：它对应真实的 `estimate_min`，只是单位是小时；`data-scope` /
`data-prio` / `data-state` / `data-startAt` / `data-completed` / `data-inboxAt` / `data-project`
/ `data-due` 同样对应真实字段。）

## 2. 派生规则

| 名称 | 规则 | 状态 |
|---|---|---|
| **今日（含顺延）** | `due_at ∈ 今天` **∪**（`state ≠ done` ∧ `due_at < 今天` ∧ 逾期 ≤ 3 天） | 已定 §5-2 |
| 逾期 | `state ≠ done` ∧ `due_at < 今天` | 确定 |
| 超期积压 | 逾期 > 3 天：不进今日，只在「全部任务 → 已逾期」里 | 已定 §5-2 |
| 本周 | `completed_at` ∈ 本周（**周一起算**） | 已定 §5-3 |
| 时间轴可用窗口 | 用户设置，默认 08:00–22:00，行粒度 30min（原型 `data-rows="28"`） | 已定 §5-1 |
| 时间轴块区间 | `[scheduled_start, scheduled_start + estimate_min)` | 确定 |
| 空档 | 窗口 − 所有已排区间 | 确定 |
| 排期约束 | 必须整段落在一个空档内，且 `空档剩余 ≥ estimate`；否则明确提示排不下，**不允许落到半个格子** | 确定 |
| `estimate_min` 缺失 | 不进时间轴；点「排进去」时先补时长 | 已定 §5-4 |

## 3. 分区 × 视图契约

- **分区 4 个**：`today` / `all` / `inbox` / `done` —— 只承载「范围」。
  唯一契约：`section.key === panel[data-panel]`（集合与顺序都要相等）。
- **视图 4 个**（只在 `all` 里）：`list` / `board` / `matrix` / `calendar` —— 是同一批任务的四种**排列**。
  结构不同（行 / 三列 / 2×2 / 7 列网格）⇒ 各自独立渲染，切换只切显隐、**不重渲**
  （勾选、排期、二级筛选状态必须留着）。
- **二级筛选**（圆盘三级）：`today` → 已逾期/高优先级/其余；`all` → 生活/工作/学习；`inbox` → 未整理/想法/参考。
  实现方式：行上带 `data-*` + `hidden` 切换，**不要复制行**到不同的子视图里。
- **读数口径**：KPI 只统计**列表视图**的行；看板卡 / 矩阵项 / 日历 chip 虽然也参与二级筛选，
  但不能进 KPI 统计（否则同一任务被数四遍）。

### 各区域的范围边界（这三处最容易读成同一个数）

| 位置 | 范围 |
|---|---|
| 全部任务 · 任务列表 | 未完成：逾期 + 今天 + 之后 |
| 全部任务 · 已完成组 | **今天**完成的 |
| 看板第三列「已完成 · 今天」 | **今天**完成的（与上一行同一批） |
| 已完成分区「本周完成」 | **本周**完成的（含今天） |

## 4. 交互 → 写入

| 交互 | 写入 |
|---|---|
| 列表行勾选完成 | `state=done`, `completed_at=now` |
| 时间轴块完成 | `state=done`, `completed_at=now`（**保留** `scheduled_start`） |
| 看板卡「→」推进 | `state` 前进一档 |
| 四象限项「✓」 | `state=done`（象限只描述未完成的） |
| 点日历某天 | 新建任务，`due_at=那天` |
| 「排进去」 | 先补 `estimate_min`（弹窗选时长），再写 `scheduled_start=空档起点` |
| 采纳收件箱建议 | 按建议改 `scope` / `source_kind`，或拆子任务 |
| 就地添加 | 新建任务，`state=todo`，其余取默认值 |

### ⚠️ 三处别照抄

1. **看板卡的"循环推进"**：原型里 已完成 → 再推一次会回到待办，只是为了方便反复演示。
   真实实现最后一列应不可再推进（或走"重新打开"这个独立动作）。
2. **详情弹窗里的「更新于 今天 09:40」「所在分区」**：演示文案，没有数据源。
3. **`data-*` 派生标记**（见 §1.2）。

## 5. 已定（2026-09-28 确认，按推荐值生效）

1. **时间轴窗口：可配置**，存在用户设置里，默认真实值 `08:00–22:00`（原型演示值同）。
   ⚠️ 还要定一条配套规则：**窗口外的任务**（例如 22:30 开始的）—— 实现时按"自动扩窗到覆盖它"
   处理，不要静默丢进待排池（丢进池里等于这条任务消失了）。
2. **逾期顺延 3 天**：`due_at` 过期且 `state ≠ done` 的，**顺延进今日**，界面上标「顺延自昨天」，
   原始 `due_at` 不改。超过 3 天的不再进今日，只留在「全部任务 → 二级筛选「已逾期」」里
   （不新增分区）。需要记录"首次进入今日的日期"才能算满 3 天。
3. **本周从周一起**。
4. **`estimate_min` 缺失 ⇒ 不进时间轴**：任务照常在列表 / 看板 / 四象限 / 日历里显示，
   但**不占用时间轴**；点「排进去」时先弹时长选择（15/30/45/60/90/120 分钟），确认后才排。
   理由：默认值会让"空档"失真 —— 你以为半小时、实际两小时，"排得下"就成了假答案。
5. **看板不做自动流转**：状态只由手动动作改（卡上「→」/ 详情按钮）。不做"排期即进行中""到点自动开始"。
   勾选完成属于用户主动动作，不算自动流转。

## 6. 原型里没有的部分

- 空态 / 加载态 / 错误态（唯一已定义的一种异常态是时间轴的"今天排不下了"）
- 撤销（勾错只能再点一次）
- 导入导出（CSV / Markdown）
- 移动端的时间轴：480px 高 + 20 行，手机上需要另一套呈现（现在只做了样式压缩）
