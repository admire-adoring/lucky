## 从 `work_index.html` 抽出 `work_task.html`（工作区 · 任务页独立成页）

用户口径：「提取为单独的 work_task.html」。
产出：`design/work/work_task.html`（4227 行 / 223KB，源文件 5521 行 / 293KB）。

**做法**：不重写，用脚本（`/tmp/extract_work_task.py`）从 `work_index.html` 按**精确锚点**切片。
保留 ① 令牌层与整份 CSS、② 整套壳（顶栏九域胶囊 / 侧栏圆盘 / 超级菜单 / 槽面板 / 命令面板 /
主题 / 折叠）、③ 页头路径行，内容区只留 `panel[data-panel="tasks"]`。
删掉：工作台那一屏 + 项目/服务器/部署/会议/文档/联系人/客户/OKR/工时/周报 十个分区，
以及只服务它们的 JS（收藏星标、弹窗、duo 横滚、`renderDuoView`、放大层、客户详情、书架飞出）。

**几处判断**

- **导航不锯**：`primaryConfig.work.items` 保留 12 项 —— 圆盘 / 超级菜单 / 命令面板都是**整个模块**的，
  抽一段出来不该把它们锯成 1 项。找不到面板的分区落到一张"这一段不在本页"的说明卡上
  （`activatePanel` 加了一层兜底：`data-panel="__rest"`）。
- **`.main` 去掉白卡**：原文件靠 `[data-workbench="on"]`（只有工作台那一屏开）把 `.main` 的白卡拆掉；
  本页的内容就是"一组卡摆在页面上"，所以把"不做大白卡"落成 `.main` 自己的规则，
  整段 `data-workbench` 机制（属性 + 2 条 CSS + JS 里那一行）一起删。页头路径行**保留**。
- **CSS 保留整份**：`card / tile / doc-book / kanban …` 这些类名在多个分区之间共用，
  按"哪些规则还有人用"去筛，筛错的代价（少一条规则 → 页面照常渲染只是样式不对）远大于留着几十条
  没人命中的规则。只删了明确只服务被删内容的两处：`.dash-star` 五条、`[data-workbench="on"]` 两条。
- **侧栏「最近」换成任务页真会上的**：任务 · 优化首页加载速度 / 任务 · 准备项目评审 / 项目 · 支付系统重构
  （删掉「部署 · v2.3.1 已上线」）。其余槽面板（快捷 / KPI / AI）是壳的演示内容，原样保留。
- **内容一个字节没改**：四档视图、列表档的主列 + 侧轨、数据池与派生口径与 `work_index.html` 一致。
  文件头写了一句"要改设计请改原文件再抽一次，别只改这一份"。

**踩到的坑（值得记）**：按 `rindex('<div class="recent-item">')` 取切片起点时，
`s[:i]` 会把那一行的**行首缩进**留在结果里，而 `s[j:]` 又带上下一行自己的缩进 ⇒
两段拼起来是 `44 个空格 + </div>`（24+20），标签数没少、结构也没断，**只有缩进是错的**——
这类"看着没问题"的残留只有把切片位置对齐到**行首**（`rindex('\n', 0, i) + 1`）才能免掉。
