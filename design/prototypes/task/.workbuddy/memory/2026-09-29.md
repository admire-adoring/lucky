## 项目区 · 任务主页：任务视图对齐任务模块那套（视图集合 + 外观）

用户口径：「项目区和工作区的任务应该使用任务区的那一个菜单的视图」。
追问后确认两件事：① 深度＝**视图集合 + 外观对齐**（不是只改命名，也不是把实现收敛成一份）；
② 范围＝**只改 `project/项目-任务主页-index.html`**（`project_index.html`、`work/work_index.html` 本轮不动）。

改了什么（`project/项目-任务主页-index.html`）：

- 档位：`TASK_VIEWS` 由 `list/board/matrix` 扩成 `list/board/matrix/calendar`，
  顺序与任务模块的「全部任务」一致；`SECTIONS.tasks.desc` 跟着改。
- 视图条：新开 `.view-bar / .view-bar__item`（**胶囊**，形取自任务模块 `task_index.html` 的 `.view-bar`），
  只给任务这一处用；`role=tablist` + `role=tab`，并在 `setTaskView` 里回写 `aria-selected`。
  ⚠️ **没有动 `.seg`** —— 本页 + 6 个兄弟页都在用它（文档那一格、项目列表那份），
  改一处就是 7 个文件一起漂。同一页里两种形不同是刻意的，注释里写明了。
- 日历：新增 `.cal-*` 样式 + `dateKey / calDays / calTaskHtml / taskCalendarHtml`。
  桶键取 `due`（`YYYY-MM-DD`，不从 `dueLabel()` 的文案回解析）；
  窗口是**滚动 5 周**（起点＝今天所在周的周一往前两周），不是"本月"——
  到期日是 `今天 ± N 天`（`DUE_OFFSETS` 最大 14），按本月切会把跨月那几条整批漏掉且不报错。
  今天的格子由算得出（`周一 = 0` 的偏移），不写死；过期且还有未完成的格子标 `is-late`；
  一格最多 3 枚、多的 `+N`（`title` 列出剩余名字）；"已完成"没有到期日 ⇒ 不进日历并在注脚说明；
  另留一条"窗外 N 条"的显式提示（当前恒为 0，`DUE_OFFSETS` 放宽时会喊出来）。
- 交互：点某一天 → `toast('原型演示：在 <date> 新建任务')`（本文件没有新建任务弹窗，
  与 `data-demo` 的约定一致）；点胶囊开详情（走原有 `data-task-open`）。
  点击委托里新分支**排在 `data-task-open` 之后**，并显式排掉 `.cal-task`（含 `+N`）。

没做、留给用户定的两件（本轮明确跳过）：

1. **卡上的一键动作**（看板 → 推进、四象限 ✓ 划掉）没搬 —— 本文件的视图都是
   "从数据重渲"的，DOM-only 改状态会在下一次筛选时被冲掉；要做得先引入一张状态覆盖表，
   而这与现有的"勾选只改 DOM"（`toggleTask`）写法会分叉，属于另一个决定。
2. **文档那一格的 `.seg` 要不要也换成胶囊**（会牵动 6 个兄弟页）。

顺带：把这套"跨模块搬视图套件"的经验补进了技能 `sibling-page-visual-port`（新增"四之补"一节，
description 与版本一并更新）。

## 应用层「统一任务页」的现状盘点（用户问"推荐做吗"时的取证）

用户口径：「任务菜单是总的，其他工作区的任务页选用任务工作区的」。
本次只盘点、未改代码。事实（都在 `client/lucky/src` 里量过）：

- `pages/workspace/tasks/TaskViews.tsx` 导出的 `ListView / BoardView / MatrixView /
  CalendarView / ViewBar / FilterBar / TaskCheckButton` **已经是"不含外壳、只吃数据"的形态**
  —— `ListView({open,done})`、`BoardView({columns})`、`MatrixView({boxes})`、
  `CalendarView({pass})`、`ViewBar({views,active,onSelect,hint})`（`views` 已经可以传子集）。
  也就是说共享边界已经存在，第二个挂载点是**接线**，不是重写。
- 同构先例已在仓里：`useProjectDetailView(id, basePath)` + `ProjectDetail({view, backTo})`
  被项目区/工作区两处挂（就是 `cross-module-shared-view` 那套），另有 工作项目 = 调用项目模块传 `scope=work`。
- 三处现状：
  · 任务工作区：`data/workspace/tasks.ts` 的 `TaskRow` + 四档（唯一完整的一份）；
  · 项目详情「任务」格：`data/workspace/project.ts` 的 `WsTask`（`adaptTasks`）+ **纯两段列表
    （进行中 / 已完成），原型设计的三档还没落地**；
  · 工作台「今日任务」卡：`WorkbenchPanel.tsx` 自有派生 + 三档视图（用 `.seg`）。
- 重复是硬的：`TaskState`（tasks.ts）与 `WsTaskStatus`（project.ts）是**同一个集合定义了两次**；
  `TaskRow` 有 `project` 但没有 `owner`，`WsTask` 有 `owner`。三处各有一张勾选覆盖表。
- 应用里**没有任何模型有 `blocked`（受阻）** —— 那一档只存在于原型（项目区）。

结论与待定项：推荐做，且现在做最省（项目区那格还没实现三档 = 只写一份而不是第三份）。
唯一待用户定的是 **`owner` 进不进任务模型**（推荐进）；`blocked` 推荐**不升**
（应用里没有数据源会产生它，升进来就是恒空一列）。本轮未动应用代码。

## 用户口径转向：**只做原型**（不碰 `src/`）

### 本轮做了：`work/work_index.html`（工作区的任务页 + 工作台卡）

- **一份池、两个壳**：`RAW_TASKS`（13 条，`days` = 相对今天的天数，`q` = 象限显式字段）。
  `TASK_SCOPE` 按 `data-view-host` 给范围：`tasksPanel` = 全量、`tasks`（工作台卡）= `days <= 0`。
  **范围由壳传，视图不判**。
- **到期口径改绝对年月日**：原来是 `w: '逾期 2 天'` 这类**给人看的文案**，既会过期
  （今天写"3 天后"，明天是假话）又没法给日历分桶，而从文案回解析是本仓禁止的一条。
  现在 `days` 是数据，`due/overdue/done` 写成 **getter**（派生一处算，避免"改了 state 忘了改 done"）。
- **四档视图**（列表 / 看板 / 四象限 / 日历）与「任务」模块同一套口径：
  列表 = 组「待办 · 逾期优先 / 已完成 · 今天」（组内按 days 升序）；
  看板 = **列按状态**（原版三列是「逾期 / 今天 / 已完成」，那是时间维，与列表分组重复）；
  四象限 = 按 `q`，只看未完成 + 底部交代；日历 = 滚动 5 周，同理见下。
- **「任务」面板从静态清单改成真的任务页**：删掉 6 条硬编码 markup，换成
  `data-view-host="tasksPanel"` + `.seg` 四档 + `#taskPanelBody`。
- **日历挂哪一档有取舍**：工作台卡**不挂日历**（卡的内容是"今天 ∪ 逾期"这一刀，
  在切片上画日历只会得到今天一个点）。四档实现只有一处（`renderTaskHost`），
  档位集合由各处的 `.seg` markup 声明 —— 与任务模块 `ViewBar` 收 `views` 同一条。
- **顺手修一条静默失效的链**：`SUB_RULES.tasks` 原来从 `.task-item > .task-tag` 的文案
  回解析状态。清单一旦变成 JS 渲染，`buildSubIndex()`（init 时跑）就早于 `wireViews()`，
  那条三级筛选会静默失效。改成**渲染器直接写 `data-sub=state`**，并把"当前生效的子筛选"
  记进 `activeSub`，重渲后再 `applySub` 一次（换视图也走这一步）。
- **清死码**：`.task-item` / `.task-tag` / `.dash-done*` 三条一族全删（产出它们的 markup 没了），
  `.dash-done` 那套折叠换成列表里的一个组（折叠会把"今天做完了什么"藏起来，而它正是卡要给的即时反馈）。

## 工作区 · 任务列表改成「主列 + 侧轨」排版（对齐任务模块那一格）

用户给了任务模块「全部任务」列表档的截图：「列表能按照这个排版吗，只不过把分布的按领域换成按项目/按模块」。

- **池子按真项目重排**：原来自造了「日常事务」这个不存在的项目。现在 15 条任务落在
  **书架上那 4 个真项目**上（支付系统重构 / 用户中心改版 / 数据看板 / 性能优化专项），
  并按「同一个项目在书架上是那个色条，在分布里也是它（一份事实，不另开一张色表）」，
  把书架的 `data-tone` 提成 `PROJECT_TONE` —— 分布条的色 = 项目身份色。
- **加 `doneDay`**：完成日相对今天的天数（只有已完成条目有）。`days` 只表示到期日。
  有了它才有"近 7 天完成节奏"，也才能把「已完成 · 今天」与"更早完成的"分开。
- **列表档全新排版**：主列（快捷添加 + 任务列表卡 + 已完成 · 今天卡）+ 侧轨（分布卡 + 近 7 天节奏卡）。
  ≥1080px 两列（1.7fr / 1fr），窄屏单列。列表**不再分组**（卡的边界就是"段"的边界，
  组头那条细线是同一件事说第二遍）→ `.dash-group / -head / -count` 三条删除，`.dash-group-name` 留给看板列头与象限格名。
- **侧轨第一组按项目、第二组按状态**：按项目 4 条；按状态 3 条固定（0 条的项目不占一行 ——
  项目是从数据里长出来的，状态三档是全集）。
- **近 7 天完成节奏是滚动窗口，不是"本周"**：周一、周二打开时"本周"只有一两根，看不出节奏
  （与日历用滚动 5 周同一条判据）。柱高 60px 轨道内按峰值取像素。
- **"更早完成的 N 条"必须留一句交代**（列表卡、看板各一条）：两处都不重复做归档，
  归档在任务区的「已完成」—— 不能无声地少几条。
- **面板结构改了**：「任务」那一页**不再是一张大卡**（列表档自己出四张卡），
  视图条那一行单独摆在外面；工作台那张卡**自带卡面**。两个壳的差别收敛成一张表
  `TASK_HOST` 的四样：`scope` / `rail` / `quickAdd` / `carded`。
- 顺手：快捷添加挂上真回执（委托 + `btn.click()` 一个出口）；`.panel[data-panel="tasks"] .card:hover`
  关掉上浮（在卡里打字会整张卡抖）。
