## 讨论：主题 / 标签 / 收藏 / 归档 是不是"只是不同的筛选条件"
- 用户提出这个质疑。**4 个里 2 个对**：收藏 ✅、标签 ✅；归档 ❌、主题 ❌。
- 给出可机械执行的判据：**把条件写成一行查询，写得出来就是筛子**。`starred:true` / `tag:架构` 写得出来 → 筛子；`archived:true` 能写但语义是**换池子**（归档笔记不参与检索/图谱/统计）；`topic:X` 能写但主题**有自己的正文与子主题** → 实体优先。
- ⇒ 归纳成三类判据：**池子（收件箱 / 笔记 / 归档）· 实体（主题）· 筛子（标签 / 收藏 / 来源 / 时间）**；只有"筛子"不该占圆盘一格。
- **反例校验**：若"凡是筛选都不占分区"成立，收件箱也该砍（它就是 `stage:record` 的筛选）—— 但它换了池子（未整理不参与检索），所以站得住。这说明书"池子/实体/筛子"比"是不是筛选"更管用。
- 自认一处护短：上一轮给「标签」做的"治理状态"三级，本质是为一个本不该占一格的东西找理由。
- **用户决策：先不动。** 接受判据，但认为标签值得单独一格。
- 保留现状的代价与条件：`标签` 分区要**名副其实地做治理台**（合并 / 淘汰），不能拿来浏览（浏览走检索）。复查条件 = "一个月都不点一次"或"检索里 `tag:` 用得比进分区多" → 再按判据降级。
- 本轮**未改动任何原型文件**，只把判据与决策写进 `MEMORY.md`。
