L1

#[tauri::command] 只写在 shell。

命令函数里出现 if / match 业务分支即违规。

L2

领域层不出现 tauri、不出现 serde_json::Value 透传。

校验：grep -r "use tauri" backend/ 为 0。

L3

rusqlite 只被 server 目录内的文件 import。

crate 用 path 依赖挂 shell，不建 workspace（会挪 target/ 导致 tauri 整套重编）。

L4

组件不 import api/*，只 import hooks/*。

校验：grep -rn "invoke(" src/pages src/components 为 0。

跨域

只允许「任意域读项目域 / 任务域」（如 srv 的 hydrate JOIN project 取项目名）。

项目域 / 任务域不许读模块专属表；域 A 不写域 B 的 SQL，要改就调对方门面。

2crate 内部目录组织

目录名 = 表前缀簇名；每个域固定 model / repo / mod 三段，门面是自由函数。

「域」是表的归属簇，不是前端的九域模块：`srv` 不属任何单一模块，`common` 也不是一个页面。 前端 pages/ 按模块摆，后端按「这张表会被谁用」摆。按域摆换来的是 编译期强制的域边界（`pub` 之外拿不到）与「删一个域 = 删一个目录」； 横切关注点（错误 / 连接 / id 生成）由 crate 根的 error.rs / store.rs / db.rs 收口。
src-tauri/src/server/领域层，唯一依赖 rusqlite + serde
├── lib.rs模块声明 + 重导出（现重导出 srv::Store，应改为 store::Store）
├── store.rsStore：open / conn()（pub(crate)）/ 锁中毒处理 —— 从 srv/mod.rs 提出
├── error.rsError / Result 全仓一份；待加 code() 让前端能按类型分支
├── db.rsforeign_keys=ON + WAL；MIGRATIONS 用 include_str! 引 design/sql-design/，不另存副本
├── project/执行层「项目」域：project / member / tag / milestone / document(_link) / risk / activity
├── task/全局层「任务清单」域：task —— 不挂项目时是收件箱任务
│   ├── mod.rs门面：pub fn list(store: &Store) -> Result<…>，取锁后调 repo
│   ├── model.rsXxx（读出）/ XxxInput（写入）；#[serde(rename_all="camelCase")]
│   └── repo.rs全部 SQL，只收 &Connection / &mut Connection，不 import Store
├── srv/跨模块簇：服务器台账（mod.rs / model.rs / repo.rs 三段已成型）
└── work/工作模块专属：work_contact / work_okr / work_time_log …（第 3 步）
