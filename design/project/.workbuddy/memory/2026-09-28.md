## 14:20 「怎么渲染不出来了」—— 模板字符串里的反引号（同一个坑第三次踩）

用户截图：文档主页的**骨架全在**（侧栏三组的标题、搜索框、排序、视图按钮、新建文档），
但**所有由 JS 生成的内容全空**（筛选项、书墙、列表）。

**判据**：这种"骨架在、JS 内容全空"只有一种成因 —— **SyntaxError**（脚本解析阶段就停了），
不是运行时错误、更不是 CSS 问题（样式看得见就是说 CSS 没事）。

**根因**：v3.3 我在 `docDetailHtml` 的 **return 模板字符串内部**插了一段 HTML 注释，
注释里为了引类名与函数名用了反引号：

```
            <!-- ...（`.doc-graph-wrap` 的栅格、`.doc-relp` 的凹槽）...
                 ⚠️ `<svg>` 的内容是**画出来的** ...
                    真正的渲染在 `openDoc` 里 DOM 落地之后（`renderDdGraph`）。 -->
```

反引号把那个模板字符串**提前闭合**了 ⇒ 余下的 HTML 成了非法 JS ⇒ 整段 `<script>` 不执行。

**修法**：把这条注释整个搬到 `return` **外面**（变成普通 JS 块注释），模板串内一个字都不留。

⚠️ **第三次踩**（前两次：`pmFieldsHtml` 里的 `` `tagPool()` ``、生成器拼 head 时用反引号括文件名）。
**硬规则**：本仓的模板字符串里**一律不出现反引号** —— 要引类名 / 文件名 / 函数名，用「」。
这条已经写进 `项目-文档详情-index.html` 里 `docDetailHtml` 的注释。

**排查口径（下次直接用）**：
1. 先看"骨架在不在"：骨架在、内容空 ⇒ SyntaxError；骨架也乱 ⇒ CSS。
2. 只查**最近改过的模板字符串区域**，逐个找反引号；不要去翻全文件。
3. 例外：反引号出现在 **JS 注释**里（`/* ... */` 或 `//`）无害 —— 但那条注释必须在模板串**外面**。

## 14:30 详情页关联图改力导向（用户贴 d3「最简知识图谱」实现）

用户贴了一份 d3 v7 的力导向 demo（`forceLink + forceManyBody + forceCenter`，含 `d3.drag`），
意味"关联图要做成这种知识图谱的样子"。做了，但**不是照抄** —— 三处按下本仓的约束改写：

1. **不引 d3**（原作者用 CDN）：本仓原型是自包含单文件、双击即开、离线可用。
   引 CDN = 没网时这一页是空的。改用**原生 JS** 写同一套力（`docForceLayout`）。
2. **起点确定**：先用 `docGraphRadial(m, center, 1)` 按跳数分圈定初值，再在初值上松弛。
   力导向"每次刷新一张新图"的根因是**随机初值 + 自由迭代**，不是力本身 ——
   初值定了、迭代步数定了（240），同一份数据永远同一张图。判据仍是「**确定 ≠ 不动**」。
3. **不跑常驻动画、不接拖拽**（原 demo 有 `d3.drag`）：拖拽会与"点节点 = 换到那一篇"抢手势，
   本仓"图谱不拖动"那条继续有效。算完把坐标写死，没有 `requestAnimationFrame` 循环。

参数：`LEN 140 / REP 20000 / PULL 0.012 / SPRING 0.02 / DAMP 0.82`，240 步。
⚠️ 松弛后位置离开"分圈的圆" ⇒ **viewBox 必须重算**（否则图被裁）；
而且 `cx / cy` 要给**中心点平移后的坐标**（不是 W/2）—— 画同圈内凹的弧时它当圆心用。
⚠️ 斥力距离下限 900（30px）：两个最大半径的点贴住就够了，再推会抖。

范围：只改**详情页**那张（卡头写「关联」）。主页那张（总览两列 / 选中分圈两态）未动 ——
它有"探索"语义，力导向会把总览态也散开。

## 14:35 用户要 d3：「d3 via CDN、随机初值 + 自由迭代、d3.drag 拖拽 都做」

| 随机初值 + 自由迭代 | `forceSimulation`（link/charge/forceX·Y/collide），中心 `fx/fy` 钉在画布正中，其余随机角度+随机半径撒开 | 参数按 **640×560** 画布给（demo 是全屏，-400 搬过来会散出框外）；多加 `forceCollide`（本仓节点半径随度数变、名字长） |
| d3.drag 拖拽 | `nodeSel.call(d3.drag())`；中心不给拖 | ⚠️ 拖拽与"点一下 = 换到那一篇"共用同一个 `<g>`：**位移阈值 3px（离起点的距离）** 分开 —— 动过就把松手后补的 click 吃掉（`ddClickMute` + 320ms 保险丝），没动就让 click 照常走。⚠️ 判"拖没拖"**不能看 `ev.dx/dy`**（d3 给的是**单帧增量**，一帧动 1px 很常见），要拿当前点和 `start` 时记的起点比 |

**保留的降级**：`docForceLayout`（零依赖确定性版）留着 —— d3 没到 / 被挡时这一格不能是空的。
两条路共用同一套节点画法与读数栏，只有"怎么摆"不同。

**节点画法重构**（为 d3 每帧更新位置）：
`docGraphNodeInner(m, key, opts)`（坐标以自身为原点）+ `docGraphNodeSvg(m, key, p, opts)`（外层 `<g transform>`）。
主页那张静态图共用，视觉不变。

⚠️ **仿真生命周期**：`renderDdGraph` / `backToDocsHome` / `activateTab` 三处都调 `ddGraphStop()` ——

## 「颜色封面怎么弄」（用户问）

**答案：不用弄，它就是类型色。** 链路是三段，没有第四段：
`:root` 的 `--k-*` 七支（一处定义）→ `.doc-book.k-<类型> { --book: var(--k-<类型>) }`
→ 书脊 / 布纹 / 折痕 / 压印框全部由 `--book` 用 `color-mix` **算**出来（封面上没有第二条硬编码色）。

**而且不该让它可选**（判据）：颜色在本仓只承担**"类型"一件事** —— 左栏 facet 的色点、书脊、
图谱节点左侧色条、详情页的类型签读的都是同一支。一旦可自定义，"看颜色读类型"这条就废了
（会出现同类不同色、同色不同类）。要换色改 `:root` 里那七支之一，四处一起变。

**顺手补的一处**：弹窗「类型」那几颗胶囊带上了各自的**色点**（读同一支 `--k-*`）——
选的时候就看得见这本书将来是什么颜色，也就不会再有人问"颜色在哪设"。`.fm-chip` 因此改成
`inline-flex + gap: 7px`。

## 编辑 / 删除放哪（用户「那文档编辑、删除在哪里实现呢」）

**答案：同一个弹窗的三种模式** —— `fmMode = 'create' | 'edit' | 'delete'`。
这是**照列表页「新建项目」的做法**（`project_index.html` 里 `modalMode` 那套）：
一套字段、一份构造器，三种模式只差"预填哪来的 / 主按钮写什么 / 有没有那颗删除"。
**绝不另做编辑页** —— 字段与新建逐字相同，做第二套只会分叉（改一处忘一处）。

| | 入口 | 形 |
|---|---|---|
| 编辑 | **详情头部**「编辑」（ghost，主位仍是「打开原文」primary） | 同一个弹窗 + 预填这一篇的值 |
| 删除 | **编辑弹窗里的第三态**（底部**左端**一颗） | 确认型：说清"删的是哪一篇 + 会连带什么" |

三条判据：
- **编辑入口放详情页**，因为那里正是"看清这一篇之后决定改它"的地方；编辑时字段取**这一篇现有的值**，
  不拿当前筛选去覆盖（新建才用筛选推导）。保存只覆盖表单那五项 —— `links` 会随时间加行，不在这里动。
- **删除不常驻头部**，也不和"取消 / 保存"挤在一起（`margin-right: auto` 把它推到左端，隔开一段防误点）；
  确认文案必须说清**连带**：它挂出去的 N 条关联一并不见、N 篇反链随之消失 ——
  不做只有一个"确定"的确认框。
- 删除后**回主页**（这一篇已经不在了，停在它的详情上没有意义）。它占的坑会自动空出来：
  左栏那棵树按 `curDocs()` 生成 ⇒ 功能 / 模块没文档了就消失；整个项目空了则是现成的空态。

⚠️ **一条硬约束（写进注释了）**：文档 id = "项目 + **池子里的下标**"（`docsOf` 里 `-d(i+1)`）⇒
**增删会让后面的 id 整体平移**。所以"记住一个 id 等会儿再用"的地方必须在同一帧用完 ——
现在三处（新建 / 保存 / 删除）都是立即用掉的。**真要做"可撤销删除"，得先给文档一个稳定的 id。**

⚠️ 同步口径：`详情原型 = 主页` + 3 处差异（文件头第一段 / title / 首屏那行 `openDoc`）。
这一轮的编辑删除是在**主页**上做的，详情原型用 `sync_detail.py` 重新同步（它是详情屏的事实源，
弹窗组件也随之到位）。踩到一个锚点坑：**`renderRing(false);` 在文件里有 4 处**（缩进 4/8/12/16），
锚点要带换行写 `\\n    renderRing(false);\\n`（前缀会把更深缩进的那些排除掉）。

## 22:41 修：工具栏 `title` 把属性提前闭合（用户截图「这是什么玩意」）

现象：编辑面工具栏上凭空多出一段 `" aria- label="引用：给选中的每行加 "> ""`，且相邻两颗按钮（引用 / 代码块）消失。

根因：`edToolbarHtml` 里的
```js
const tool = (k, inner, title) => '<button ... title="' + title + '" aria-label="' + title + '">'
```
而 `tool('quote', …, '引用：给选中的每行加 "> "')` 的 title **自带一个 `"`** ⇒ 属性当场闭合，
`> "` 之后那一串被浏览器当**正文**渲染出来，`aria-label=` 也变成了散装属性。

修：`title` / `aria-label` **一律过 `esc()`**，并把提示语里的引号换成**「」**（不与属性引号打架）。

⚠️ 这类 bug `node --check` **查不出来** —— 它语法合法、JS 不报错、骨架也不白，只有肉眼看得见。
⇒ 已把「**属性值只要不是字面量就必须 `esc()`**」立成 MEMORY 里的硬坑，并给了一条静态复核法：
把脚本里 `attr="' + 表达式` 全捞出来过一遍，非 `esc()` / 非布尔字面量的就是嫌疑。
（当场过了一遍新增的那 11 处：其余 9 处是布尔（`aria-pressed`）或自产 id（`data-dd-edit` / `data-rd-go` / `data-ed-tool`），安全。）
