## 事故修复：整页内容渲染不出来（用户「怎么渲染不出来了」+ 截图）

**症状**：页面**壳全在**（顶栏 / 侧栏头 / 页头 / 筛选卡外壳 / 侧栏 tab 行），但一切由 JS 渲染的
内容全空 —— 两组筛选 chip、卡片列表、侧栏「概览」槽、顶栏徽标（还是 HTML 里的 `—`）、
侧栏 tab 还停在静态默认的「最近」上。

**原因**：上一轮把项目弹窗的四条接线写在 `newProjectBtn` 那句后面（脚本中段 L4732），
其中 `pmClose.innerHTML = iconSvg('close')` 会读 `const icons`（图标表，在 **L5103**）。
`function iconSvg` 会提升、`const icons` 不会 ⇒ 这一句执行时 `icons` 在 TDZ 里，
抛 `ReferenceError: Cannot access 'icons' before initialization`，
**把同一次顶层执行里后面的全部渲染初始化一起带走**（`renderContent()` / `renderRing()` /
`renderSlots()` 都在它之后）。

**修法**：四条接线挪到文件末尾「首屏」段之后（`renderRing(false)` 之后），原位置留一条注释
说明"为什么不在这里"。

**可复用判据**（已写进 `inline-row-actions` skill 的新一节）：

- **"壳都在、内容全空" ⇒ 先怀疑脚本在渲染初始化之前就中断了**，不要去查渲染函数。
- 排查只找**顶层立即执行**的语句（函数定义不算），看它引用的标识符是否都在这行**之前**初始化完
  —— 重点盯 `const` 表（图标表 / 配置表 / 常量表）。
- 语法检查查不出来（不是语法错误）；控制台那一行错误的位置离真正的原因隔着上千行。

## 卡片视图补上进度读数（用户「卡片加上进度条」+ 卡片截图）

## 项目类型的设计口径（承接 09-26 的「3 种」结论）

类型 = **固定 3 值枚举 + 一张「类型 → 分区模板」映射表**，不做第四值、不做多选、不做自定义。

```ts
type ProjectScope = 'work' | 'life' | 'learn';   // 单选、必填、不可为 null
SCOPE_META = {
  work:  { label:'工作', icon:'briefcase', sections:[…7 格] },
  life:  { label:'生活', icon:'leaf',      sections:[…5 格] },
  learn: { label:'学习', icon:'book',      sections:[…5 格] },
}
```

**要改的一处（现存真错）**：分区模板现在由**数据条数**裁 ——
`visible: () => curPool().servers.length > 0`（两个原型文件的 SECTIONS，L3655/L3664 与 L4231/L4240）。
后果：新建的工作项目还没录服务器，「运维」「账户」两格凭空消失，装完第一台才长出来。
⇒ 应改由**类型**裁：`SCOPE_META[scope].sections.includes(key)`，工作固定 7 格 / 生活·学习固定 5 格。

**类型在 UI 上只出现在 4 处**（各一个职责，不重复）：新建表单三选一（必填无"全部"）／
列表筛选 chip 组／卡·行·看板一枚**中性徽标**（图标 + 文字）／详情 Hero 同款徽标。

**徽标不上色**：本页颜色已有两个语义（`--m-*` 当前模块强调色、`badge-*` 状态），
再给三类各配主色会与状态徽标抢读 —— 类型靠图标区分，不靠色。

**类型决定且只决定 3 件事**：分区模板 / 取哪个数据池 / 在哪个模块域的切片里出现（`/work/projects`）。
不决定：状态、优先级、进度、权限、配色。

**「个人项目」不给它类型值**：它是 life ∪ learn 的并集，作为 chip 会让"全部 = 各项之和"不再成立、
计数口径撒谎。先不做；真要快捷，做成筛选视图预设（preset），不是第 4 个类型。

**存量迁移**：有外部交付对象 → work；否则目标是认知/技能/可发布作品 → learn；其余 → life。
判不出来的先落 life，**不设"未分类"第四值**（类型必填是它作为结构键的前提）。

## 发现的真缺陷：「Bug」格出现在生活/学习项目里（用户「生活那来的bug」）

1. **数据**：`POOL[scope].documents[i].links`，三种 kind ——
   `out 产出 → 工作项` / `bind 约定 → 另一篇文档` / `ref 参考 → 另一篇文档`。
   ⚠️ 目标只接 `task` / `doc`：问题清单那个池子是 `pick()` 出来的子集，下标与内容的对应
   逐项目不同，接上去会出现"某篇文档依据一条跟它无关的风险"。
   ⚠️ 越界的下标在 `docsOf()` 里直接丢（池子里的示例数据不保证每个项目的任务数都够）。
2. **文档详情**：把原来那张**假的**「关联任务」（`tasksOf(p).slice(0, 4)` —— 每篇文档都
   "关联"同一个项目的前 4 条任务）换成真边，并多出一张「被引用」（反链）。
   另一篇文档**能跳过去**（走同一套主从 `data-doc-open`）；工作项只能诚实回一句"没接"。
3. **关系网换血**：属性（类型 / 来源）**退出图** —— 它们在封面小签与左栏 facet 里已经
   说过两次，而且属性不是关系（那是把字段画成线）。图改成
   **两列「工作项 —— 文档」+ 文档之间的同列弧线**（向右鼓出去，不横穿文档列），
   两族边靠**线型**分开（实线 = 文档之间 · 虚线 = 挂到工作项），颜色仍只留给"类型"一件事。
   `W ≈ 602`：列宽按"渲染时几乎不缩放"定（SVG 被放大时 12px 字会跟着变粗）。

**一条边界**：加了边就**可能出现孤立文档**（谁也没连）。列布局下它是**看得见的**
（那一行没有线），所以仍然不需要再配"谁没连上"的清单 —— 与前一轮那条判据接得上。

**同时收窄的一处**：`/knowledge/graph` 那边的双链图谱（`design/know/knowledge_index.html`）
是另一回事：它的节点是**笔记实体**、以当前笔记为中心按跳数展开、并有孤儿/黑洞两种巡检。
文档这边不该长成那样（缺 `Link` 表、缺正文、缺规模），用户问"知识图谱的区别"时已答清。

## 图谱扩成跨实体的一跳（用户「改成知识图谱呢，因为功能总有关联」）

上一轮我把「双链」的边界讲清了，但用户下一句把重点放对了：**这个应用的实体本来就互相引用**
（任务 / 问题 / 会议 / 文档 / 服务器 / 账户 / 笔记），只接 `task` 与 `doc` 是我收得太窄。

**改了三处**：
1. **边的目标族扩到四族**，且**一条边一种意图、每种意图只对一族目标**（避免出现"某文档依据
   一条跟它无关的风险"那种错配）：
   `out 产出 → 任务` / `risk 风险 → 问题清单` / `meet 会议 → 会议` / `bind 约定 · ref 参考 → 文档`。
   · `risk` / `meet` 的池子是 `pick()` 出来的子集 ⇒ 越界下标在 `docsOf()` 里丢掉；
     语义写成"这篇文档**要处理的风险** / **是哪场会的产物**"，两类目标在任何项目下都读得通。
   · **服务器 / 账户仍不接**：它们与文档的关系在「运维」那一格已经表达过（部署文档就挂在
     那台机器旁边），搬过来要另编一套语义。
   · 反链**只有文档之间才有**（任务/问题/会议不会"link 到"一篇文档）。
2. **图谱左列 = 关联实体（各族混排）**，族名写进节点的**第二行前缀**（「任务 · 3 天后」/
   「风险 · 待修复」/「会议 · SEP 19」）—— 族不靠形状也不靠颜色，因为形状与颜色在这一格
   已经各有职责（圆角 = 节点、左侧色条 = 类型）。右弧仍是文档之间。
   `rowH` 从 64 收到 56：左列最多会出现 7 个实体（4 篇文档各挂 2~3 条边），64 就要翻屏。
3. **视图名「关系网」→「图谱」**（与知识库模块里那个入口同名），图例改成两句：
   实线 · 连到另一篇文档；虚线 · 连到任务 / 风险 / 会议。

**这一版正好印证了上一轮的判据**：用户要的"知识图谱"落在**这一格**时，形态就是
**以文档为中心的一跳局部图** —— 与知识库那张「双链图谱」同源（"以当前笔记为中心 · 1 跳"，
理由也一样：节点一多就只剩一团毛线，宏观问题交给统计答）。真正的"全图"该是独立页，不是这一格。

## 图谱真的能用起来（用户「名字改成了图谱，你这功能没变啊」）

上一轮我把"改了名字 + 换了左列的实体"当成了改动，但用户看到的是：**还是一张静态的画**。
这是对的 —— 图谱这个控件的价值不在"画了什么"，在**能不能走**。

**加的交互（一条铁律 + 三件东西）**：
- 铁律：**位置一动不动**。选中只影响显示，不影响布局 —— 空间记忆是这张图相对清单的唯一优势，
  "筛一下全都挪位"等于让读者白记一次。
- **点节点 = 选中**（再点一次 / 点空白处 / 状态条那颗 ✕ 都能取消）：选中的描边换 `--m-ink`、
  与它**直接相连**的邻居跟着亮、其余压暗。三种状态由**同一张邻接表**派生（`adj` 一边画边一边记）
  —— 三处状态同源，才不会"图亮了、状态条说错了"。
  ⚠️ **点节点不再直接打开那一篇**：探索与跳转不能共用一个手势（本仓的图谱 skill 里写死了这条），
  "打开"归状态条那颗按钮。键盘 Enter/Space 走同一个入口 `selectGraphNode`。
- **画布内的状态条**（选中才出现）：说清"这一组有几个"（连到 N · 被 M 篇连到）+ 「打开」+ ✕。
  它一次解决三件事：给出读数、给一个**显式的取消出口**（原来只有"点空白处"，没人会知道）、
  把"关联了什么"留在画布内。
- **节点行尾写连接数**：图自己要能说出"谁是枢纽"，否则读者得一条一条数线。

**两个必须防的坑（都写进代码了）**：
① 选中的节点可能被**筛选掉了**（刚改了类型 / 搜索）⇒ `adj[sel]` 为空，整张图会被判成"全都无关"
   一起压暗，看着像坏了 ⇒ 渲染时先校验"这个 key 还在不在这一批里"，不在就当没选中。
② `bind` 是**双向的**（两篇都写了这条边）⇒ 一对文档会画出两条一模一样的弧（DOM 两份、屏幕一条）
   ⇒ 加 `drawnPairs` 去重。

**仍是缺的**：**挂边没有入口**（边都在 `POOL` 里，能看能选能走，不能加）——
那是一条独立动作（选类型 + 选目标 + 当场生效、刷新还原），用户没点这条，先留着。

**框内留白**（用户：「太靠上和太靠下了」+ 红框圈住签与页脚）：上一版 `--bk-pad-y` 只留
`frame + 2px` ⇒ 页脚**正好压在压印框的下框线上**、签几乎贴着上框线。改成一律 `frame + 8px`
（横竖三边同一个偏移量），并顺手把运维那一档从 88 放到 96 —— 四行版面 + 框内留白之后
88 那一档横竖都不够了。**判据**：压在框线上的元素一律读成"出框了"，这不是"挤"，
是框与内容的关系错了。

## 集成知识图谱（用户：`design/know/知识图谱.html` + 「集成知识图谱」）

那份文件是知识库模块下的**独立全屏页**：顶栏（搜索 / 导入 / 主题）+ 左侧文件夹与标签 +
主区四视图（局部图 / 全局图 / 时间轴 / 白板）+ 右侧笔记面板（正文 / 正向链接 / 反向链接 /
未链接提及），**依赖 d3 v7 与 FontAwesome 两个 CDN**、玻璃材质。用户三问三答定位了集成范围：

| 问 | 答 | 结果 |
|---|---|---|
| 集成到哪一格 | 换掉文档格的「图谱」视图 | 不动 ① / ③，只换 ④ 里那一格的第三视图 |
| 图的位置怎么定 | **确定性布局** | 不引 d3、不自写力模拟 |
| 搬哪些能力 | **只勾「节点读数」** | 局部图/全局图/统计、时间轴、白板都没搬 |

**这一版做了什么**（`项目-文档主页-index.html`，同一份文件，只换 ④ 的图谱那一格）：

1. **布局分两态，同一个问题问两次**：没选 = 「这一批长什么样」（两列总览，同 v2.2）；
   选了 = 「这一篇连着谁」（以它为中心、**按跳数分圈**：0 圈中心 / 1 圈直接邻居 / 2 圈更远）。
   两种都是**算出来的** —— 同列均分行距、同圈均分角度（从正上方起、按数据顺序）、
   圈半径 `max(上一圈 + 122, 这一圈节点数 × 158 ÷ 2π, 116)`：节点多了圈自己长大，
   不需要"力"去推开它们。⇒ 同一份数据永远同一张图，也不会"标签叠字 / 中间空四周贴边"。
2. **节点换成圆点 + 一行名称**（参考件的做法）。两件事各占一条通道：**实心/空心 + 形状**
   分节点种类（实心圆 = 文档、空心圆/菱形/方 = 任务/风险/会议），**线型**分边的两族。
   颜色因此只剩"文档的类型"一件事（仍是 `--k-*`，与书脊同表）。半径按度数 ——
   谁是枢纽不用一条一条数线（v2.2 那个"行尾写连接数"因此撤掉，圆点大小已经在说）。
3. **右栏读数栏**（`#docRelp`，选中才出现；没选中时 `is-plain` 让图撑满整行）：
   正向「连出去 N」/ 反向「连进来 N」逐条列出，**点一条 = 换中心继续走**（不是打开详情）。
   "打开这一篇"由栏头那颗按钮负责。
4. 撤掉 v2.2 的画布内状态条（信息并入读数栏栏头）；`renderGraphBar` / `.doc-graph-bar` /
   `.gb-*` 整族删除。

**一处推翻**：v2.2 立的"位置一律不动：选中只影响显示、不影响布局"**作废**。
选中有意重排 —— 换的是"看什么"，而不只是"看亮哪几个"。但重排**可预测**
（同圈按数据顺序），与力导向那种"每次打开都不一样"是两件事。判据：
**确定 ≠ 不动。要保的是"可复现"，不是"零位移"。**

**没搬的，理由都写进文件头了**：全局图（单项目 4 篇文档的规模下它就是总览那一态）/
时间轴（与列表同数据同顺序，见文件头 ①）/ 白板（笔记整理的工具，与文档关联不是一件事）/
统计条（节点数由图上数得出，链接数由线数得出 —— 本仓"一处读数只留一处"）。

⚠️ **「未链接提及」没做**：它要有**正文**才能解析出"提到了但没挂链接"，而本仓文档只存索引、
正文留在原工具里 —— 与"真双链做不了"是同一件事。**不编替代品**（"同来源 / 同类型"不是提及）。

技法两条（可复用）：
- **参考件的"深度 1/2/3 跳"按钮不搬**：本仓单项目 4 篇文档，1 跳就基本连全 ⇒ 做了也是死控件。
  布局照旧**自动分层**（有几层画几层），规模小时自然退化成"中心 + 一圈"。**控件跟规模走**，
  不跟着参考件走。
- **凹槽里的复用徽标要跟着 hover 换底**：`.rel-item .rel-kind` 的底是 `--bg-slot`，
  挪进凹槽（同色）会隐身 ⇒ 默认换 `--bg-card`；但条目 hover 时条目自己变卡面，
  两者又同色 ⇒ 再加一条 `.relp-item:hover .rel-kind { background: var(--bg-slot); }`。
  一句话：**徽标与它所在的底永远要差一档。**

技法一条（生成器）：
- 这一轮起**不再按行号切片**，改成 `cut(start, end, new)` 锚点切片 + `count() == 1` 断言，
  七处替换一次过（上一轮行号降序那道坑的反面教材）。

技法两条（可复用）：
- **书脊与折痕写成 `background-image` 的叠层**（`linear-gradient(90deg, … 0 var(--bk-spine), transparent …)`），
  不用伪元素：它们本来就是封面上的两层光，这样 `::after` 能空出来做压印框。
- **装饰尺寸做成三个变量**（`--bk-spine / --bk-frame / --bk-frame-l`），其余用 `calc` 推；
  三档尺寸（书墙 118 / 概览 102 / 运维 88）各覆盖一次即可 —— 比写百分比省事，
  也避开"padding 的百分比一律按**宽**解析"那个坑。

## 书墙按**功能（= 文档类型）**分架（用户「算了，后面单独设计这个图谱页，回到书墙页，加一个根据功能分组」）

图谱那一格**原样留着**（用户放下的是"继续在图谱上迭代"这件事，没说撤），这一轮只动书墙。

- **架头是网格里的一个跨列项**（`grid-column: 1 / -1`），**不是"每组一个网格"**：
  后者会让只有 1~2 本的组把书拉成"一行一本"的超宽开本（`1fr` 就是这么算的）。
  一组 = 一个架头 + 若干 `.doc-book`，全都平铺在**同一个** `repeat(auto-fill, minmax(140px, 1fr))` 里。
- 分组维度 = `kind`（方案 / 设计 / 接口 / 测试 / 规范 / 调研 / 参考），顺序取 `DOC_KIND_ORDER`
  （它是目录，**位置稳定才找得到**，不按"哪类多排前面"），组内保持右上角那个排序。
- **架头不写计数**、**空组不渲染**：左栏 facet 已经在说"这一类有几篇"，而且它是随另一维变动的
  动态计数；架头再写一个当前篇数就是同一屏两组数字（一处读数只留一处）。缺口由左栏那几个 `0` 说。
- 架头形：类型色点（`--k-*`，与左栏 facet 同一支）+ 类型名 + 一条 `flex: 1` 的发丝线
  （v1 的 `.shelf-group-title` 做法）。v1 那个 `.shelf-count` **没搬**（理由同上）。
- 新增 `docShelfHtml(list)`（书墙从 `shown.map(docBookHtml)` 换成它），其余一律没动。

⚠️ 顺带记一个 **shell 坑（不是本仓的）**：macOS 自带的是 **BSD grep，不支持 BRE 里的 `\|`** ——
用它复查代码会拿到"没找到"的**假阴性**（这一轮差点误判成改动没落地）。要复查就 `grep -E`。

## 文档加一层「功能」维（用户「副筛选条件，比如这是登录的相关文档，（设计、规范、接口、测试）等一系列」）

**上一轮的误读**：用户说"根据功能分组"，我按 **kind（类型）** 做了 —— 这一轮他把"功能"说清了：
**"功能"= 登录鉴权这样的功能点**，而「设计 / 规范 / 接口 / 测试」是那个功能下的**类型**。
所以文档是**两层维度**：

| | 粗（新加） | 细（原有） |
|---|---|---|
| 维度 | **功能**（登录鉴权 / 迁移与发布 / 出行安排 / 签证与保险 / 读书与复习 / 源码实践） | **类型** `kind`（方案 / 设计 / 接口 / 测试 / 规范 / 调研 / 参考） |
| 在哪 | 筛选栏**最前** | 筛选栏第二组 + **书墙架头** |
| 性质 | **内容数据**（各 scope 自己的一小组） | 枚举（`DOC_KIND_ORDER` 固定顺序） |

落地（22 处）：`POOL[scope].documents[i].func` → `docsOf` 透传 → `docFuncFilter` 状态 →

## 缩小书墙的书（用户「缩小书墙的书」）

⚠️ **关键：书的大小只由栅格的列宽决定，动 `--bk-*` 是没用的。**

## 「还是大」—— 书墙列宽是**不连续的**（这条比什么都重要）

上一轮 140 → 108，我以为缩了，**其实书一点没变**：`repeat(auto-fill, minmax(M, 1fr))` 里，
列数 `n = floor((容器宽 + gap) / (M + gap))`，每列 = `(容器宽 − (n−1)·gap) / n`。
内容宽 644 / gap 16 时：

| M | 列数 | 每本宽 |
|---|---|---|
| 140 | 4 | 149 |
| 123 ~ 105 | **5** | **116** |
| ≤ 94 | 6 | 94 |
