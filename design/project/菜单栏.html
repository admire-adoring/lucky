菜单栏 · 统一样式 v2

菜单栏是四部分里的 ③：当前这个实体的下级分区。② 头部说"这是谁、到哪了"， 它说"此刻在看这个实体的哪一面"。一页里只有一条。

v2 换版（2026-09-27）：从"下划线"换成"浮起的一条 + 选中一块实底 + 图标"。 三条依据：① 每格现在带图标和计数，下划线那条太轻 —— 一排 7 格全是同灰度的文字， 读不出"哪一格有东西"；实底把当前格钉出来，图标把 7 格分开；② 它与左侧圆盘同源 （同一份分区表、同一张图标表），某个分区在环上是什么图形，在这条栏上就是什么图形； ③ 这套形就是 React 里通用 tab 的形（.mw-root .tabs/.tab）， 所以它是"把项目详情也并到通用那套"，而不是新造一种。

⚠️ 页签是真 <button>：appearance / background / border / font 这组重置漏一条， 浏览器就会自己画一圈边框 + 默认底色 —— v1 之前那半轮讨论， 讨论的其实是这层原生外观（它看着像设计、其实不是）。

  • 「有更新」不再另放一颗红点：在新形态里它没有落脚处 —— 页签右上角是计数胶囊，再往外会被 .tabs 的 overflow-x 裁掉（一个轴设了 auto，另一个轴的 visible 会跟着变成 auto）。改成把计数胶囊换成告警色：它想说的本来就是"注意这个数"。只有 tasks / bugs 两格会挂 has-update，而这两格都有计数 ⇒ 不会出现"想提醒但没有胶囊"的情况。
  • 没有禁用态：分区不是开关，"这一格不能去"在本系统里不存在（能列出它，就说明它可去）；真不可达就不渲染这一格。
  • 悬停不位移：一排七八个格，任何一个上浮都会让整排抖（.card:hover 那条 translateY(-2px) 不适用于它）。悬停只换底色。
  • 选中格不显示「有更新」：那个信号的意思是"这里有你没看的"，而当前格正在被你看 —— 两件事同时出现会互相消解。

深色

同一套令牌的另一套值：只换值、不改关系（栏的圆角、格间隙、实底、告警色都不动）。 .dark 挂在任意容器上都成立
  • 深底上强调色要提亮（--m-ink: #FDBA74），实底上的字反过来换深字（--m-on）⇒ 选中态那两条规则一个主题一份值，不用分叉写。派生令牌（--m-tint / --danger-bg）必须在 .dark 里再声明一次。

交互与可达性

  • 真按钮：<button type="button">，Enter / Space 由浏览器负责；那条重置也没法省（见页头）。
  • 语义：容器 role="tablist" + aria-label；每格 role="tab" + aria-selected。注意只有这一组叫 tablist —— 侧栏那三个槽用的是 .slot-tab，别共用同一个 label。
  • 焦点环画在格内（outline-offset:-2px）：一排相邻格，外扩的环会盖到邻格上。
  • 数字键直达：详情态按 1..7 切分区（无修饰键、焦点不在输入控件里）。这条是页面级快捷键，但它依赖"这条栏的顺序是稳定的"。
  • 点击即切，不重渲整页：菜单栏与正文栏共用一次 activateTab(key) —— 分区的 key 就是面板的 data-panel，两处不会各说一套。

与 React 落地态的关系（换版后新出现的一条）

  • v2 的形取自 React 的通用 tab（module-workspace.css L349-361 的 .mw-root .tabs/.tab：胶囊 + 实底 + 白字；配色用 --mw-m-main）。
  • ⚠️ 而 React 的项目详情那一套（.proj-detail .tabs/.tab，L2944-2984）现在还是下划线。也就是说：这一版是原型先走一步，把项目详情并到了通用那套 —— 落地时要跟着改 React 那两条（把 .proj-detail .tab 换成通用那套，或直接复用 .mw-root .tabs）。旧说法里"两套不合并"要撤回：形合并了，留着的是两处挂载（环是谁的、基路径不同）。
  • 面板内的"换一种看法"（列表 / 看板 / 四象限）仍用 .seg：它是面板里的选项组，不是页面级导航 —— 一级导航（这条栏）已经是一排胶囊了，面板里再用一排等重的胶囊会读成"两条导航"。
