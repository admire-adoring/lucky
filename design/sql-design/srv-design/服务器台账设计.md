# 服务器台账 · 数据库设计

**范围**：工作模块「服务器」分区（`/work` → 服务器台账）、服务器详情（`/work/servers/:host`）、
项目详情的运维发布记录与部署文档，在 SQLite 里的表。

**前缀**：`srv_`。这一簇**不属任何单一模块** —— 一台机器可服务任意 `scope` 的项目（`srv_server_project`
连到 `project`，没有 scope 限制），所以不用 `work_` 前缀（那是"只此一域"的承诺），另起一簇。

**共用约定**见 `../全局架构.md`。**依赖** `0001_init.sql`（`app_user` / `project`）。

**事实源**：

| 事实源 | 提供什么 |
| --- | --- |
| `src-tauri/src/server/srv/` | 仓储实现：机器 `list`…`delete`、发布记录 `release_*`、部署文档 `doc_*`。列名以它为准 |
| `src/api/servers.ts` | **写入路径**：`ServerInput` / `DeployReleaseInput` / `DeployDocInput` 与对应出参形状（`srv_*` 命令） |
| `src/lib/server-view.ts` | `toLedgerServer` —— 真实 `Server` → 台账视图形状 |
| `src/components/workspace/project-detail/AddServerForm.tsx` | 表单真正收集到的字段（`ServerFormDraft`） |
| `src/data/derive.ts` | `LedgerServer` / `LedgerGroup`（视图形状）；`buildDeploys` / `buildDeployDocs` 仍是演示数据 |
| `src/lib/server-conn.ts` | 连接状态（会话态，不入库） |

## 一、写入路径定了两件事

写入路径是 `src/api/servers.ts` → `shell` 的 `srv_*` 命令 → `server::Store`；
表单（`AddServerForm`）是界面上唯一的入口。它决定两处：

1. **`env` 是 4 档**：`prod` / `stage`（预发）/ `test` / `local`（本机）。表按写入路径取 4 档；
   视图形状 `LedgerServer.env` 只保留"生产 / 非生产"两档（卡片上只分这两态），中文名走 `envLabel`。
2. **凭据随台账落库、但落的是密文**（2026-11-04 改）：早期版本存本机钥匙串，
   签名 / 换构建 / 重装之后条目就没了，编辑页也读不回来。现在密码与私钥路径加密写进
   `secret` 列（AES-256-GCM），密钥是库同目录的 `vault.key`（0600，不进库、不进仓库）。
   ⇒ 库文件被复制去做排查、进备份时，拿到的是密文；换机迁移要连 `vault.key` 一起拷。
   `cred_ref` 保留为历史列，不再写。

## 三、关键列说明

### 3.1 `srv_server`

- `host` 是业务唯一键（路由 `/work/servers/:host` 用它），但**主键仍用 `id`** —— 机器改名时不至于
  让外键与历史记录全部跟着改。`host` 上单独一条 `UNIQUE`。
- `role_code`（web / db / cache）与 `env_code`（prod / stage / test / local）存 code，
  「数据库 / Web 层」「生产 / 预发」这类展示名留前端（D3）。
- `os` / `cores` / `mem_gb` / `disk_gb` 是**机器自报、连上一次后缓存**的事实。它们进表是因为
  服务器详情页的「概览」要放"没连上时也存在"的值；而负载读数（CPU / 内存使用率 / 运行时长 / 版本）
  要连上才读得到，**不落本表**（见 §五）。
- `secret` 是凭据密文（`v1:` 前缀 + nonce + 密文，hex）；明文只在保存与探测那一下存在内存里。
- `cred_ref` 是早期钥匙串方案的遗留引用，不再写。
- `removed_at` 表达"从台账收走"（软删）；`NULL` = 在册。

### 3.2 `srv_server_project`

一台机器服务多个项目是常态。**顺序有语义**：`sort_order` 首位是主项目，日志 / 部署 / 终端三条路由
都用它拼地址（`server.projects[0].id`）。⇒ 这张表必须有 `sort_order`，不能只做无序列的连接表。

### 3.3 `srv_path_group` + `srv_server_path`

分组是**每台机器自己的一套有序词表**（原型里叫 `pathGroups`）。它必须落表而不是从路径现算，因为：
① 组的顺序是声明的，不等于路径首次出现的顺序；② 组可以暂时没有路径（此时不显示，但组定义仍在）。
`srv_server_path` 用复合外键 `(server_id, group_name)` 指向它 —— 归类只能"选"，不能"填"新组。

### 3.4 `srv_term_session` + `srv_term_command`

终端页 2026-11-04 才接上真 SSH。这两张表**只做审计，不存命令输出**：

- `status` 三档 `open` / `closed` / `lost`。会话本体活在应用进程内存里（`srv::Hub`），
  进程一退那些连接就没了 —— 所以下次打开同一台机器时，先把上一条 `open` 改判 `lost`，
  否则库里会留着一条永远"开着"的假记录。
- `command_count` 是冗余计数：每跑一条 `command_count + 1`，会话列表不必再 `count(*)`。
- `srv_term_command` 冗余 `server_id`：查"这台机器敲过什么"不必 JOIN 会话表；
  退出码 `NULL` 表示命令没跑起来（连接断了 / 超时被本地掐），与"跑了但失败"不是一件事。
- 输出不落库：一条 `cat` 就是几 MB，存进来只会让库长胖；`output_bytes` 只回答"该不该截断"。

### 3.5 `srv_deploy_release`

- `released_at` 存 ISO 时刻，`'昨天' / '5 天前'` 是派生文案（D1）。
- `duration_sec` 存秒；回滚那条没有部署耗时 ⇒ 可空（`'2m 12s'` 不落列）。
- `result_code` 只有 `success` / `rollback` 两值。`changes` 一个字段两种读法（成功 = 变更说明，
  回滚 = 原因），与原型一致。
- `operator_code` 引用 `app_user.code`（前端出参就是 `'LY'` 这种码）。

### 3.5 `doc`

部署文档**归属项目，不归属机器** —— 服务器详情页那排书架是按项目分的（一台机器服务两个项目，
就看到两排）。所以只有 `project_id`，没有 `server_id`。

> 与 `work_doc` 不是重复登记：`work_doc` 是"全站文档的可检索入口"，本表是"运维现场要用的清单"。
> 原型两条口径都写了，`work-docs.ts` 的文件头也记了这一条。

## 四、索引

```sql
CREATE INDEX ix_srv_server_env      ON srv_server(env_code, role_code);   -- 环境 / 角色筛选
CREATE INDEX ix_srv_server_project  ON srv_server_project(project_id);    -- 项目视角分组
CREATE INDEX ix_srv_server_tag      ON srv_server_tag(tag_id);            -- 按标签反查
CREATE INDEX ix_srv_path_server     ON srv_server_path(server_id, sort_order);
CREATE INDEX ix_srv_release_project ON srv_deploy_release(project_id, released_at DESC);
CREATE INDEX ix_srv_release_server  ON srv_deploy_release(server_id, released_at DESC);
CREATE INDEX ix_srv_doc_project     ON doc(project_id, sort_order);
```

「台账」本身不是一个表，是 `srv_server` + `srv_server_project` 的连接查询（按 host 已经是唯一行，
因为 `host` 有 `UNIQUE`）。

## 五、不落表的东西（都判过）

| 内容 | 现状 | 判定 |
| --- | --- | --- |
| 负载读数（CPU / 内存 / 磁盘使用率、运行时长、当前版本、迷你折线、目录占用） | `ServerItem` 里现算 | **实时采集，不落本台账**：要连上才读得到，本页只报"没连上时也存在"的值。要沉淀就走监控域另开时序表 |
| `reclaim`（哪些文件可以清） | 池子里的声明 | **派生**：真实系统靠扫描磁盘得出 |
| `fsExtra` / `fsHome`（路径浏览器补项与落点） | 池子里的声明 | **原型脚手架**：真实实现走文件系统，不进库 |
| `path.preview`（文件内容预览） | 池子里的声明 | **真实实现读文件**，不进库 |
| 连接状态（`isConnected`） | `lib/server-conn.ts` 的模块级 Set | **会话态**：SSH 是这次会话里按下去的，刷新即回初值 |
| `roleLabel` / `envLabel` / `logCount` / `deployCount` | `derive.ts` 现算 | **派生**：展示名留 `meta`，两个计数由查询算 |
| 凭据（密码 / 私钥路径） | 表单收集 | **加密落库**：`srv_server.secret`，密钥在库同目录的 `vault.key`（见 §一） |
