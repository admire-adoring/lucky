## 0 · 先读：三条最重要的规则

**① 「面板」与「遮挡」是两组不透明度，不可混用。**
面板 α 决定「玻璃板有多实」，它同时影响两件**相反**的事（越高 → 内容区越洁净，越低 → 玻璃感越强），
所以它没有最优值、只有选点；遮挡 α 决定「压底衬」，由文字对比度反解、**有明确下界**。
混用会让「面板想更透」与「输入框要更实」互相绑架 —— 同一支 α 不可能既是 `.50` 又是 `.78`。

**② 面板色必须中性（色度 ≈ 0），「可见」靠明度差。**
`.g` 的底色是 `rgb(var(--g-panel-rgb) / var(--g-panel-a))`，所以**面板色的色度就是内容区色度的下限**。
带色的面板色（色度 26）会让内容承载区被染色到 23，且提高遮挡无效。

**③ 改任何材质令牌前，先确认它属于「硬约束」还是「可调旋钮」。**
硬约束由对比度反解，动它必须重算；旋钮是观感取舍，随便调。见 §4。

## 1 · 三层结构

```
① 刻度（原语）   --g-pa-1..5 / --g-oc-1..7      只被槽位引用，组件不直接读
② 槽位（语义）   --g-panel-a / --g-oc-field …    组件只读这一层
③ 档位（应用）   .g1 ~ .g4                      一次绑定「不透明度 + 模糊 + 饱和度 + 投影」
```

**为什么要有刻度这一层**：组件只读槽位，那么「把卡片整体调透一点」就只需要改一个刻度，
不必去翻二十个组件。如果发现自己在组件里写 `rgb(... / .5)` 这样的裸值，那是设计漏了槽位。

**档位是一次选型**，不是四个独立参数：

| 档位 | 用在哪 | 面板 α | 模糊 | 饱和度 | 投影 |
|---|---|---|---|---|---|
| `.g1` | 小控件 / chip | `--g-pa-1` .10 | `--g-blur-1` 12px | `--g-sat-1` 128% | `--g-sh-0` |
| `.g2` | 浮层面板 / 菜单 / 气泡 | `--g-pa-3` | `--g-blur-2` 20px | `--g-sat-2` 134% | `--g-sh-1` |
| `.g3` | **卡片 / 表格（正文承载）** | `--g-pa-4` | `--g-blur-3` 28px | `--g-sat-3` 140% | `--g-sh-2` |
| `.g4` | 外壳条 / 侧栏 / 顶栏 | `--g-shell-a` | `--g-blur-4` 44px | `--g-sat-4` 146% | `--g-sh-3` |

**用法**：`class="card g g3"`。**`.g` 是材质本体（写 background 与 backdrop-filter），
`g1..g4` 只写槽位变量 —— 两者必须同时出现**，只写 `g3` 会得到一个没有材质的空盒子。

## 2 · 令牌总表

### 2.1 · L1 底衬层

#### 面板不透明度刻度 `--g-pa-*`

| 令牌 | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--g-pa-1` | `.10` | 同 | 仅装饰 / 图标（不承载文字） |
| `--g-pa-2` | `.48` | 同 | 大字号（≥24px，仅需 3:1） |
| `--g-pa-3` | `.64` | **`.50`** | 浮层面板：菜单 / 气泡 / 分段控件 |
| `--g-pa-4` | `.76` | **`.64`** | 正文承载：卡片 / 表格（α_min 判据的下界在此档） |
| `--g-pa-5` | `.92` | 同 | 近实底：破坏性确认 / 数据表 |

> 亮色取值更低，因为亮色底衬本身亮、深色文字对比天然充足，面板可以更透。

#### 遮挡不透明度刻度 `--g-oc-*`

| 令牌 | 值 | 用途 |
|---|---|---|
| `--g-oc-1` | `.26` | 护底弱端（渐变收尾，不再承载文字） |
| `--g-oc-2` | `.38` | 表头（其上是 11.5px 元信息） |
| `--g-oc-3` | `.46` | 护底强端（页头顶部，裸页头文字所在处） |
| `--g-oc-4` | `.62` | 进度条槽（需与填充形成可辨差） |
| `--g-oc-5` | `.72` | 凹槽：开关轨道 |
| `--g-oc-6` | `.78` | 输入框（其内文字须 ≥4.5:1，故最实） |
| `--g-oc-7` | `.85` | badge 外环（需与背后底色断开） |

**遮挡刻度亮暗共用** —— 它们承载的是「文字与底色」关系，不随主题变。

#### 槽位（组件只读这一层）

```css
--g-panel-a      /* .g 面板本体，默认 --g-pa-3，由 .g1~.g4 逐档覆盖 */
--g-oc-scrim-hi  /* 页头护底强端 */   --g-oc-scrim-lo  /* 弱端 */
--g-oc-thead     /* 表头 */
--g-oc-meter     /* 进度条槽 */
--g-oc-groove    /* 开关轨道 */
--g-oc-field     /* 输入框 */
--g-oc-ring      /* badge 外环 */
```

#### 两种色（不可合并）

| 令牌 | 暗色 | 亮色 | 含义 |
|---|---|---|---|
| `--g-scrim-rgb` | `9 11 22` | `255 255 255` | **遮盖色** —— 配 `--g-oc-*` 使用，负责「压底衬」 |
| `--g-panel-rgb` | `70 72 84` | `211 213 219` | **面板色** —— 配 `--g-panel-a` 使用，负责「让玻璃板被看见」 |

**为什么不能合并**：凹槽（`.track` / `.bar`）表示「凹」，本就该与底衬同色系；
面板表示「浮」。两者共用**颜色**可以，共用 **α** 不行。

**为什么面板色必须中性**：面板色的色度就是内容区色度的下限（见 §0 规则②）。
亮色 `211 213 219` 的色度是 8；暗色 `70 72 84` 是 14。两者都靠**明度差**与背景分离。

**面板 α 与面板色必须同向调整**：α 越高，面板越趋近面板色。若面板色偏亮，
提高 α 会让面板**更亮** → 暗色浅字对比反而下降（实测 α `.70→.76` 时某处从 4.59 掉到 4.33）。
**提高 α 必须同时把面板色压暗。**

#### 其它

| 令牌 | 暗色 | 亮色 |
|---|---|---|
| `--g-shell-a`（外壳条，横跨视口需更稳，略高于 `pa-3`） | `.66` | `.48` |
| `--g-fallback-bg`（`@supports` 不支持 `backdrop-filter` 时的实底） | `rgba(10,12,22,.96)` | `rgba(255,255,255,.96)` |

### 2.2 · L2 模糊层

| 令牌 | 值 | 说明 |
|---|---|---|
| `--g-blur-1..4` | `12 / 20 / 28 / 44px` | **面积越大越厚** —— 小控件糊 12px 会失去形状 |
| `--g-sat-1..4` | `128 / 134 / 140 / 146%` | 补偿 `blur` 抹掉的色度。**不要超过 150%** —— 超过会放大背景色（透光率 >100%） |

> ⚠️ `blur` 只降低方差、不改变均值。底衬里没有可辨认的结构时，模糊「无从感知」——
> 这时加大 blur 是无效的，要改的是底衬（见 §7）。

### 2.3 · L3 高光层与磨砂

| 令牌 | 暗色 | 亮色 | 说明 |
|---|---|---|---|
| `--g-tint-a` | `.10` | `.07` | **贴顶高光带**峰值（顶部约 20% 内衰减到底） |
| `--g-tint-b` | `.025` | `.03` | 整体霜：几乎不可见，只为消除「纯色板」感 |
| `--g-frost` | opacity `.11` | opacity `.16` | 磨砂颗粒（SVG `feTurbulence`，140×140 平铺） |

**三条禁令**：
1. **高光必须是「贴顶带」，不能是「整面斜向渐变」。** tint 是加法性质的 ——
   同一个 α，给暗底衬加的绝对亮度是亮底衬的 3~5 倍，整面铺会把卡片漂白。
2. **磨砂颗粒必须叠在材质自身**（`.g` 的 `background-image` 最上层），
   放在环境层会被卡片自己的 `blur` 整个抹平。
3. **贴顶高光、`::before` 折射、`border` 三者已足够**，不要再加 `inset 0 1px 0` ——
   那是「白边」的来源（详见 `_audit/README.md` 坑 #11/#12）。

```css

--g-sh-2  卡片              --g-sh-3  外壳 / 对话框
```

亮色的投影带蓝调 `rgba(46,56,102,·)`，暗色用纯黑 —— 亮色纯黑投影会显脏。

#### 可辨边界（无障碍，与装饰边界**分开**）

| 令牌 | 暗色 | 亮色 | 门槛 |
|---|---|---|---|
| `--g-ctl-line` | `rgba(214,222,246,.56)` | `#4A443A` | **≥3:1**（SC 1.4.11） |
| `--g-ctl-line-2` | `rgba(224,231,250,.68)` | `#332F28` | hover / 强调态 |

**这两支和 `--g-edge` 不能共用**：卡片的边是装饰，可以很淡（甚至看不见也行）；
输入框的边是功能，必须看得见。**同理，浅色主题必须用实色** ——
半透明描边在亮底衬上会被稀释（有效 α 只有标称的 ~0.7）。

### 2.6 · 语义色

品牌只用于「可交互 + 标识」，语义只用于「状态」—— **两者不混用**。

| 令牌 | 暗色 | 亮色 | 依据 |
|---|---|---|---|
| `--ok` | `#6ee7b7` | `#04543d` | 亮色按「最不利彩底 L≈0.58」反解 → 5.32:1 |
| `--warn` | `#fbbf24` | `#7a4a02` | 彩底 5.13 / 白底 5.98 |
| `--bad` | `#ffc0ca` | `#96102f` | 亮色按最不利彩底 `(212,195,214)` 反解 → 5.3:1 |
| `--info` | `#93c5fd` | `#1d4fb8` | — |

每个语义色还有三支配套：`--<语义>-bg`（浅填充）、`--<语义>-line`（边界，需 ≥3:1）。

⚠️ **语义文字色不能沿用实色界面的值** —— 玻璃会透出背景的彩，最不利底衬比纯白更暗。
亮色 `--ok` 曾用 `#0b7a5c`：在彩底只有 3.65，**在纯白底也只有 4.25**（本来就偏浅）。
标定时必须按「彩底 + 纯白底」**双场景**反解。

### 2.7 · 模块色系（9 组）

**四层角色，各司其职，不可互换**：

| 角色 | 令牌 | 取值方式 | 用途 |
|---|---|---|---|
| 色团 | `--m-lt-1/2/3` · `--m-dk-1/2/3`（RGB 三元组） | 设计给定（**只改过 Color01 的色度补偿**） | 弥散背景 |
| 色团（全量） | `--a-<模块>-1/2/3`（hex） | 设计原值，**逐字保留** | 跨模块引用（如侧栏 9 个入口） |
| 强调色 | `--s-<模块>`（RGB 三元组） | 设计给定 | 图表主色、进度条、标签底色 |
| 填充色 | `--brand-a` / `--brand-b` | **同色相反解**，亮度 a=0.180 / b=0.170 | 按钮、激活项（承白字） |
| 文字色 | `--brand-ink` | 反解，**亮暗各一支** | 链接、tick、focus 边框 |

**为什么填充色要反解**：设计给的强调色直接作按钮填充时，白字对比度亮色 6/9、暗色 9/9 不达标
（`#F59E0B` 白字仅 2.15）。白字可行的填充亮度窗口极窄：

```
上界  L ≤ 0.183                             ← 白字 ≥4.5:1（固定）
下界  L ≥ 3 × (L(底衬) + 0.05) − 0.05       ← 随底衬变：亮 0.123 / 暗面板提亮后 0.169
```

暗色下窗口宽仅 **0.0143**。**渐变两端都必须落进窗口**，否则渐变中段会出现不可辨区段。

#### 背景结构

```css
background:
  radial-gradient(148% 124% at 5% -14%,   rgb(var(--m-lt-1) / var(--m-a1)), transparent 86%),
  radial-gradient(128% 108% at 106% 16%,  rgb(var(--m-lt-2) / var(--m-a2)), transparent 88%),
  radial-gradient(142% 118% at 62% 116%,  rgb(var(--m-lt-3) / var(--m-a3)), transparent 86%),
  linear-gradient(135deg, …底色…);
```

**三条规则**：
1. **「是色还是斑」由扩散半径决定，不由 α 决定。** 半径必须**大于视口**（130%~148%）——
   色彩铺满全屏、梯度极缓，才是「整片色调」。半径小于视口会形成可辨认的块（= 圆斑）。
   **α 决定「有多浓」，两者不能互相替代。**
2. **色团中心贴在视口边缘**（甚至略在视口外，如 `5% -14%`）。
   放进视口中央会让内容承载区直接吃到色彩（实测表内色度 11 → 18）。
3. **弥散 α（`--m-a1..3` / `--m-b1..3`）逐套独立** —— 色团色度差 10 倍，
   统一 α 会造成 2.2 倍浓度差。目标浓度：亮 28~32 / 暗 22~30。

> ⚠️ `dashboard`（微光夜语）的 α **有意高于其他套** —— 它是设计指定的「夜色要有颜色」，
> 打破了「9 套浓度归一」的约定。

### 2.8 · 间距 / 圆角 / 字阶 / 动效

```css
/* 间距（4px 基准） */

--t-xl:19px  --t-2xl:24px  --t-3xl:29px

/* 动效：安静优先 —— 只此一条缓动曲线 */
--ease:cubic-bezier(.22,1,.36,1)
--dur-fast:140ms  --dur:200ms  --dur-slow:320ms
```

数字一律用 `.num`（`font-variant-numeric: tabular-nums`）—— 否则数值变化时列会跳动。

## 3 · 组件写法

```html
<!-- 卡片（正文承载）-->
<div class="card g g3">…</div>

<!-- 浮层 / 菜单 -->
<div class="menu g g2 g--refr">…</div>

<!-- 外壳条 -->
<header class="topbar g g4">…</header>

<!-- 输入框：用「面」，边界另配 --g-ctl-line -->
<input class="input" style="--g-panel-a:…">   <!-- 见下 -->
```

**四条纪律**：

1. **`.g` 与档位类必须同时出现。** 只有 `g3` 没有 `g` = 没有材质（历史 bug，见坑 #1）。
2. **`g--refr`（边缘折射）只给大面积面板。** 控件档用实色描边 ——
   1px 控件上的折射会变成「双线」（功能边界 + 装饰折射相邻）。
3. **元素自身的背景不得延伸到 border 之下** —— 加 `background-clip:padding-box`，
   否则等于用自己的暗底稀释自己的描边。
4. **不要写裸值。** 需要新的不透明度时，先在刻度里加一格再引用。

## 4 · 硬约束 vs 可调旋钮

| | 硬约束（**动了必须重算/重测**） | 可调旋钮（随便调） |
|---|---|---|
| **文字色** | `--fg-*`、`--ok/warn/bad/info`、`--brand-ink` | — |
| **边界** | `--g-ctl-line` / `-2`（≥3:1） | `--g-edge` / `--g-refr-*`（装饰） |
| **填充** | `--brand-a/b`（白字 ≥4.5 且 vs 底衬 ≥3） | |
| **面板** | `--g-panel-rgb` 的**亮度**（与 α 同向） | `--g-panel-rgb` 的色相（但色度须 ≤10） |
| **不透明度** | `--g-oc-field` / `-thead` / `-meter`（承载文字） | `--g-oc-groove` / `-ring`（纯形） |

| **几何** | — | `--sp-*` / `--r-*` / `--t-*` |
| **动效** | — | `--dur-*` / `--ease` |

**判据**：某项是否承载「文字可读性」或「组件可辨识性」？是 → 硬约束。

## 7 · 已知取舍与限制

**① 内容区色度 14 / 16（门槛 ≤12）。**
`内容区色度 ≈ 背景色度 × (1 − α) × saturate放大` —— **背景越浓，内容区必然越脏**，
只能靠提高 α 抵消，代价是玻璃感（透光率）下降。当前是平衡点。

**② 暗色面板分离度 0.062（「清晰」区间的下限）。**
再提亮面板会吃掉文字余量（`--bad` / `--fg-3` 先不达标）。这是「面板明显 ↔ 文字可读」的真实取舍。

**③ 「模糊感」依赖底衬有可辨认的结构。**
`blur` 只降方差、不改均值 —— 底衬若只有自身已模糊的渐变，卡片内外没有清晰度差，
模糊就「无从感知」（注：门禁③ 的「结构衰减」测不出这件事，它测的是 `blur` 是否在工作）。

**④ 面板「可见」靠明度差，不是色度。**
代价是面板色偏中性灰，少了蓝紫色调。若想要带色面板，必须接受内容区被染色。

**⑤ 浅色主题的可辨边界必须用实色。**
半透明描边在亮底衬上会被稀释（有效 α 只有标称的 ~0.7）。

## 9 · 机械守卫（本仓库新增）

规范里最贵的那几条**写错了不会报错**，只会"看起来差一点"。所以实现里配了断言，
跑 `node design/run-gen.mjs` 时逐条检查（全部在 `gen-modules.mjs` 的结构自检块内）：

| 守卫 | 拦的是什么缺陷 |
| --- | --- |
| 旧材质类名不许出现在**标记**里（`glass-*` / `bg-surface*` / `shadow-xs\|sm`） | 旧令牌整片失效，而失效得很干净（背景变纯色，不报错） |
| 档位类 `g1~g4` 必须与 `.g` 成对出现 | 得到一个"有变量、没材质"的空盒子（§1 纪律 1 的原话） |
| 九个入口都要带 `mod-tile`，且 `data-module` 互不相同 | "每个菜单域一种颜色"缺一个 —— **只有截图能发现** |
| 色表必须同时给出 `[data-series=…]` 与 `[data-module=…]` 两个空间的规则 | 有一处不跟着变，而"哪一处没变"要对比两屏才发现 |
| 模块色槽（RGB 三元组）**只能出现在 `rgb(...)` 里** | 直接当 `<color>` 用不报错、不继承，而是静默落回 `@property` 的兜底值 → **九个模块同色**（本轮真踩到） |
| 瓦片不许再声明 `--s` | 与色槽撞名 → 入口底色被静默打回中性玻璃，而图标仍是彩色的，所以"看起来有颜色"（本轮真踩到） |
| 选中态必须排在 `.g.mod-tile:hover` 之后 | 同特异性靠源码顺序裁决，反了选中态会被 hover 盖掉 |
| 主题图标的选择器必须是 `:root:not([data-theme='light'])` | 暗色是**缺省**，写死 `[data-theme='dark']` 时"没有属性"匹配不上 → 默认主题下图标反了 |
| prism.css 的注释里不许出现「紧贴文字的注释收尾符」 | 实测：`--m-a` 后面接一个星号加斜杠，把注释**提前闭合**，浏览器错误恢复一路吃掉后面的 `:root {...}` —— **整块色表被丢弃**，九个模块取不到强调色。零报错、高亮正常、页面照常渲染（本轮真踩到） |
| prism.css 必须含 `@derived:modules` 标记 | 派生色必须由脚本反解写入，不能手抄（手抄一定会漂，而漂掉只有门禁能发现） |
| 极光色块的**半径 × 淡出止点 ≤ 100%** | 半径大于视口时色块本体落在屏幕外，只剩"渐变的整体偏移"，**没有可辨认的色块边界** → 「透过玻璃」与「什么都没透过」不可区分（§12 的根因）。⚠️ 判据必须是**乘积**不是半径本身：中央色雾 `72% × 72% = 52%` 是完全合法的 |
| 极光层**两套主题各 ≥6 个色块** | 层数少 → 页内色相单一；少一份主题 → 另一半页面没有色块。⚠️ 只收**声明了 `background-image` 的**规则，否则会误伤 `prefers-reduced-motion` 那条 `animation:none`（第一次写就误报） |
| `--m-mix` / `--m-heat` 必须有声明 | 缺了它们，`color-mix(… var(--m-mix) …)` 变成非法值 → **整条 `background-image` 被丢弃**（回落成纯色底衬），零报错 |

**三条流程纪律（都是实测换来的）**：

1. **"源码看着对"不等于"渲染是对的"**。本轮两次栽在这上面（`--accent: var(--s)`、
   注释里的星斜），两次都只有**读计算值 / 量像素**才能定位。
   `design/debug/probe-series.mjs` 读计算值，`design/debug/*.py` 量像素。
2. **量不出差别的测量，等于没量**。第一次量"九个模块是否各是一色"时，
   18 张截图的数值一模一样，我差点去改 CSS —— 真实原因是**截图工具只改了初值，
   而页面脚本会把它覆盖回当前模块**。判据：**外部工具驱动状态必须走页面的状态入口
   （点一下），不能去改它的内部属性**；脚本是状态的唯一所有者。
3. **同一个问题连推两轮都没解决时，别再推第三轮 —— 去找参照版，把它量出来当目标。**
   §10/§11 两轮都在"从原理推"（透射率 → α_min → ΔL/×耦合），每一步都有道理，
   合起来仍不是用户要的那件事。§12 换了做法：先在仓库里找出**用户认可的那一版**
   （`workbench_v2.html`，迁移前的旧玻璃令牌），渲染、量指标、当靶子 —— 一次就定位到
   真正的差别（色块半径 128~148% vs 18~40%）。
   ⚠️ 配套的一条：**跨版量指标时，别用过拟合的指标**。这轮先后用过
   "格间标准差 / 亮度极差 / 众数色 ΔL"，前两个都因为**两版布局不同**而误导过
   （卡片占比、hero 结构都不一样）。判据：**换版比较时，指标必须能在两版里指向同一批物体**；
   指向不了就换指标，或者配合"看图"定案。最终定案那张图
   （`/tmp/glass-final/对照-优化前后.png`）比任何单个数字都有说服力。

## 10 · 第二次修订：把"玻璃感"找回来（2026-09-20 上午）

**症状**：用户看完第一版落地结果，一句话 ——「玻璃组件怎么都没有」。
**先查"有没有"**：读计算值确认 `.g` 的三层（磨砂 + 霜 + 贴顶高光）全部生效、
`backdrop-filter` = `blur(28px) saturate(1.4)`、档位槽位都解析正确 —— **材质一件都没丢**。
所以问题不是"没有玻璃"，而是**参数让玻璃读起来不像玻璃**。

排查方式：用**注入覆盖令牌**跑六组对照（`design/debug/experiment-material.mjs`），
一次拿到 N 个候选的截图再挑 —— 观感问题最快的收敛方式，而且不动源码。

**结论是三条原因叠在一起，没有一条是"代码没写"**：

| # | 原因 | 为什么读成"纸板" |
| --- | --- | --- |
| ① | 亮色**面板色是中灰**（`211 213 219` @ .64），比底衬还**暗** | 亮底衬上"更暗"= 一块灰板；"更白"才读作"被光照亮的玻璃"。旧版是 `rgba(255,255,255,.70)`，即"更白" |
| ② | **边缘折射铺到了对角线 42% 处**，而亮色那支是暖灰（`120 112 96` @ .17） | 名字叫"边缘"、停点在中间 → 每张卡泛一层**米黄**。截图 2× 放大一眼可见 |
| ③ | 环境底衬的**彩度不足** | 玻璃 = 背后有可辨认的颜色被模糊/染色。背后近乎灰白时，再好的材质也只是灰板；同时"每个菜单域一种颜色"也几乎看不出来 |

### 三处改动的判据（不是调参，每条都在改一个"前提"）

**① 亮色面板色 `211 213 219` → `240 243 248`（近白）。**
规范那条「面板『可见』靠明度差」的前提是**底衬近白**（它自己写着"亮色取值更低，因为亮色底衬本身亮"）——
那时面板只能靠"更暗"被看见。而本原型的底衬是**模块色团铺出来的彩色场**（规范 §2.7 自己的结构），
面板靠"更白"就被看见了，而且更对。
⚠️ 规范另一句「面板色偏亮 → 提高 α 会让面板更亮 → 暗色浅字对比下降」**只对暗色成立**（浅字压更亮的底衬）；
亮色是深字，面板变亮只会**提高**对比（实测 `--fg` 10.91 → 14.7，`--fg-3` 4.47 → 6.02）。
**跨主题照抄一支值，就会把上一主题的结论搬到下一个主题上。**

**② 折射停点 42% → 9%，并在 30% 收干净。**
「边缘折射」是**边缘**现象，峰值落在元素中心不是"边缘"。暖色那支只留几个百分点当冷暖色边。
（颜色与 160deg 方向仍照规范，只改停点。）

**③ 背景浓度：修两处**
- 规范 §2.7 的背景结构第 4 层写的是「linear-gradient(135deg, …底色…)」——**底色未指定，是留白的旋钮**。
  这里就用**当前模块的强调色**（`--s`）稀释后铺满（`--m-tint`，亮 .20 / 暗 .34）：
  色团那三支是**淡彩**，单靠它们铺不出"整片色调"，而"每个菜单域一种颜色"要的正是整片能看出是哪一域。
- ⚠️ **弥散 α 的归一方向写反了**：原来是 `α ∝ 1/彩度`（淡色团铺得最足），
  正确方向是 `α ∝ 彩度`。想清楚合成公式就不会错：
  `合成 = (1−α)·底衬 + α·色团`，偏离底衬的程度 `∝ α · |色团 − 底衬|`；
  色团1 那几支几乎是白（`#DEFAF3` 彩度 ~0.03），**它们与底衬的差是"更白"**，
  铺得越足画面越白。写反的后果不是"不够浓"，而是**越调越白**（实测彩度一直卡在 0.8~2.8 上不去）。

**④ 暗色面板色 `70 72 84` → `82 85 98`（跟着底衬挪一档）。**
规范 §5 耦合清单：`--m-a*`（背景浓度）一动，**面板分离度必然要重算**。
实测底衬彩度 4.4 → 10.2 的同时亮度也 0.028 → 0.033，面板没动 → ΔL 0.0624 → **0.0436（"清晰"跌成"可辨"）**。
所以补一档把 ΔL 拉回 0.0628。⚠️ 规范那句"再提亮会吃掉文字余量"这次**不成立** ——
暗色浅字余量很足（`--fg` 7.9:1），提亮后面板分离度与文字对比两头都够。
**先量再改，别照抄结论。**

### 修订后的实测（两个主题都对上了规范基准）

| 门禁 | 亮色 | 暗色 | 规范 §6 基准 |
| --- | --- | --- | --- |
| 面板分离度 ΔL | **0.1124** 清晰 | **0.0628** 清晰 | 亮 0.110 / 暗 0.062 |
| 文字对比（实测底衬） | `fg` 14.7 · `fg-2` 7.56 · `fg-3` 6.02 · `mute` 4.41 | 6.83 · 5.05 · 4.66 · 3.42 | 正文 ≥4.5 / 元信息 ≥3 |
| 底衬彩度（九套区间） | 0.8 ~ 6.2 | 1.8 ~ 10.2 | — |

修订前的对应值：ΔL 亮 0.129 / 暗 0.0624；文字 10.91 · 5.61 · 4.47 · 3.28；
彩度 亮 0.8~2.8 / 暗 1.2~4.4。

## 11 · 第三次修订：优化设计令牌，把"玻璃感"做成一档可选的值（2026-09-20）

**症状**：第二轮改完亮度对比后，用户的反馈是「那就优化设计令牌，现在**一点都看不出**玻璃感」。

**这次先量化了一个假设**（`design/debug/measure-frost.py` / `measure-frost2.py`）：
玻璃的可读性 = **透过率 × 底下的大尺度结构**，两者缺一不可。
沿扫描线量高频能量：卡片内 ≈ **1.5**、卡片外 ≈ **10~37** —— 结构衰减 ~90%，
也就是说"模糊"**确实在工作**。所以问题不在模糊，在于两件事：

| # | 原因 | 判据 / 实测 |
| --- | --- | --- |
| ① | **底下几乎没有可供显示的结构** | ⚠️ 环境颗粒被**衰减了两次**：颗粒 SVG 里 rect 的 `opacity` 与所在层的 `opacity` 是**相乘**的。上一版复用了 `.g` 内部那支磨砂图（烘死 `opacity=.16`）再乘 0.26 → 净 **0.04**，而旧版设计是 0.5×0.3=**0.15**。底衬于是"平坦"到模糊无从感知 |
| ② | **面板 α .64 把背景挡完了** | 透过率只剩 36%，且这 36% 落在一片低速变化的渐变上 → 读成"染了色的板" |
| ③ | **没有"口沿"** | 面板越透越需要一条明确的收边。规范禁止再加 `inset 0 1px 0`（白边的来源），但不禁止**把已有的 border 上边调亮** —— 仍是三条机制，只是其中一条换了颜色 |

### 关键的一步是**重算 α_min**，而不是"把 α 调小一点"

规范的 `.64` 来自 α_min 判据，而那条判据的本意是**保证正文对比度**，它随面板色变：

```
正文 ≥4.5:1  ⇒  面板合成亮度 ≥ 4.5 × (深字亮度 + 0.05) − 0.05 ≈ 0.202
实测本原型的面板合成亮度 = 0.78  ⇒  余量是判据下界的 3.9 倍
```
所以 `.64` 在本原型里**远不是下界**，真正限制下界的是**面板分离度 ΔL**（α 越小面板越贴近底衬）。
于是亮色 α 可以放到 `.30 / .36`（ΔL 仍 0.127，在"清晰"），把余量换回玻璃感。
⚠️ **暗色不能跟着降**（两端都在暗端，一降面板就沉回底衬）—— 实测 .66 时 ΔL = 0.0445，
"清晰"跌成"可辨"，所以暗色那一列是 `.32~.54 / .70~.82` 的窄区间。

### 顺手把"背景浓度"与"面板分离度"的耦合再验一次

`--m-tint`（背景色罩）与 `--g-noise-op`（环境颗粒）一动，底衬的**亮度**也跟着动，
所以**每调一次背景都要重测 ΔL 与文字对比**。这不是理论风险：本轮调完背景后
暗色 strong 的 ΔL 从 0.0624 一路掉到 0.0445，而它自己不会报错。

### 交付形态：玻璃档位（三档 × 两主题）

玻璃感 = **透过率 × 背后结构**，它和"内容底衬有多干净"是**反向**的 —— 所以没有唯一的好值，只有选点。
把选点做成档位（`<html data-glass="quiet|standard|strong">`），这件事就从
"改令牌 + 重测对比度"变成"选一个名字"，而**三档都已经过门禁**：

| 档位 | 亮色 α | 亮色 颗粒/色罩 | 暗色 α | 暗色 颗粒/色罩 | ΔL 亮 | ΔL 暗 | 定位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `quiet` | .46/.56 | .09 / .28 | .58/.86 | .09 / .18 | **0.1376** 清晰 | **0.0727** 清晰 | 内容洁净优先 |
| `standard` | .36/.46 | .16 / .42 | .50/.80 | .20 / .24 | **0.1546** 清晰 | **0.0601** 清晰 | 折中 |
| `strong`（默认） | .30/.36 | .24 / .58 | .42/.76 | .32 / .30 | **0.1689** 清晰 | **0.0452** 清晰 | 最像玻璃 |

文字对比（实测底衬）：`--fg` 亮 14.18 / 13.56 / 12.95 · 暗 6.55 / 6.49 / 6.32；
`--fg-3` 亮 5.81 / 5.55 / 5.30 · 暗 4.47 / 4.43 / **4.32**。
⚠️ **暗色的 `--fg-3` 在"最透"这一档略低于 4.5**（4.32~4.47，12.5px 三级文字）——
这是"最透"的已知代价；要严格 AA 就用 `quiet`(4.47) / `standard`(4.43)。
⚠️ **暗色三档的 α 全部明显高于亮色**，而且色罩整体压低：暗色底衬一旦被色罩提亮，
面板就**再也拉不开 ΔL**（实测色罩 .34 时 ΔL = 0.0421、"可辨"；压到 .30 并抬 α 才回到 0.0452）。
**暗色的"玻璃"靠颗粒与面板本身，不靠背景亮。**

### §8 差异清单的追加项

| # | 项 | 本文原来怎么说 | 实际怎么落 |
| --- | --- | --- | --- |
| ⑫ | `--g-pa-4`（亮） | `.64` | **`.30 ~ .46`（按档位）** —— 见本节 α_min 重算 |
| ⑬ | `--g-pa-3`（亮） | `.50` | **`.30 ~ .46`（按档位）** |
| ⑭ | 环境颗粒的强度来源 | 未规定 | 独立一支满强度的 SVG + 单支 `--g-noise-op`（亮 .16 / 暗 .20 基准）—— **不许复用 `.g` 那支烘死透明度的图**（相乘会静默衰减两次） |
| ⑮ | 上沿口沿 | 禁令 3 禁止 `inset 0 1px 0` | 未违反：加的是 `--g-edge-lip`（**border 上边的颜色**），机制仍是三条 |
| ⑯ | 背景第 4 层 | `linear-gradient(135deg, …底色…)` | **两段**（强 → 弱 → 强）：一段只给"整体偏色"，两段才在画面中部造出**大尺度高低差** |

## 12 · 第四次修订：重建极光层，让"底下真的有东西可看"（2026-09-20）

**症状**：第二轮改完亮度对比、第三轮做完成档位之后，用户的反馈仍然是
「那就优化设计令牌，现在**一点都看不出**玻璃感」。

### 这次换了方法：先找回"参照版"，再去够它

前两轮都在**从原理推**（透射率、α_min、ΔL），推出来的每一步都有道理，但合起来
仍然不是用户要的那件事。所以这一轮先问："用户认可的到底是哪一版？"

在 `design/` 目录里找到了 **`workbench_v2.html`**（09-19 21:12，迁移前、旧玻璃令牌），
渲染出来一看就清楚了 —— 它有**清晰可见的彩色色块**铺在卡片底下，卡片是浮在色场上的
亮霜面。于是把它**量出来当目标**，而不是继续推：

| 指标（粗网格 8×6，量的是"大尺度结构"） | v2 参照版 | 优化前 | 优化后 |
| --- | --- | --- | --- |
| 格间标准差 R / G / B | **17.39 / 16.99 / 4.22** | 11.73 / 9.71 / 6.24 | **16.78** / 11.31 / 5.69 |
| 彩度极差 | 0.253 | 0.201 | **0.279** |
| 亮度极差 /255 | 66.2 | 39.5 | 52.9 |
| 面板分离度 ΔL（强档·亮） | **0.351** | 0.031★ | **0.3006** |

★ 这一格的两种量法差很多（另一法是 0.1689），因为"卡片区域"的众数色在优化前
**本身就是底衬色**（卡片与底衬几乎同色，众数落在谁身上都不一定）。这正是"卡片没有浮起来"
的量化表现；优化后两种量法开始收敛。

### 根因：不是"玻璃不够"，是**色块的边界跑出了屏幕**

把两版的极光层逐层拆出来对比，差别只有两个数：

| | v2 参照版（8 层） | 优化前（4 层） |
| --- | --- | --- |
| 色块半径 | **18% ~ 40%** | **128% ~ 148%** |
| 色块颜色 | **饱和**（品牌色原值，α 0.16~0.52） | 淡（色团原值） |
| 色罩 | 无 | `linear-gradient(135deg, …)` 近全屏，α 峰值 ≈ **1.04** |

判据：**`blur` 只降低方差、不改变均值**。半径大于视口时，色块本体落在屏幕外，
画面上只剩"渐变的整体偏移"，**找不到任何可辨认的色块边界** —— 而玻璃要显示给用户看的
恰恰是色块边界。于是「透过玻璃」与「什么都没透过」在观感上**不可区分**，面板再透也没用。

⚠️ 单独看代码是看不出问题的：`radial-gradient(148% 124% at 5% -14%, …)` 完全合法、
高亮正常、**渲染无报错**。

### 精确判据是「半径 × 淡出止点 ≤ 100%」，不是「半径要小」

这条一步就写错过（见 §9 守卫表）：第一版守卫拦"半径 > 70%"，结果把第 ⑧ 层
（中央色雾，72%×72%）一起拦了 —— 它**是**大半径，但它的淡出止点 72% 让
`72% × 72% = 52%`，边界稳稳落在视口里。
所以判据落在**乘积**上：渐变要在视口内淡干净。

| 写法 | 半径 × 止点 | 判定 |
| --- | --- | --- |
| `148% 124% … transparent 86%` | 127% | ✗ 边界在屏幕外 |
| `30% 11% … transparent 76%` | 23% | ✓ |
| `72% 62% … transparent 72%` | 52% | ✓（色雾） |

### 两处改动

**① 8 个小而饱和的色块**（位置/半径/停点逐层沿用参照版），色相仍按模块走：

```
色块颜色 = color-mix(in srgb, 色团色 × --m-mix, 本模块强调色)
色块 α   = 该色团的弥散 α × --m-heat
```

两个新旋钮（都声明在 `:root`）：

| 旋钮 | 作用 | 为什么不能合并 |
| --- | --- | --- |
| `--m-mix`（75%） | 色块**是什么色** | 色团是淡彩、强调色是饱和的；纯色团在"色团本身就近白"的那几套（微光夜语的 `#EED0F2`）会淡到看不见边界，纯强调色又会把页内色相变化抹平 |
| `--m-heat`（0.75） | 色块**有多浓** | 色相不对时调 heat 只会得到"更浓的错色" |

⚠️ `color-mix` 的两个入色**带同一个 α** 时结果的 α 就是它（按 α 预乘插值），
所以 `rgb(var(--m-lt-1) / calc(var(--m-a1) * var(--m-heat)))` 这一支同时决定了色与浓度。

**② 暗色 `--m-tint` 上限由 ΔL 决定，不由"想多浓"决定。**
底衬在暗色里每浓一分，亮度抬一分，面板分离度掉一分：
实测 tint `.30` → ΔL **0.0403**（"清晰"跌成"可辨"），降到 `.22` → **0.0490**。
同一件事在亮色里是**反的**（面板比底衬亮，底衬越浓 ΔL 越大），
所以两列的 tint **不是同一个数按比例缩放**，是各自解出来的：

| 档位 | 亮 tint | 暗 tint |
| --- | --- | --- |
| quiet | .28 | .18 |
| standard | .42 | **.20**（原 .24） |
| strong | .58 | **.22**（原 .30） |

### 修订后的实测（六档全部落进"清晰"，且**文字对比同时变好**）

| 档位 | ΔL 亮 | ΔL 暗 | `fg` 亮/暗 | `fg-2` | `fg-3` | `mute` |
| --- | --- | --- | --- | --- | --- | --- |
| quiet | 0.1751 | 0.0729 | 15.3 / 7.14 | 7.87 / 5.28 | 6.26 / 4.88 | 4.6 / 3.58 |

`219° 330° 278° 138° 300° 97° 355° 196° 173°` —— 9/9 不同，彩度 0.23~0.40。

## 13 · 落地到应用（`src/**`）：两套材质并存与四条接线规则（2026-09-20）

把设计原型实现进正式代码时，令牌层不是"搬过去"就完了 —— 应用里**已经有一套**玻璃材质，
两者会并存一段时间。这一节记的是接线方式与随之而来的四条纪律。

### 接线：`index.css` 依次导入三份

```
@import 'tailwindcss';            ← Tailwind v4，输出落在 @layer theme/base/components/utilities
@import './prism.css';            ← Prism 令牌（无 layer）
@import './workbench-hero.css';   ← 工作台 Hero 的 817 行空间编排
```

**顺序不是风格问题，是胜负问题。** 实测确认：`--color-ink-400` 解析成 `#5f6785`
（Prism 的 `--fg-mute`），而不是 `index.css` 的 `@theme` 里那个 `#74808f`。
原因是 **Tailwind 把 `@theme` 的输出放进 `@layer theme`，而 prism.css 不带 layer ——
无 layer 的声明一律压过有 layer 的，与特异性无关**。
这条一旦断掉，`--color-ink-*` 这类旧别名会安静地回到旧玻璃取值：类名还在、
页面照常渲染，只是颜色整套换回去了。

### 纪律一：两套材质分工，不互相替换

| 用在哪 | 材质 | 颜色令牌 |
| --- | --- | --- |
| 工作台（新写的 `src/components/workbench/**`） | Prism 的 `.g` + `.g1~.g4` | Prism（`--s` / `--fg-*` / `--line`） |
| 既有页面（项目列表 / 详情 / 登录） | 旧玻璃 `glass-panel` / `glass-bar` / `glass-soft` | 同上（经 prism.css §6 的别名） |

**颜色已经统一到 Prism，材质还没有。** 这是刻意的：颜色可以靠别名一次接通，
材质不行 —— 规范要求档位与本体成对出现（α + 模糊 + 饱和度 + 投影绑在一起），
`glass-*` 那几个工具类表达不了。既有页面要换材质，得逐个组件改 class，
那是独立的一轮，不该混在这次里做。

### 纪律二：`build-css.mjs` 必须把这两个 `@import` 摘掉再编译

这个脚本把 `src/styles/index.css` 编译成 `style#lucky-y-tw` 内联进**原型**。
而 index.css 现在是应用的入口、已经拉进了 prism.css 与 workbench-hero.css，
原型又**分别**内联了这两份 —— 不摘的话同一份令牌与同一套 hero 几何会出现两遍：
体积翻倍，且 `@property` 与同特异性规则重复注册会让过渡行为变得不可预期。

判据：这里要的是「应用的**布局工具类**」，不是「应用完整的样式入口」。
脚本里对这两行做了存在性断言 —— 导入写法一变就报错，而不是静默地内联两遍。
（实测：摘掉之后原型的产物哈希与改动前**逐字节一致**。）

### 纪律三：工作台只渲染当前模块那一份

原型用 `<div hidden>` 藏另外 8 份面板（9 模块 × 5 磁贴 = 45 块 DOM 常驻），
应用里改成**条件渲染** —— 切模块时只挂当前那一份。
判据：`hidden` 是"静态页面的切换手段"，React 里有更好的表达；
45 块磁贴常驻会让每次切模块都要 diff 一整片不相干的树。

### 纪律四：`data-series` 仍然写在 `<html>` 上，不进 Context

整页氛围（极光底衬）由 `[data-series="<模块>"]` 驱动，而消费它的元素
**不在工作台组件的子树里**（助手栏是同级兄弟）。走 Context 要让每个远房组件
都订阅一次；写属性是"一次写、全页生效"。写在 `useEffect` 里，不放 render 期间。

⚠️ 与原型的一处差异：`data-accent` 由 React **声明式**写在 Hero 的 section 上
（原型是脚本运行后才补），所以首帧就有正确的强调色，不会先闪一下兜底靛蓝。

### 内容层：生成物而非手抄

9 个模块 × 5 磁贴 + 焦点 + 对话（约 70 KB）**由脚本从 `gen-modules.mjs` 导出**，
写成 `src/data/workbench-content.ts`，带 `--check` 防过期 —— 理由与"CSS 不手抄"一致。

⚠️ 还配了一条**口径守卫**：导出时把项目投影压成指纹带进生成物，
`src/data/workbench.ts` 拿 `PROJECTS` 现算一遍比对，不一致就报错。
因为 `gen-modules.mjs` 里的 `P` 是 `projects.ts` 的手工投影，两处就会漂，
而漂了之后页面照常渲染，只是"工作台说 164 条任务、项目页说 166 条"。
