# 个人系统 · 项目长期约定

## 【最高优先级 · 全局约束】本工作区永久执行规则（2026-09-26 用户明确指示）

适用范围：**本工作区（`design/study`）内的所有对话与所有任务**，持续生效，用户无需再次声明。以下三条为硬约束，优先级高于其它任何流程/技能中的同类建议：

1. **禁止截图验证** —— 不启动浏览器截图、不调用截图类工具、不做"渲染后截图取像素"这类校验。需要确认页面效果时，直接说明"请在浏览器中自行查看"。
2. **不添加额外说明** —— 只交付被要求的内容，不追加解释、背景、总结、"补充建议"、"可选优化"等未被请求的段落。回复保持极简。
3. **禁止编写或运行任何测试** —— 不写测试文件、不跑测试命令、不做"验证性脚本"。任务完成即结束。

冲突处理：若其它 skill / 历史约定要求"截图验收""跑一遍测试""补充说明"，一律以本节为准并跳过该步骤。

## 模块与对象归属（学习模块相关）

顶层模块：工作台 / 任务 / 日程 / 生活 / 工作 / 学习 / 项目 / 知识库 / 设置。
学习模块 **9 个分区**：概览 / 目标 / 技能 / 资料 / 题库 / 笔记 / 复习 / 练习 / 项目。
（**没有「输出」分区** —— 本系统个人自用、不面向发布；理由与替代方案见"四条边界"。）

**对象归属（唯一存放处）**
| 对象 | 家 | 状态字段 |
|---|---|---|
| 目标 | 学习·目标 | 期限 · 完成度 |
| 技能 | 学习·技能（能力地图） | 等级 · 缺口 |
| 资料（外部原件） | 学习·资料 | 进度 %（读到哪）· 来源 |
| 卡片（问→答） | 学习·题库 | 掌握度 · 来源 · 标签 |
| 笔记 | 学习·笔记 | 成熟度（速记/文献/永久/主题） |
| 练习记录 | 学习·练习 | 正确率 · 耗时 · 轮次 |
| 项目 | **顶层·项目** | 进度 · 里程碑 · 期限 · 验收方 |
| 到期排程 | 学习·复习（调度器） | 到期 · 间隔 |

**判定判据（机械，不靠主观）**
1. **卡片（题库）vs 练习**：根判据 = **题库跟踪"我知不知道"，练习跟踪"我能不能做出来"**。
   三条一秒可判的检验（任选一条，结论一致）：
   - 需要打开编辑器或画板吗？需要 → 练习；只用嘴/笔写几个关键词就行 → 题库。
   - 做不出时丢的是什么？丢记忆（背过但忘了）→ 题库；丢技能（懂原理但写不出）→ 练习。
   - 这个界面扮演什么角色？就是工作台（点开卡片翻面自评，一轮在此结束）→ 题库；只是记录本（真正的活在 VS Code / 白板里干）→ 练习。
   推论：**编程题的"套路"在题库背（20 秒），"落地"在练习做（20 分钟）**；题型套路是可背的知识点，某道题的 AC 是一次练习。练习不只有编程题，还含系统设计、白板口述、复盘写作（对内）。
2. 有没有"外部的、能被读完的原始件"→ 有 = **资料**；没有 = **笔记**。
3. 需要 git 仓库吗（多文件 / 会继续改）→ 需要 = 升为**项目对象**；只是当次片段 = 留练习记录当附件。
4. 有人等它吗（验收方 / 上线日期）→ 有 = 项目的工作/生活域；没有 = 项目的学习域。
5. 归档判据：还能源出价值吗（被真实工作复用 / 别人在用）→ 不能就归档（练手项目不该长期占项目列表）。

**四条边界（防止反复争）**
- 学习 = 过程与材料；知识库 = 沉淀的成品（一个主题的最终答案）；项目 = 有交付物的执行。
- **管道：资料（外部原件）→ 笔记（我的加工）→ 知识库（成品）**。终点是知识库，不是"发布"。
- **「输出」分区已删除（2026-09-25）**：它天生是按"对外发布"设计的（独有字段＝渠道 / 发布日 / 反馈），而本系统是个人自用、用户明确不需要分享 ⇒ 过不了"状态独立"闸门。它真正有价值的那部分（把学到的东西整理成讲得通的成品）由**笔记的主题级**（成熟度顶端）承担；"讲一遍检验真懂"由题库的卡 + 练习的白板口述承担；需要给人看的凭证（开源项目）归顶层项目模块。
- **笔记 / 知识库 的判据 = 给谁看**：只有我 = 笔记；我先沉淀、将来复用 = 知识库。
- 剪藏必须拆两条：原件进资料、我的批注进笔记，用 source 互相指。
- 卡片只有一个家（题库）：面试题与从笔记生成的卡都在那里，按来源筛；笔记里不再有"闪卡"。
- 一次练习可关联多张卡（多对多，不算重复）；到期排程只实现一套（复习）。

**命名规则**：二级枚举里，**实体词不许撞名**（曾经的"练习·题目" vs "题库"、"笔记·闪卡" vs "题库" 都已改掉）；**状态词允许跨分区重复**（目标/项目各有"进行中"，它修饰的是各自的对象，不是同一个东西）。

**三级的取舍（2026-09-25 定稿；前一版"枚举→chip、对象→三级"已被推翻）**
- 用户指出：题单 / 主题"不算子菜单，就相当于分类"。**成立** —— 它们是"同类对象的集合"（多重归属），不是"父对象的组成部分"（唯一归属）。
- 严判据：**三级 = 父对象的组成部分，只能有一个父级**（书的章节、目标的关键结果、项目的里程碑）；**分类 = 集合，可同时属于多个**（题单、主题、标签、公司）。
- 一秒检验：**同一个东西会不会出现在两个子页里？** 会（《两数之和》同时在 LeetCode 75 与剑指 Offer）⇒ 分类 ⇒ chip / 选择器；不会 ⇒ 真子级 ⇒ 才可以占一层。
- **结论：学习模块的圆盘只有两级**（模块 → 分区），9 个分区平级，没有任何分区带三级。
- 分类的呈现：数量会长 ⇒ **页内顶部选择器**（题单）；固定且少（≤6）⇒ chip（成熟度、状态、类型）。分类天生可能几十个，所以它适合选择器而不是菜单层级。
- 真子级的正确位置是**详情页内的目录 / 锚点**（书 → 章节、目标 → 关键结果、项目 → 里程碑）——那是页面内导航，不是全局导航。
- 交互契约（若将来真加了子级）：四处入口（圆盘三级 / 图标列 / 键盘 / 中心门）共用一份 `applyChildView`；下钻即应用第一个子项；返回即回全集。

## 跨模块共享视图与侧栏槽区
项目对象归顶层「项目」模块，学习模块的「项目」分区只挂**同一份 UI**：同一数据源 + 同一个渲染函数（壳传 filter）+ 同一个详情函数。共享块必须挂可见标记（`共享视图 · 来自 XX 模块`），否则评审者会默认它属于当前模块，然后提"这里再加个字段"——漂移从这句开始。

**圆盘下方栏（`.sidebar-slot`）=「今天该干什么」的支撑区**，不是第二个导航、也不是报表。四个槽各回答一个问题：
| 槽 | 回答 | 内容 |
|---|---|---|
| 今日（默认） | 现在做什么 | 4 条可点入口：待复习 / 今日计划 / 薄弱题 / 继续在学资料 |
| 快捷 | 记点什么 | 6 个窄按钮：新建笔记 · 录入题目 · 添加资料 · 记一轮 · 复习卡 · 能力地图 |
| 轨迹 | 我刚动过什么 | **时间序且跨分区**的最近动作（按分区排的列表等于把圆盘抄一遍） |
| 进度 | 还剩多久 · 走到哪 | 头条=最近截止目标的剩余天数；下面三行=目标进度 / 本周时长 / 题库掌握 |

**「进度」槽的取数规则（不绑场景，2026-09-25 定）**：槽的语义是"还剩多久 + 走到哪"，**不是"面试冲刺"** —— 名字与内容都不该预设"正在求职"，否则非求职期这个槽永远是空的。规则：有带期限的目标 ⇒ 头条「N 天后 · 最近截止的那个」；一个都没有 ⇒ 退化为「连续 N 天 + 本周时长」。下面三行口径固定，其中"目标进度"与头条同源（目标名只在头条出现一次）。

三条排除项：分区导航在圆盘 ⇒ 不放分区列表；回顾性统计在概览 ⇒ 这里只放**今日口径**；AI 常驻入口在顶栏 ⇒ 不放对话面板（212px 宽的对话面板不可用）。
两条自检：① 槽里每一项能不能"点一下就到现场"，只能看不能动的数字最多留 2 条；② 收起态整块隐藏 ⇒ 它承载的东西必须是可选辅助，不能是唯一入口。

## 分区独立原型页（把一个分区从模块主页里单拎出来看）
- 命名：`{模块}-{分区}-index.html`，放同一目录（对齐 work 的 `工作-项目-项目详情-运维-index.html`）。例：`design/study/学习-目标-index.html`。
- 配方 = **复制模块主页、只换内容区**：外壳（顶栏胶囊 / 超级菜单 / 圆盘 + 图标列 / 槽区 / 主题 / 命令面板）与令牌层不重写，`cp` 之后四处锚点改动：① 头注释与 `<title>`；② CSS 在 `</style>` 前追加一段（状态色 + 本分区专属前缀类）；③ 内容区把 N 个面板换成「本分区面板 + 一张 `data-panel="__other"` 占位面板」；④ JS 在 `/* 初始化 */` 前插入数据与交互，初始化改成 `currentItemIdx = 本分区下标` + `activatePanel('本分区 key')`。
- **必须改的一处兜底**：`activatePanel` 原本在找不到面板时"显示第一个面板"，在单分区页里会造出「面包屑写资料、内容显示目标」的假状态。改成落到 `__other` 占位卡（写清"该分区不在本页，请回模块主页"）。
- 不与模块主页争归属：本分区页只加"看得更细"的结构，对象字段与归属口径与主页一致；跨分区入口只给演示反馈，不假装会跳过去。
- **信息密度：一屏里同一件事只说一遍**（首版目标页因为违反这条被用户判为"乱、多"）。预算分配：统计只在 hero（一句结论 + 一行 metric）／"还剩多久"只在一条**横向时间条**／支撑来源只在卡上／对象规则压成**页脚一行**。⇒ 不设 KPI 卡组、不设右栏、不设状态分布卡、不设对齐检查卡（它与卡上的"缺支撑"徽标是同一件事）。
- 卡也要一次只说一遍：期限既在右侧大字、就不再挂"剩 N 天"徽标；"落后 Xpt"既在进度行、就不再单列。**徽标每卡 ≤ 2 个（1 状态 + 最多 1 警示）**，警示只在"有话说"时出现。
- 收场的目标（已完成 / 已搁置）用**两行紧凑卡**（标题 + 完成度 + 一句口径 + 1 个动作），且默认筛选停在"进行中"——历史不占版面。
- 次要动作收进一个「···」，卡上只留 1 个主操作（主操作 = 这个目标下一步真正要做的事，可以每张不同）。
- **新增与维护的落点在自己身上，不在别处**：新增 = 工具栏「+ 新建目标」（弹出对象字段表单）；维护 = 卡上「···」按「改内容 / 改时间 / 改状态」三组列动作；日常发现 = **汇总数字本身可点**（hero 上「落后于时间 / 缺支撑」点开就是待处理清单，每条给一个动作）——汇总数不做成报表，做成入口。
- **派生字段一律不进表单**：目标表单里只有 目标 / 期限 / 验收口径 / 关键结果（各带一个「来源」）/ 支撑来源；**完成度与状态没有输入框** —— 完成度 = 关键结果的达成比例（来源选「题库掌握度 / 练习记录 / 项目进度」的格子自动更新），状态由 期限 + 完成度 派生。表单里没有的东西，人就不会去维护它。
- 关键结果的「来源」是四选一：手填 / 题库掌握度 / 练习记录 / 项目进度。选后三种 = 不手填。**手填的进度一定会撒谎。**
- 状态流转都带前置条件，不做成一键切换：进行中 → 搁置必须写**复活条件**；已搁置 → 进行中必须**补一个期限**；已完成 → 归档必须写 **1 条复盘**。
- **卡片必须数据驱动**（`state.goals` + `render()`），否则"增删改查"全是假的：静态 HTML 的卡片只能做筛选 toggle，改一个数字要改两处。派生量只算一处（`pctOf / timePct / lateOf / handGap`），hero 数字、时间条、筛选计数、卡片全部取同一份。
- **支撑来源不是独立字段**：它就是关键结果里「来源」的汇总（去重）。这样永远不会出现"手写的支撑和关键结果对不上"；表单里也因此没有这一项，少一个要人维护的东西。
- **删除必配撤销**（toast + 撤销，7 秒），并写清"只删目标本身，不动它挂靠的资料 / 题库 / 练习"。**归档是删除的正确替代**：收场的目标退场但记录留着，「已归档」筛选条只在真有归档项时才出现（否则每个新用户都看到一个 0）。
- 日期一律用本地零点解析（`new Date(s + 'T00:00:00')`）：`new Date('2026-10-20')` 按 UTC 解析，GMT+8 下「剩 25 天」会算成 26 天。
- 参数千万别用 `form.name`：那是 `<form>` 自身的 name 属性，会盖掉同名输入框（`form.querySelector('[name=name]')` 才对）。
