## 优化「项目详情 · 运维」原型

文件：`工作-项目-项目详情-运维-index.html`

### 结构与一致性
- 补上项目详情页骨架：`hero-mini`（返回 / CORE / 项目名 / 刷新 + 最后更新时间）+ sticky Tab 条（7 个，
  运维高亮，文档 Tab 跳 `work_project_detail_document.html`），与「文档」页对齐。
- 原「🛠 运维面板 + 4 个药丸」语义与 hero 标题重复 → 重构成 4 张 KPI 指标卡（数值 + 单位 + 副说明）。
- 修正数据矛盾：头部原写「1 运行中」但两台服务器都是运行中 → 改为「2 台 / 环境健康 1 项告警」。

### 修掉的真实 bug
- `.doc-books` 缺 `display:flex` → 三本书竖向堆叠（截图确认）。
- `.skeleton-list { display:flex }` 覆盖 `hidden` → 骨架屏常驻。
- `.usage-item .meter-track` 是 `<span>`，`width:100%` 不生效 → 进度条退化成小药丸。
- `.app` 的 `z-index:1` 形成层叠上下文 → 移动端抽屉被遮罩压住、模糊且不可点。
- `.doc-book` 原来是 `<button>` 且内部嵌可点元素（非法 HTML）→ 改 `div[role=button]` + 真实按钮。
- 折叠全部由 `max-height` 硬编码改为 `grid-template-rows: 0fr/1fr`。
- `openModal` 是死代码 → 接入破坏性操作（重启 / 回滚）二次确认，含影响范围说明 + 焦点管理 + Esc。

### 新增交互深度
- 服务器行内联迷你资源条（CPU/MEM/DISK + 阈值变色），展开态另有等宽三项资源块。
- prod-db-01 磁盘 95% 告警：行左侧琥珀边、告警徽标、KPI 告警卡，串起阈值语义。
- 发布记录状态筛选 chip + 空态；刷新按钮带骨架屏加载态。
- 移动端抽屉导航（768px 以下）、触屏命中区放大到 44px、`:focus-visible` 焦点环、
  `role=button` 全面支持 Enter/Space、`prefers-reduced-motion`。

### 验收（真实渲染，非目测）
- 无头 Chrome 截图 + 脚本注入，覆盖浅/深色、展开、弹窗、筛选、加载、抽屉等 8 个状态。
- 像素级对比度实测 23 个元素 × 2 主题 = 46 项，全部 ≥ WCAG AA（修了浅色 muted 2.4:1、
  深色发布副信息 4.37:1、书脊标签 2.42:1 三处）。
- 4 档视口（1440/1024/768/500）`scrollWidth == clientWidth`，无横向溢出。
- 驱动全部交互路径（折叠/展开/筛选/弹窗/主题/抽屉/键盘/刷新），无控制台错误。

### 未做（需用户决策）
- 两页 Tab 语义不统一：文档页是页内切换面板，运维页是跳转/占位。统一前需先定 Tab 定位。
- `index` 清单文件命名映射含义不明（列的是逻辑名而非文件名），未擅自改动。

## 第五轮：点击日志弹出查看器（用户指定）

要求：点击日志出来弹窗。

### 结构决策（值得记）
把日志内容从「右栏内联输出」搬到**弹窗**里，右栏改为**概览**。
理由：弹窗若只是复制右栏内容，就是纯重复；改成
「左栏=路径列表 / 右栏=概览 / 弹窗=完整内容」三者各司其职，两个需求都不作废。
- **右栏概览**：名称 + 路径 + 「共 N 行 · 最后更新 X」+ 级别 chips（体积 / INFO / WARN / ERROR，
  WARN 与 ERROR 为 0 时不显示，避免视觉噪声）+ 最近 3 行预览 + 动作（打开完整日志 / 重命名 / 下载 / 复制路径）。
- **弹窗查看器**：`modal-lg` 880px、隐藏「取消」只留「关闭」，
  内含路径行 + 工具行（实时跟随 / 下载 / 复制路径）+ 可滚动日志区（54vh，逐行交错动画）。
- 原 `.log-pane` 保留为**数据源**（`.log-output { display:none }`），弹窗与预览都从它 clone ——
  一份数据三处渲染，不再维护第二份内容。

### 实现要点
- `openConfirm` 增加 `size:'lg'`（切 `.modal-lg .modal-viewer`）与 `hideCancel`，
  并让 `desc` 变为可选（查看器不需要那句说明文字）。
- `closeModal()` 里 `stopLive()` + 清 `viewerCtx`：关掉查看器就停跟随，避免后台无限追加。
- `pushLiveLine` 追加到 pane 后，若查看器开着且看的是同一条，同步 clone 一行进去 + 更新其 stat。
- 初始焦点落在日志区（`tabIndex=-1`，键盘可直接滚动），焦点环单独覆盖成模块绿
  `--ok-fg`，不用默认的深色粗框。

### 修掉的真问题
**「最近 3 行」取 `slice(-3)` 是错的** —— 日志按时间倒序（最新在最上面），
所以最近 3 行应该是 `slice(0, 3)`。这个 bug 只有把渲染结果看一眼才会发现，逻辑上不会报错。

### 验收
概览 chips「186 MB / INFO4 / WARN1」与实际行数一致；内联输出确认已隐藏；
点左栏/下拉均弹出查看器（标题=日志名称、行数正确、宽弹窗、取消按钮已隐藏），概览同步；
实时跟随 8s 内弹窗 4→7 行且概览同步；关闭后跟随自动停；
新增路径后自动弹出查看器并显示等待态；重命名后概览标题同步；Esc 可关；无控制台错误。

## 第七轮：日志改为「弹独立窗口」（用户指定）

需求：不是新标签页，而是**独立的浏览器窗口**，方便一边重新部署一边盯日志。

### 做法
- 运维页的日志入口保留 `<a>`（无 JS 时仍能正常跳转），改为
  `onclick="return openLogWindow(this)"`：
  ```js
  const w = window.open(href + '#win', 'ops-log-window',
      'width=1320,height=920,left=80,top=60,resizable=yes,scrollbars=yes');
  if (w && !w.closed) { w.focus(); toast(...); return false; }  // 已开窗口 → 阻止本页跳转
  return true;                                                  // 被拦截 → 走链接默认跳转
  ```
  **窗口名固定**，所以反复点只会聚焦同一个窗口，不会开出一堆。返回 false 阻止本页跳转是关键。
- 日志页识别窗口模式：URL 带 `#win` → `IS_WINDOW`。
  ① `document.title` 改为「…（独立窗口）」便于在窗口列表里辨识；
  ② 返回按钮变「✕ 关闭窗口」，走 `window.close()`，**并加 150ms 兜底**：close 只对脚本打开的
     窗口生效，若没关掉（直接访问 `#win`）就回跳转运维页，避免按钮点了没反应；
  ③ 面包屑的「运维」单独用 `navOps()` 始终跳转（面包屑关窗口很反直觉）；
  ④ **自动开启实时跟随** —— 这个窗口的存在意义就是盯日志，省掉一次点击。
- 无障碍：`<a>` 保留 href，键盘 Enter 仍可触发；window.open 必须挂在用户手势上，否则被拦。

### 验收方法上的一个坑
用合成 `element.click()` / 直接调函数**不算用户手势**，headless 里 `window.open` 一律返回 null。
所以：
- 不加 `--disable-popup-blocking` 时返回 `true` → 恰好验证了**兜底路径**（退回本页跳转）；
- 加该 flag 后返回 `false` 且拿到活的窗口引用 → 验证了**主路径**。
但加了 flag 后 headless **进程不退出**（新窗口还在），必须 `w.close()` 立刻清理，
否则 `--dump-dom` 永远等不到、外层 timeout 杀进程（exit 137）。

日志页 `#win` 模式实测：title 变化、返回按钮变「✕ 关闭窗口」、跟随自动开启、3s 内 5→6 行；
普通访问模式：title 不变、按钮仍为「← 返回运维」、跟随关闭、行数不变。两页无控制台错误。

## 日志页：级别改为「按日志源声明」（起因：不是所有日志都有级别吧）

### 结论（用户判断正确，且问题更深）
8 条日志源里 **4 条格式上根本没有级别字段**：
- 有级别：nginx `error.log`（`[error]/[warn]/[notice]`）、`app.log`、pgbackrest `backup.log`
- 无级别：nginx `access.log`（combined 原文）、`/var/log/syslog`（`service[pid]:` 前缀）、
  WAL 归档流水（`archive_command` 的输出）

原实现给 8 条全套了 INFO/WARN/ERROR。两个后果：
① **失真** —— access.log 里不存在 "WARN" 这种东西，那行「上游响应慢」本是监控层的判断；
② **假控件** —— 在无级别文件上按级别筛，点 ERROR 永远 0 条，而这块筛选器占了工具条最显眼的位置。

### 改法
- `.log-pane` 加 `data-lvl="none"` 作为**唯一声明点**，连带三件事：
  ① 不渲染级别列，网格 `78px 58px 1fr` → `84px 1fr`，正文换等宽（原文本就是等宽的）
  ② 行强调改左侧色条（`box-shadow: inset 2px/3px 0 var(--bar-warn/--bar-danger)`），不再冒充级别徽标
  ③ `.log-toolbar[data-lvl="none"]` 收起级别筛选器，搜索框接管空出的宽度
- `refreshScope` 里对无级别源**强制把级别状态复位为 all** —— 否则在 error.log 上筛了 ERROR
  再切到 access.log，会撞上「共 6 行 · 显示 0 行」的空态，看着像日志是空的。
- 内容真实性（既然承认没有级别字段，就不该再是半解析摘要）：
  access.log → combined 原文，并补 `10:12:41 ... 502` 与 error.log 的 `connect() failed` 同刻呼应；
  wal-archive → `0000...091 archived (16 MB, 14.2 s)`；syslog → 标准 `CRON[pid]:` / `sshd[pid]:` 形态。
- 实时跟随模板按日志源分组（`LIVE_BY_LOG`，原先只有一组通用英文句）—— 往 access.log 追加一行
  应用日志本就是文本错配。新增的自定义路径退回 `LIVE_GENERIC`。
- 新增路径默认 `data-lvl="none"`：我们并不知道它的格式，不假设。

### 又一次「按下标对齐」
`refreshScope` 里级别计数原按 `const order = [...]` 与按钮**下标**配对；按钮一增减就静默错位
（与之前 `setServerTab` 同一个坑）。改成按钮带 `data-lvl`、按值匹配，并抽出 `syncLevelButtons()`。
`pushLiveLine` 里也顺手避掉同类问题：`% 4` 写死长度会越界（各源模板 3~4 条不等）→ 改 `% lines.length`。

### 验收（用技能脚本 html-ds-delivery-verify）
- 对比度：4 场景（access/error × 浅深）共 **51 项全绿**，最紧 4.81:1（深色搜索占位）。

  原因是 `capture.mjs` 只从 URL 传 `?theme=`，而页面只读 localStorage —— 深色场景其实渲染成了浅色。
  给页面补上「URL 参数优先于存储」后重跑，立刻暴露 **2 项真未达标**：深色下左栏路径/时间

## 追加六：带交互的启动命令（`su -` 要密码）

### 用户口径
「如果是带交互的呢，需要输入 `su -` 的」—— 原部署页把启动命令写成列表（操作名 + 命令），
默认假设每条命令都能非交互跑完；但 `su - deploy` 会停在 `Password:` 上，界面上完全没有这个概念。

### 决策：**识别 + 标注**，不替用户改写；执行侧加第四态「等待输入」
- 表单：命令列表每行常驻一个 `>_` 开关（**不依赖识别** —— `./deploy.sh` 这种识别不出来的也得能标），
  识别到或已标记时才多出一行「交互提示」（普通命令行不长高）。识别表区分「一定会停」（`su` 无 `-c`）
  与「可能停」（`su -c` / `sudo` 无 `-n` / `ssh` / `mysql` / `psql`），分别用 ⚠ 与 ℹ。
- 执行：`step-wait` 第四态 —— 琥珀底 + 左侧强调条 + 琥珀圆点 + `等待 12.3s` 计时，
  输入框内联在**输出流里**（`Password: [____] [继续]`），不弹窗不跳页。
  超时 180s 即失败、`su` 给 3 次机会、`sudo` 凭据在同一次执行内复用（`su` 不缓存 —— 两者语义本来就不同）、
  输入后回显 `••••••••` 并把输入框从 DOM 移除、**中止时必须收掉输入框**。

### 顺带修掉的三处真问题
1. `markRemainingSkipped` 只 `classList.add('step-skip')`，**留着 `step-idle`** —— 一行同时带两个状态类，
   任何按 `classList.contains` 判断状态的地方都会读到自相矛盾的行。改成先 `remove` 再 `add`。
2. `abortDeploy` / `jumpToCurrent` / `updateJumpBtn` 一律用 `querySelector('.step.step-run')` 找当前步 ——
   等待态不在 `.step-run` 里，于是「中止」找不到当前步、什么都不标。三处都补 `.step-wait`。
3. 窄屏（≤860px）步骤列折成**横向滚动条**时，要等输入的那一步很可能停在可视区之外
   （`documentElement` 没有任何溢出告警）。补 `revealStepCard(i)`：只改 `container.scrollLeft` 把它带进可视区，
   不用 `scrollIntoView`（会连带滚动整页）。同一媒体查询里 `.step-run` 的强调条已转到底边，
   `.step-wait` 却还是左侧竖条（在横向卡片上看不见）⇒ 一并转成 `inset 0 -3px 0`。

### 图标：`⌨` 换 `>_`
`⌨`（U+2328）在本机字体链里**没有文本字形**，兜底渲染成**彩色 emoji 键盘**：`color` 完全不参与渲染
（对比度脚本量的是 computed color，量到的是渲染时没人用的颜色）、深色下是一坨深蓝、`font-size` 也控不住字形。
改用纯 ASCII 的 `>_`（语义还更贴切：命令行在等你输入）。**放大 6~10 倍截图才看得出来** —— 光看数字是全绿的。

### 布局体检（只测量，未改动文件）

用户问「布局有什么修改方案吗」，先量事实再给方案。三项实测：

1. **主内容横向稀疏**：1440 下主区内宽 1102px，列表行宽 1076px，而文字只占 78px ⇒ **行内空白 90%**

2. **主内容纵向也没填满**：可用 782px，内容只占约 490px（头 86 + 卡片 118 + 区块 246）⇒ **纵向利用率 58%**，
   底部约 300px 空白。注意 `scrollHeight == clientHeight` 只说明"没有滚动"，**不等于内容填满了**，
   要单独比 content 与 avail。
3. **侧栏槽区空白 51~74%**：槽可用 438px，四个面板内容 114~214px。圆盘块 196px 反而占了大头。

`Range.selectNodeContents(el).getBoundingClientRect().width` 取（`scrollWidth` 对 flex 子项拿不到自然宽）；
纵向要单独比 `.main` 的 `scrollHeight` 与内容实际高，不能只看有没有滚动条。

### 圆盘设计评估（用户问「目前的圆盘设计好吗」，只分析未改动）

**结论：不好，但不是画得不好 —— 是「形式与内容不匹配」**：它装的是一个 3~12 项的**列表**，却用**环**来排，
而环的两个真正优势在这里一个只在极端项数成立、一个结构上用不了。

**依据 1 · 机制（代码可验证）**
- `START = -90, step = 360/n` ⇒ **同一项的位置随项数变**。环形布局唯一的强项是肌肉记忆，
  而这里每个模块的分区集合不同，没有稳定标识可锚定 ⇒ **结构上不可能形成肌肉记忆**。
- `--r` 固定 65px，不管 3 项还是 12 项 ⇒ 形状不携带任何关于项数的信息。
- 判据：**如果形状不携带信息，它就是装饰。**

**依据 2 · 空间账（同一高度预算）**

| | 圆盘 | 四列图标网格 | 差 |
|---|---|---|---|
| 3 项（默认落地页 dashboard） | ~196px | 54px | **多花 142px** |
| 12 项（work） | ~196px | 126px | 多花 70px |

⇒ **网格在任何项数下都不输**，还赢在位置稳定。而且默认落地页恰好是圆盘最不划算的那一档。
（圆盘块高度实测 196~200px = 容器 172~176 + gap/padding + 名称条 20。）

**依据 3 · 中心门是装饰不是控件**：它是侧栏里视觉权重最大的元素（53px 圆 + 进度弧 + 罗盘，实测直径
比图标大 76%），但 ① 现在没有文字 ② 弧长编码的"第几个"与高亮图标冗余 ③ 同时管进入/返回/进度三件事。

**依据 4 · 收起态已经证明竖列可行**：`rail` 就是同一批项的竖列版本，代码已写好，只是被限定在收起态。

**三个方向**：A 只降代价（半径随项数变 + 中心门去弧，3 项省 ~40px，保留视觉标志）；
B 按项数切形态（n≤5 用竖列复用 rail / n≥6 保留圆盘，两套心智模型）；
C 换四列网格（+ 分组标题，任何项数都不输，代价是放弃环形视觉）。**我推荐 C。**

**叠加问题提醒**：用户要求"图标不显示名称、悬停才显示"。这在 4~5 项时没问题，
但 12 项时要靠图标识别或逐个悬停 —— **若保留圆盘又保留无标签，最吃亏的就是 work 这个 12 项模块**。

### 追加六：圆盘改造 —— 让形状携带信息（同文件）

用户定的方向是「**主要是看着和普通的千篇一律的不一样就行**」⇒ **撤回我上一条推荐的 C（四列图标网格）**：
网格正是"千篇一律"的样板，我当时是在为"好用"优化，而用户要的是"不一样"。
关键反思：**纯色化删掉极光与毛玻璃后，圆盘成了整个界面里唯一非矩形的结构** —— 它是这套 UI 的结构性
识别符号，删了它就只剩卡片 + 列表。所以方向从"换掉它"改成"**让它的形状携带信息**"。

三处改造（全部是几何，无新令牌、无文字）：

1. **半径随项数变** `radiusFor(n) = clamp(46, 40/(2·sin(π/n)), 65)`
   —— 「3 个分区 ⇒ 小盘，12 个 ⇒ 大盘」。下界 46 = 中心门半径 26.5 + 图标半径 15 + 4px 缝。
   实测圆盘块高：3/4/6 项 **166px**、8 项 178、9 项 190、12 项 **200**（改前一律 196~200）。
2. **弧 → 分段刻度** `arcStops(n, activeIdx)`：段数 = 分区数，已过段填 `--m-main`、未到段留淡痕。
   实测填充段严格跟随选中项（1→12 段），下钻到三级时换成子项列表的刻度。
   未填充的几格**显式声明为纯装饰**（总数由图标本身可见）⇒ 不适用 3:1 图形门槛。
3. **选中项沿半径向外咬合 5px**（悬停 3px）：当前项从盘面里"探出来"，而不是只换一块颜色。
   副作用是正向的：外推**增大**了与相邻项的净距（work 12 项由 5.7/3.6px 提到 **7.3/5.7px**）。
   容器四边的呼吸位因此从 8px 提到 10px。

`--dial` 中心门刻意保持固定 53px：它是唯一的恒定锚点，环在它周围伸缩。

验收：对比度 60/60 仍全达标（最紧 5.16:1）；刻度已填充段 4.47~5.95:1（门槛 3.0）；
最外沿 70/88px 未越出容器；名称条命中正确；5 档视口零横向溢出。

### 三条命令分五档（`autoInfo(run)`）
| 档位 | 判据 | 页面表现 |
|---|---|---|
| `ready` | 已是非交互写法（`sudo … -n` / 普通命令） | 沉默；`sudo -n` 额外给「服务器上要有这一行授权」+ 复制 |

## 追加九：连接身份决定"要不要输入"（本轮用户问题的正面回答）

### 用户口径
「能实现自动交互吗，或者在连接服务器的时候使用了这个登录，从这里是不是就不用输入了」

**这个直觉是对的**，而且能落成一条机械可判的规则：

| 机制 | 是否免掉这一步的输入 | 说明 |
|---|---|---|
| **连接身份是 root** | ✅ 免 | root 下 `sudo` 免认证、`su - 任意用户` 也不要密码 ⇒ **同一条 `su - deploy`，root 进来就不问** |
| sudo 时间戳缓存 | ✅ 免 | 默认同 tty 15 分钟（`timestamp_timeout`）；页面按"同一次执行内复用"建模 |
| 已免密的 sudoers | ✅ 免 | `NOPASSWD: <具体命令>` |
| 已配公钥的 ssh | ✅ 免 | 配合 `-o BatchMode=yes`（要密码就立刻失败） |
| 已经是同一条 SSH 会话 | ❌ 不免 | `su -` 不会因为"你已经连上来了"就免 —— 它认证的是目标用户 |
| `su - user`（非 root 且无 PAM 信任） | ❌ 不免 | `su` 没有 NOPASSWD 等价物 |

### 落地：把「连接身份」当成和「目标服务器」同级的执行上下文
- 来源：`?user=`（运维页打开部署窗口时带），默认 `deploy`；执行区头部给一个原生 `<select>` 可现场切换
  （`deploy / root / appuser`，URL 带来预设之外的身份时动态加 option）。
- `autoInfo` 里加一条**只作用于提权命令**的规则：`sessionUser === 'root'` ⇒ `su` / `sudo` 一律 `ready`，
  并带 `rootFree: true` 标记。**ssh / psql 不受影响** —— 本机是 root 不等于对端免认证（这条专门写了用例）。
- 新函数 **`needsHuman(x)`**：`ask` 是「用户说这条要人」的声明，但当身份已经保证免认证时它就不该生效 ——
  否则会出现**「提示说不会提示 / 徽标说需输入 / 真跑起来停住」三方打架**。
  `autoSummary`、`cmdBrief`、执行序列、摘要 title 全部改走 `needsHuman`。
  （本轮就是这么被抓的：先只改了文案，徽标和执行没跟上，4 条断言一起红。）
- 文案跟着事实走：`✓ 当前连接身份是 root，切到 deploy 不需要密码`；已标记人工的行写
  「已标记「需人工输入」，但…—— 这次不会提示」；root 下不再显示 sudoers 授权行（用不上）；
  终端开头写明本次身份。

## 日志页 · 十三轮：左栏日志路径补「编辑 / 删除」（用户：怎么只有新增）

用户说得对：那一栏是"日志路径**配置**的宿主"，却只能往里加 —— 加错了只能忍着。

### 形态由三个约束推出
1. `.log-src` 是 `<button>`，**按钮里不能再套按钮**（非法 HTML）⇒ 每项外包一层 `.log-item`
   （`role="presentation"`），动作按钮是它的**兄弟**，绝对定位叠在行尾。
2. 栏宽 252px，名称 + 「容量 · 时间」余量只剩十几 px ⇒ 动作**常驻会把名称挤到截断**。
   改成悬停 / `:focus-within` 时出现，**同时元数据让位**（占同一格、交叉淡入淡出，零重排）。
3. 隐藏必须用 `visibility`（延迟 0.14s 切）—— 只给 `opacity:0` 的按钮**照样能被 Tab 聚焦**，
   会得到"看不见但有焦点"的按钮。`:focus-within` 那一半顺带给了键盘用户入口。

- 弹窗说清影响范围（「服务器上的日志文件不会被删除」）+ `btn-danger` + 动词「移除」；
- **撤销**：删之前把现场整个存下来（item / pane / box / next sibling / 整组），toast 带「撤销」按钮，
  停留时间 2.4s → **6s**（破坏性操作的后悔时间要够）。为此给 `toast()` 加了可选第三参 `action`；
- 删掉的正好是**当前项** ⇒ 自动落到剩下的第一条，不让右栏停在"一份已经不存在的日志"上。

### 删空之后（截图复核时才发现的漏项）

补 `setHeadEmpty()`：空态时给 `.log-main-head` 打 `data-empty`，用 `visibility:hidden` 藏掉动作组
（不用 `display:none`：标题行高度不变、加回来不跳）。同时空态文案从"这台服务器还没有配置日志路径"
改成"还没有可查看的日志"，避免与右栏标题「没有日志路径」echo。

### 实测（`/tmp/wb_check/path_actions_test.mjs`，34 项全绿）

### 写测试时踩的两个坑（都是"量错了东西"）

## 追加十一：路径与命令拆成两张卡片（弹窗变成「一卡一问」）

### 用户口径

### 拆卡片会多出 40~70px 高度，用「卡片头兼作字段标签行」抵掉
拆一张卡多出：卡片间距 14 + 内边距 15/16 + 卡片头 20+13 ≈ 78px。三张就顶到视口上限了。
抵法是**去掉字段自己那一行 label**（17px + 6px 间距 × 3 = 69px）——
一张卡片只有一个字段时，"卡片名"和"字段名"本来就是同一个词，写两遍纯属噪声。现在：

```
① 配置名称 · 左栏列表里怎么显示   [必填] [?]  ──────────────
② 服务器路径 · 上传的文件会放到这个目录 [必填] [?] ──────────
③ 启动命令 · 传完之后按顺序执行什么  [必填] [?] ──────  [3 条]
```

实现：`group()` 把卡片头挂成 `g.head`、把一条 `<i class="grp-fill">` 挂成 `g.fill`；
`field({ inHead: g2 })` 时把「必填 / ? / 计数」`insertBefore` 到 `g.fill` 之前，字段自己只剩控件 + 错误行。
卡片名同时是 `<label for=...>`（点它能聚焦输入框）；`o.label` 在这条路上不再需要。

### 三个必须记的实现细节
1. **填充线必须是真元素，不能是 `::after`**：字段的元信息要分别落在它两侧（标签类在左、线填充中段、计数在右），
   伪元素挪不动位置。
2. **计数的靠右不能再用 `margin-left: auto`**：auto margin 的优先级**高于 flex-grow**，
   会把 `.grp-fill` 压成 0 宽（线消失）。改成靠 `.grp-fill` 吃满剩余空间，计数自然贴右。
3. **`put()` 的插入参考点容易搞错层级**：`fill` 是卡片头的子节点、不是卡片容器的子节点，
   `insertBefore(node, card.fill)` 要作用在 `card.head` 上 —— 写在 `card` 上会直接抛异常。

### 顺手修掉一个**数据丢失**的真 bug（既有）
`onConfirm` 把 `cmd` 存成 **JSON 文本**，而 `cmdEditor` 读初值写的是 `Array.isArray(init) ? init : []`
⇒ 新建一条配置、再点「编辑」，**命令列表是空的**（保存后原来填的命令被清掉）。
修法两条腿：① `cmdEditor` 改用 `cmdList(init)` 读（数组与文本都吃）；
② `onConfirm` 改存结构化数组，与初始数据同型 —— 存文本会让下游到处多一层"可能是字符串"的分支，
而这个分支一定会有人漏写。`set()`（chips 灌值）也改走 `parseCmds`，不再假设入参类型。

### 追加十五：「怎么没有居中」＝ 死规则（同文件 `导航-v5.html`）

用户反馈「怎么没有居中」。量下来**规则没坏，是它只在 ≥1696px 生效**：

| 视口 | 主区可用宽 | 页头左缩进 / 右余 |
|---|---|---|
| 2400 | 2062 | 352 / 352 |
| 1920 | 1582 | 112 / 112 |
| 1700 | 1362 | **2 / 2** |
| 1600 | 1262 | **1 / 1** |
| 1440 | 1102 | **1 / 1** |

`max-width: 1360px` 要有"可用宽 > 1360"才有留白可收 ⇒ 视口 ≥1696px。**1440/1600 下它是死代码**，
内容铺满 ⇒ 看着完全没居中。**这就是上一轮我提过的那句"只覆盖 ≥1700"，当时没往下追。**

改法：`max-width: min(var(--content-max), 100% - var(--content-gutter) * 2)`，放在 `@media (min-width:1360px)` 里。
- 两个令牌：`--content-max: 1360px`、`--content-gutter: 56px`。**改 gutter 一个值就能调松紧。**
- 效果：1440 → 留白 57/57、内容 990；1600 → 57/57、1150；1800 → 57/57、1350；
  1920 → **112/112、1360（触上限）**。连续、单调。
- 起点 1360 不是拍的：两列要排得下 2×2 卡片，主列需 ≥560px
  （主列 = (可用宽 − 96 − 16) × 1.7/2.7 ⇒ 可用宽 ≥1001 ⇒ 视口 ≥1339）。
- 复测：各档横向溢出 0、可见文本截断 0；两张截图（1440/1920）目视对称。

**可复用判据**：`max-width` 型"收口"规则**先算它的生效阈值**（可用宽 = 视口 − 侧栏 − 各层 padding），
再决定它是不是死代码。写了 `max-width` 不等于生效 —— 这是本项目第二次踩（前一次是 1920 的顶栏错位）。

### ① 图标（4 个按钮 + 顺手把全页都统一了）
四个字符 `▶ ✎ ↓ ⧉` 来自四个不同字体族 —— 粗细/光学大小/基线都不一样（✎ 落成手写体、⧉ 小到看不清），
且非 ASCII 符号会落到 emoji 字体族，`color` 不参与渲染 ⇒ **hover / 激活态改色对图标无效**（跟随变绿时图标仍是灰的）。
换成一整套内联 SVG：同一 16 网格、1.6 描边、`stroke="currentColor"`。伴随改动：
- **路径数据只留一份**（JS `ICON`）：静态标记写 `data-ico="…"`，`paintIcons()` 在初始化时灌入；运行时新建的按钮 `svgIcon()`。
- 顺手把剩下的字符图标全换掉：`⟳ 刷新` `🌙/☀️ 主题` `✕ 关闭`（顶栏 + 弹窗）`⌄ 折叠箭头 ×6` `▸ 目录` `✓ ⚠ ℹ toast` `🔍 空态`。
  现在 UI 里已经没有字符图标（`＋` 是文案的一部分，保留）。
- 尺寸在各容器上覆盖：15 工具 / 14 搜索 / 13 行内 / 11 折叠 / 24 空态 ——
  **容器写了 width 的地方里面的 svg 必须跟着写**，否则按基础 15px 渲染顶破容器（实测折叠箭头那一栏被顶出）。

### ② 搜索框
- 从"绝对定位两个图标压在一个 input 上"改成"一根 flex 容器排四件东西"：图标不再靠 padding 让位，
  **焦点环挪到容器上**（`:focus-within`，整根框亮比只亮中间一段明确）。
- 右侧那一格是**两态同一位**：空着显示 `⌘F`（快捷键本来就绑了，只是没人知道），有值让位给「清空」。
- placeholder 收短（搜索日志内容… → 搜索日志）、清空按钮 20 → 22px 命中区、宽度上限 420 → 340（让给四个 chip）。
- **Escape 清空搜索**（弹窗/选择器关闭优先）。
- 宽度上限统一：删掉「无级别源时 420px」那条 —— 同一根框在切换日志时改宽度看起来像布局出错。
- 没加"搜索命中数"：标题行的 `共 N 行 · 显示 M 行` 已经在做同一件事，加了就是两处说一件事。

### ③ 四个 chip —— 「这是什么」的答案是"值没有标签、范围没写清"
- 前两个（`47.100.x.x` / `4C8G · Ubuntu 22.04`）**没有标签**，所以读起来就是两串陌生字符 ⇒ 加「主机」「规格」。
- 后两个（`告警 11 条` / `错误 9 条`）是**这台机器全部日志的合计**，但和标题行「当前这一份」的行数混在一起、
  没有范围说明 ⇒ 改成「本机告警 11」「本机错误 9」。
- 四块灰胶囊也分了类：身份类保留中性底，状态类用语义色底衬（琥珀/红），价值在于"这四块不是同一类东西"。
- chip 值加了 `title`（IP / 机型 / 合计口径）。

### 一次真实事故：const 的 TDZ 让脚本中途中断
把 `const ICON` 插在 `function toast` 之前，而 **`applyTheme()` 在它上面 30 行就被调用** ⇒
`svgIcon()` 读 `ICON` 抛 `ReferenceError`，**脚本从那一行起全部不执行**：页面照样渲染（HTML/CSS 是静态的），
但图标全空、所有点击无反应。`new Function(script)` 查不出来（语法没错）。
修法：整段移到 `<script>` 最前，并在注释里写明"谁先用到它，定义就必须在谁前面"。
**连带改进探针**：第一条断言改成「首屏无 `Runtime.exceptionThrown`」，且 `ev()` 遇到 `exceptionDetails` 立刻打印
（否则第一处失败会让后面所有断言变成二次误报 —— 这次就是先看到一堆 `undefined` 才发现根因的）。

## 追加十三：部署页的「服务器路径」接上目录选择器（移植日志页那套）

### 用户口径
「新增/编辑部署配置的服务器路径，参考 [日志页] 的右侧日志文件分组，新增日志路径的[浏览]服务器目录」
（"流浪"是语音转写误字）。

### 移植了日志页的什么
假目录树 + 面包屑 + 逐级进入 + 筛选框（条目 ≥10 才出现）+ 底部一句话说明 + 同一个弹窗换正文视图。
**没有叠第二层浮层** —— 正文里飘出来的下拉会被 `.modal-body{overflow-y:auto}` 裁掉（既有教训）。

### 三处必须改的地方（因为「选目录」≠「选文件」）
1. **选中的落点是当前层，不是某个条目**。日志页靠"点文件名即选中"；目录本身没有"文件名"可点，
   所以在面包屑下方加了一条 `pick-bar`：左边等宽显示**当前完整路径**、右边一个「用这个目录」。
   ⇒ 一张卡片里同时有"进入"（点目录名）和"选中"（按钮）两种动作，各自有明确控件。
2. **文件行列出来但不能选**（上传目标是目录）。给 `aria-disabled` + 无 hover + 点击时 toast
   「上传目标要选目录，不能选文件」—— **"点了毫无反应"比"点了被拒并说明原因"差**。
3. **落在哪一层要更宽容**：日志页的 `fsDirFor` 找不到就回 `/var/log`；部署页改成**逐级回退到最长的存在前缀**
   （配置是历史留下的，路径指向的目录可能早就没了）—— 覆盖 4 种起点：目录本身 / 指向文件退一级 /
   中间层不存在 / 完全不存在回默认（`/opt/app`）。

### 最关键的一条：切视图返回时，**整块摘下来暂存**，不要重新生成
日志页 `showForm(prefill)` 是每次重建表单（它只有两个普通输入框，重建无损失）。
部署页有三张卡片、其中一张是**列表编辑器** —— 重新生成会把用户刚敲进去还没保存的命令全部重置。
⇒ `openDirPicker()` 里 `formView = mBody.querySelector('.form-body')` 把表单整块摘下来存着，
`closeDirPicker()` 再原样 append 回去。**输入的 DOM 一直活着，值、焦点、错误态自然都在。**
两个配套：① 三张卡片要包一个 `.form-body` 容器（不能取 `firstElementChild`，正文将来多一个说明段就取错）；
② 探针里加了两条硬断言（切视图期间改的名称 / 加的命令行，切回来必须还在）。

### 踩到的两处
1. **`HOST_FS` 的根节点少了 `type:'d'`** ⇒ `fsNodeAt` 第一次比较就判"不是目录"、直接返回 null，
   表现是"已填 `/opt/app/releases` 却落在 `/opt/app`、列表 0 行"。日志页没这问题是因为它从
   `LOG_FS[server]`（本身就是 `fsDir`）开始走。**根也要 fsDir。**
2. 探针自身三处写错（筛选命中数算错、没先 `focus()` 就断言焦点、期望值抄成旧路径）——
   都属"断言写错"，不是页面缺陷。教训同上次：**断言里的每个期望值都要现算或从现场读，别手抄。**

### 弹窗按钮的复位（沿用既有判据）
进选择器时 `mConfirm.hidden = true` + 底部换成「返回」；`openConfirm` 里**每次复位**
（否则下次打开会带着上一次的「返回」）。另外 `closeModal` 里也清一次 `picker/formView` 兜底。
Escape 的语义分档：**在选择器里 = 退回表单**，在表单里才关弹窗。

### 验收
- 选择器探针 46 条 + 视口 24 条：入口/标题/按钮语义、已填路径的落点、面包屑逐级、
  目录排文件前且按名排序、10 个版本目录触发筛选框、筛选命中 6 个且**焦点不丢**、空态、
  文件行不可选、三条常用路径在树里都存在、**返回表单后名称与命令都没丢**、
  四种路径起点的落点、保存后配置与右栏摘要同步、Escape 分档、按钮复位。
- 对比度：4 个场景 **94 项全达标**（最紧 5.48:1）；`pick-use` 文字 6.99/7.08、
  边框 4.20/5.82；`pick-bar`、`pick-row` 按容器单列（1.06~1.18，数值照旧打印）。
- 几何：1440×900 / 1440×800 / 560×900 三档 —— 不超屏、不内部滚动、面包屑与目录行零溢出。
- 回归：卡片 3×2 + 全流程 + sticky/行内改写，全绿。

### 一份待办（不擅自做）
现在**同一个能力有两份实现**：日志页的选择器选文件、部署页的选择器选目录。
差异只有两处（选中动作的落点、路径起点的回退策略）。若以后还要第三个入口，
应该抽成"共用目录树 + 可配置的选中语义"，而不是再抄一遍。

### 追加二十：五项新增的定义（用户问「规格·评审·代码·验证·上下文 是做什么的」）

一句话框架：**它们不是并列类别，是一条链上的环节** ——
规格（我要什么）→ 上下文（机器懂规矩）→ 代码（我做了什么）→ 评审（谁在等我判）→ 验证（凭什么说对）；
**验证没过是回到规格，不是回去改代码**。

| 项 | 回答的问题 | 三级 | 独立出来的判据 |
|---|---|---|---|
| 规格 | 我要让 AI 做的东西说清楚了吗 | 需求 · 方案 · 接口契约 · 验收标准 | **它有生命周期**（草稿→确认→锁定→已实现→过期），文档没有。有状态的东西才需要独立入口 |
| 代码 | 东西在哪、现在什么状态 | 仓库 · 我的分支 · 未合并 PR · 最近提交 | AI 让**并行度上升**（同时开几个 worktree / 改几个仓库）⇒ "我手上摊开几摊"编辑器给不了 |
| 评审 | 现在有多少在等我判断 | 待我审 · 我的 PR · **AI 产出待复核** · 需返工 | 它是**队列**不是仓库；**会积压且你会关心积了多少**的东西就该有独立读数 |
| 验证 | 这批改动凭什么说它对 | 测试用例 · 回归清单 · 验收标准 · CI 状态 | **"对不对"是独立问题**。代码说"做了什么"，验证说"凭什么说它对"；且它必须与规格里的验收标准一一对应 |
| 上下文 | AI 怎么知道我们项目的规矩 | AGENTS.md · skills · 编码/提交规范 · MCP 连接 | ① 是真工作量 ② **会腐烂**（写着用 Redux 其实早换 Zustand）③ 有版本、要跟代码一起提交 |

**关键判据（可复用）**：**任何"会被反复读取、且会悄悄过期"的东西，都需要一个地方能看到它的新鲜度。**
AI 时代新增的就是这一类 —— 以前不存在"喂给机器的说明书"。
**命名备选**：规格 想更口语可叫「方案」；评审 若要强调 AI 复核可叫「复核」。

## 追加十四：目录选择器只列目录

### 用户口径
「目录浏览不需要看到文件」

### 改了四处（一处是必须连带改的）
1. `renderPickList()` 只取 `type === 'd'` 的条目，删掉文件行那一整支（含 `aria-disabled`、点击 toast）。
2. CSS 跟着收：`.pick-row.dir` / `.pick-row.file` 两类合并成 `.pick-row` 一种；`.pick-name` 从等宽改成
   **普通字体 + 700**（目录名是中文/业务词，等宽反而别扭）。
3. **必须连带改的：所有"几项"和筛选条件改按「子目录数」算**。原来用的是 `Object.keys(node.children).length`，
   只列目录之后这个数会把看不见的文件算进去 ⇒ 出现两种对不上的账：
   "显示 3 项却只有 2 行"、以及"只有 8 个子目录却弹出筛选框"（筛选框的门槛是 ≥10）。
   新增 `dirCount(node)`，计数与筛选门槛都走它。
4. 空态文案跟着变：`这个目录是空的` → `这个目录里没有子目录`（只有文件、没有子目录的目录是常见情况，
   `/opt/db/migrations` 就是 —— 而且它仍是个合法上传目标，「用这个目录」照旧可用）。

**树里的文件节点保留**（那是机器上的事实，将来别处可能要用），只是在选择器这个视图里不参与。
注释里写明了，免得后来人以为是"渲染漏了"。

### 验收
- 只列目录三条硬断言：`/opt/app/current`（有 `VERSION` 文件）只列 `config / static` 且各为「0 项」；
  `/opt/db/migrations`（只有 3 个 .sql、0 个子目录）走空态且不报错；`/var/www/pay-web/dist` 只列 `assets`；
  另加一条**全页扫描**断言：`.pick-row.file` 与 `.pick-row[aria-disabled]` 必须都是 0。
- 选择器探针 46 + 视口 24 条全过；卡片 / 全流程 / sticky 三组回归全绿；结构自检 div 配平。

### 追加二十一：「接口文档、数据库修改放在哪里」

**答案：两样都不进 `文档`**，因为 `文档` 装的全是**事后叙述**，而这两样是**事前约束 / 不可逆动作**。

- **接口文档 → `规格 > 接口契约`**。它不是"叙述"而是"约束"，而且是 AI 生成两端代码的主要输入之一。
  附带要求：**它必须显示 drift**（契约与实现是否一致）—— 否则又是一份会悄悄腐烂的东西
  （同 `上下文` 那条判据）。别维护两份（对外文档 = 已发布契约的一份投影）。
- **数据库修改 → 拆两处**（这是关键，它被"数据库"这个词捆在一起了）：
  - **表结构 / ER / 索引设计** → `规格 > 数据模型`。它是**设计决策**，和接口契约同级（都是系统边界定义）。
  - **迁移脚本执行 / DDL / 数据回填** → `发布 > 数据库变更`。它是**一次高风险不可逆动作**，
    必须和代码发布排序配合（先加列 → 发代码 → 再删旧列），且必须有回滚或前滚方案。

**通用判据（本轮最有价值的一条）**：
**分类不看「它是什么东西」，看「它出现在哪个时刻」**——
事前约束 → `规格`；不可逆动作 → `发布`；事后叙述 → `文档`。
按"东西"分会在"数据库修改该放哪"这类问题上卡死（它同时是设计、是代码、是发布动作）。

**一个视觉要求**：`数据库变更` 在同一层里是**唯一不可逆**的（代码能回滚，删掉的列回不来）
⇒ 它不该和"发个前端"长得一样，需要显式的不可逆标记（二次确认），不能只靠一个普通三级项。

**调整后的 12 项三级（补全）**：
规格（需求·技术方案·**接口契约**·**数据模型**·验收标准）/ 待办（全部·今日·缺陷·逾期）/
项目（进行中·风险·**迭代**·已完成）/ 会议 / 代码（仓库·我的分支·未合并 PR·提交）/ 评审（待我审·我的 PR·AI 产出待复核）/
验证（测试·回归·验收·CI）/ **发布（生产·预发·回滚·数据库变更）** / 上下文（AGENTS.md·skills·规范·MCP）/
文档（ADR·Wiki·会议纪要）/ 汇报（OKR·工时·周报）/ 概览。

### 追加二十二：这 7 项在「项目内」也有一份（用户口径：外面放所有项目的，项目内部放项目自己的）

**用户这句话一次性解掉两个悬着的问题**：
1. 项目详情的 Tab 是「页内分区」还是「跨页导航」→ **页内分区**（那 7 项就是该项目自己的）。
2. 同名项在两处出现会不会重复 → **不会，只要两层的"三级切法"不同**。

**模型：同一份数据、两个作用域**（不是两套页面）
- 内层 = **归属地**，可写，问「这个项目里有什么」→ 三级按**类型**切。
- 外层 = **队列**，只读 + 跳转，问「现在什么在等我」→ 三级按**状态 / 归属**切。

| 二级 | 内层三级（类型） | 外层三级（状态） |
|---|---|---|
| 规格 | 需求·技术方案·接口契约·数据模型·验收标准 | 待确认·已锁定·已过期 |
| 评审 | 待我审·我的 PR·AI 产出待复核 | 待我审·卡太久·需返工 |
| 验证 | 测试·回归·验收·CI | 失败·待验·已通过 |
| 发布 | 生产·预发·回滚·数据库变更 | 待发布·已发布·回滚过 |
| 上下文 | AGENTS.md·skills·规范·MCP | 已过期·待更新 |
| 代码 | 仓库·我的分支·未合并 PR·提交 | 我活跃的仓库·落后的分支 |
| 文档 | ADR·Wiki·会议纪要 | 最近更新·待归档 |

**哪些项只在一层**：`数据模型 / 接口契约` 只在内层（跨项目看"所有表结构"没意义）；
`会议 / 汇报 / 概览` 只在外层（人的维度；项目详情自己就是该项目的概览）；`待办` 两层都要。

**两条实现约束**：① 必须抽「不含外壳的正文组件 + 两个只负责套壳的薄页面」（工作区已有同类判据，
见 `cross-module-shared-view` 技能）；② **外层每条必须带「是哪个项目」，内层不带** ——

## 日志页 · 十七轮：支持三种查看方式（tail -n N / tail -f / less）

用户问「这三种查看方式怎么设计页面」。**先给判断，再落地。**

### 设计判断：不做三个 tab
三条命令在界面上不是三个功能，是**两个正交维度 + 一个搜索模式**：

| | 跟随关 | 跟随开 |
|---|---|---|
| 范围=末尾 N 行 | `tail -n 100` | `tail -f` |
| 范围=全部 | `less` | `less +F`（少见） |

判据：**「开实时」和「往回翻」能同时成立吗？** 能 ⇒ 它们就不该是互斥的 tab。
做成三个页面，就得回答"分页模式下能不能开实时"这种本不该存在的问题。
（按实现分类 vs 按用户意图分类 —— 前者永远会漏掉组合。）

### 终端语义 → Web 对应物（不是换皮）
- `tail -n N` → 工具条最左的**取数范围**下拉（最近 20 行 / 最近 100 行 / 全部行）。
- `tail -f` → 已有的**跟随**开关（本轮没动它）。
- `less` 的"分页" → **往回取更早的行**。Web 里滚动条本身就是分页器，照搬分页器是错译；
  真正的对应物是列表末尾的「加载更早的 N 行」（`b` / Ctrl-B）。
- `less` 的 `/` + `n` → **高亮 + 跳转（保留全文）**，不是把不匹配的行藏掉（那是 grep）。
  ⇒ 新增「定位 / 只看匹配」二选一，**默认定位**；查找条给 `1 / 2 处匹配` + ↑↓ + 快捷键。
  Enter/↓ 或 `n` 下一个，Shift+Enter/`N` 上一个；`n`/`N` 在输入框里不生效。

### 实现要点
- **两个通道必须分开**：范围外的行是 `is-unloaded`（还没从服务器取回来），
  筛掉的行是 `[hidden]`（取回来了但不显示）。混成一个，`共 N 行` 就说不清。
- **方向**：本页新的在上 ⇒「最近 N 行」= DOM **前** N 行，被挡住的是**末尾**。
- 搜索高亮用 **TreeWalker 逐 text node 包 `<mark>`**，不整块重建 `innerHTML` ——
  行里有 `<code>` 状态码，整块重建会把配色冲掉。还原靠 `dataset.raw`。
- 跳转只改日志区自己的 `scrollTop`（居中算法），**不用 `scrollIntoView`**（它会滚动所有祖先，整页跟着跳）。
- 命中底色做成**中性**（往页底压深一档），颜色全交给 `<mark>`：有色底衬会把这一行所有文字
  一起拉低对比度（深色下 muted 实测掉到 4.3:1）。当前命中用伪元素画左条，避开 `is-error` 已占用的 inset box-shadow。
- 「加载更早」提到下一档后**同步下拉框的值** —— select 是唯一真相源，按钮只是它的快捷方式。

### 数据
给 web-access 补 14 行更早的访问日志（20 → 34 行），默认档 20 才有东西可分。
真实产品不需要补数据（syslog 本来就几千行），原型不补就**看不出这个功能存在**。

### 两个静默 bug（都是"看起来完全正常"）
1. **插入差一行 ⇒ 新行嵌进了上一行内部**：`lines[close:close] = rows` 里 `close` 指的是
   收口 `</div>` 那一行，必须写 `close+1`。症状：`querySelectorAll('.log-row')` 照样数得出 34 条、
   时间列也读得出来 —— 是"搜索多命中一处"才暴露的（那一行的 textContent 包含了整段嵌套行）。
2. **方向写反**：`最近 N 行` 切了末尾 ⇒ 行数对得上、时间列也在走，只是**给你看的是最旧的那批**。
   第一次修我在文件上直接改了，**没同步改补丁脚本** ⇒ 后来从备份重放补丁时被静默回滚，
   探针只表现为"数字不同"，差点又去查别的地方。

### 一、搜索搜的是什么（实测，不是读代码猜的）
| 试搜 | 结果 | 说明 |
|---|---|---|
| `10:0` | 4 处 | **时间列也被搜进去了** |
| `GET` | 11 处 | 正文 |
| `upstream`（只在 error.log） | 0 处 | **不跨文件** |
| 切到 error.log 后 | 关键词仍在，命中 5 处 | 关键词跟着走（有用：换一份继续找同一个词） |
| 范围=20 时搜 `401`（在第 24 行） | 0 处 | **未载入的行不参与** |

⇒ 覆盖范围是「**当前这一份 · 已载入的行 · 整行文本（时间 + 级别 + 正文）**」。三条都合理，
但用户看不见 —— 所以**0 命中时补一句说清没搜哪里**：「还有 N 行未载入，时间范围外还有 N 行」。

### 二、时间范围筛选
**它是取数条件，不是又一个筛选器**，所以和「最近 N 行」是**两个独立控件**（不是塞进同一个下拉）。
计算顺序：`按时间圈出候选 → 在这个子集里取最近 N 行 → 再按级别/关键词筛`。
于是「加载更早的 N 行」的计数 = **时间范围内**未载入的行数，语义自洽（改前会把范围外的算进去，已修）。

- 预设：全部时间 / 最近 3 分钟 / 最近 10 分钟 / 自定义时间…
- ⚠️ 相对范围的基准取**本份日志最新一行的时刻**，不是系统当前时间 —— 日志流说的"最后 5 分钟"
  就是"从最新一条往前 5 分钟"；原型数据固定在 10:xx，用系统的"现在"（19:4x）会得到空集。
- ⚠️ **解析不出时刻的行**（原型里的「昨天 22:41」）给 -1，只在「全部时间」下出现 ——
  跨天要完整日期才能比较，硬比会得出错误的相对顺序。
- 自定义：选它时**预填当前可见的整段跨度**（从"看全部"起步比从空输入框起步少想两步）；
  下拉框那一项的文案改写成**真实范围**（`10:05 – 10:10`），否则控件会一直显示"自定义时间…"，
  而那是个**动作**、不是当前值。
- **跟随 × 固定时间窗 = 互斥意图** ⇒ 开跟随自动切回"全部时间"并 toast 说明，
  否则"一边接新行、一边只让旧区间可见"看起来就是没反应。

### 三、顺手修掉的一处（只有截图才看得出来）
`.log-host-meta` 的 `margin-left: auto` 是上一轮为"补上工具条右侧空白"加的 —— 前提是**一行放得下**。
加了时间控件后 db 那台的工具条折行（多了级别筛选 250px），auto 把 chips 推到第二行最右，
**左侧空出 717px 的洞**，看着像没加载出来。删掉 auto 让它自然流：
web 一行紧贴右侧（余量 16px）、db 第二行左对齐。判据不是"显得空不空"，而是**这一行会不会折**。

最近 10 分钟 ⇒ 32 行（`已载入 20 / 32 行` + `加载更早的 12 行`）；

### 两次"取关键词"的教训

## 追加二十：两种传文件方式改成「二选一」

### 改法：两段控件 + 只渲染选中那一种的面板

## 日志页 · 二十轮：跟随按钮图标不跟着变（用户报）—— 连带查出两处同根 bug

用户：「跟随按钮点击，图标没有跟着变」。**先测再改**：颜色 **是** 变的
（`rgb(91,106,130)` → `rgb(4,120,87)`），**形状没变**（`data-ico` 一直是 `play`）。
所以不是 CSS 的问题，而是"开启后按钮语义已变成'点它会暂停'，图标却还是'播放'"。

### 根因：缓存式渲染函数记错了维度
`paintIcons()` 里 `if (el.dataset.painted) return;` —— `painted` 记的是**"灌过没有"**（布尔），
于是**运行期改 `data-ico` 会被静默忽略**。改成记**"灌的是哪一个"**（`painted === data-ico` 才跳过），
再加一个统一入口 `setIcon(el, name)`（改 `data-ico` + 重绘），函数就变成可重入的了。

### 顺着同一根因查出两处（都是"看起来正常"的静默 bug）
1. **主题图标在深色冷启动时与状态相反**
   `applyTheme()` 在脚本前段（定义处即调用），`paintIcons(document)` 在脚本**末尾**。
   深色冷启动：`applyTheme(true)` 先画**太阳** → 末尾 `paintIcons` 照硬编码的 `data-ico="moon"`
   又灌一次 → **页面是深色、图标是月牙**。`applyTheme` 改走 `setIcon` 后两者同步。
   ⚠️ 这类顺序 bug **只在冷启动出现**，点一次主题按钮是测不出来的。
2. **主题按钮从来没有写过 `color`** —— 深色下黑图标压 `#1E293B`，**1.44:1，等于看不见**。
   原因：`<button>` 不吃继承（UA 给 `buttontext`＝黑），而图标是 `currentColor` 的 SVG。
   用 emoji 时不需要它（emoji 自带颜色、不参与 `color`），所以**"图标统一为内联 SVG"那次改动的
   隐含前提是"每个容器都必须有显式 color"** —— 这条当时没写下来，所以漏了一个。

### 排查方式：遍历而不是抽样
写了一次审计：把所有**可见**的 `svg.ico-svg` 的 `stroke` 色，与它**真正叠着的那个不透明底色**
（沿祖先链找第一个 alpha>0.9 的 `background-color`）配对算比值。结果干净利落：
浅色 10 类全达标、深色 **9 类里只有 `theme-toggle` 不达标（1.44）**，其余 5.12~7.01。
修完两侧均 0 不达标。审计脚本固化成了常驻测试 `icon_audit_test.mjs`（12 项）。

### 验收
新增 `icon_audit_test.mjs` 12 项全绿（跟随 ▶⇄⏸、主题浅/深冷启动 + 点击、浅深两套图标对比度）；

### 又一条工具教训
`cat > x.mjs <<'ZEOF'` 写含**模板字符串 `${…}`** 的 JS 会被外层 zsh 吃掉（报 `Bad substitution`）——
heredoc 的引号挡不住 `-c` 传进来的那层展开。**带 `${}` 的脚本一律用 Write 落盘**。

## 追加二十一：新增配置时加「分组标签」，归到对应分组

### 用户口径

### 契约：有标签看标签，没标签看路径
```js
function groupFromPath(path) { …原来的前缀表… }
function groupFor(c) { return (c && c.group) || groupFromPath(c && c.path); }
```
- 演示数据 c1–c5 补上显式 `group`（app/web/db），左栏呈现与之前**逐组一致**。

## 日志页 · 二十一：新增日志路径时加「标签」，落到对应分组

用户：「新增的时候加标签，添加到对应的分组中」。

### 形态
弹窗从两字段变成三字段：**名称 / 路径 / 标签**（顺序 = 想事情的顺序：起个名 → 文件在哪 → 归到哪一类）。
标签是一个**下拉 + 按需切输入态**的复合控件，两态共用同一个位置（`.field-slot` 里换控件，不叠第二行）：
- 缺省态是「选已有」（选项 = 这台服务器现有的组名，从 DOM 现算，末尾补上「自定义」兜底）；
- 字段标题右侧一个「＋ 新建标签」切成输入态，同时它自己变成「选已有」——同一个按钮来回切。

### 三个刻意的决定
1. **给选项而不是自由文本**：自由文本会立刻长出「Nginx / nginx / NgInx」三个组。
   缺省是"选"而不是"填" —— 绝大多数时候用户只是把新日志放进已有的组。
2. **标签就是分组的名字，身份直接复用**：新增 `groupBoxFor(scope, 标签名)`（原来是写死的
   `customGroupBox`），按 DOM 里的组名查、没有就建。白拿三件事：新建标签撞上已有名字会自动并进那一组、
   `tagsOf()` 的下拉选项永远和左栏实际分组一致、改数据自动跟上。**只要有第二份"分组配置"，它就会走岔。**
3. **路径 → 标签的自动推断**（`guessTag`）：`/var/log/nginx/…`→Nginx、`/var/lib/postgresql/…`→数据库、
   `pgbackrest`→备份、`/opt/app/…`→应用、`syslog|auth.log|…`→系统。
   三条约束：**必须命中已有标签才采用**（猜错比猜不中糟，会悄悄塞错组而用户不会复查）、
   **只在用户没自己动过标签时跟随**（`touched` 标志，手动选过的值不能被路径改写）、
   猜不中就落中性桶「自定义」。这条让"浏览服务器目录 → 选到 nginx 下 → 标签自动是 Nginx"整条链自然。

### 编辑弹窗跟着一起（同一份构造器）
标签可改 ⇒ 改了就**换组**：来源组空了整组收掉（与删除同一条规则，不留「空组 0 项」），
目标组由 `groupBoxFor` 保证展开（否则"它搬走了"看不见）。
**只在标签真的变了时才动** —— 只改个名字不该顺手把用户折叠着的组展开。

### 配套
- `.field-slot` / `.modal-select`（`appearance:none` + 同一套内联 SVG 箭头，各平台自带箭头形状位置都不一样）。
- `#logAdd-tag` 两态共用同一个 id → `label[for]` 在两种形态下都指得着（同时只存在一个）。
- 校验：新标签为空 ⇒ 不关窗、输入框标红（路径空仍是老规则）。
- 新增的 toast 改成 `已添加「x」到「Nginx」` —— **落点是这次操作的关键结果，得说出来**。
- 新增后补一次 `renderGroupMeta(k)`（放在 pane 落位之后 —— title 从 pane 的 `data-path` 派生）。

### 验收（`/tmp/wb_check/tag_field_test.mjs`，38 项全绿）
三字段与选项列表、默认「自定义」、路径推断（nginx→Nginx / syslog→系统 / pg→数据库）、
手选后路径不再改写、选择器来回切标签不丢、确认后落进 Nginx 组（组计数 3 项、展开态、title、
toast 带落点、**没有多出一个「自定义」组**）、新建标签建新组并落进去、空标签不给过、
再次打开时选项里已有新标签、编辑换组 + `Nginx 空了整组收掉`、db 那台选项独立、零溢出、无 console 错误。

**四条判据**（可复用到任何"应用内窗口顶栏"）：

## 二十三、「绑定本地文件」也能弹窗挑文件 —— 选择器抽成"双源 × 双语义"

**触发**：「绑定本地文件也支持弹窗选择本地文件」（同批还有一条"顶部日志弹独立页"，用户随后确认是笔误、不用管）。

**做法**：把原来只服务"服务器目录"的选择器抽成 `openFsPicker(opts)`，两个入口共用同一棵渲染：

- `src: 'host' | 'local'` —— 数据源（`HOST_FS` / `LOCAL_TREE`）
- `mode: 'dir' | 'file'` —— 选中语义（底部「用这个目录」 / 点行即选中）
- `standalone: bool` —— 从表单里打开（正文摘下来暂存、给「返回」） / 整个弹窗就是它（给「取消」）

`openDirPicker(path, cb)` 保留成一行包装，表单那边的调用点一行没动。

**判据**：

1. **同一能力的第 N 个入口 = 抽参数，不抄实现**。三个差异（源 / 语义 / 归属）全部收进 opts，渲染函数里只出现分支、不出现第二份列表代码。
2. **本机树从 `LOCAL_FS` 现算**（`LOCAL_TREE` 由文件清单拼出来）—— 另存一份树 = 换了文件忘了改树，浏览里就永远看不见它。
3. **文件行的形状要说明"点了会怎样"**：目录是 chevron（继续往下走），文件是文件图标（到这儿为止）。只靠颜色分不出来。
4. **一个面板里两个同等重的主按钮 = 没有主按钮**：同行的「浏览…」用中性描边 + secondary 文字，「绑定」才留 dp 描边。两者 `align-items: stretch` 等高。
5. **选文件的列表里，`n 项` 的口径要跟着视图走**：选目录时只算子目录，选文件时文件也算 —— 两个方向都会出账（"显示 8 项却弹出筛选框" / "只有 2 行"）。

**踩到的坑（本轮真出现）**：

- **又一次"分支变量忘了在函数头定义"**：`renderPicker()` 里加了 `withFiles` 分支，但变量只在 `renderPickList()` 里定义了 ⇒ 打开选择器直接 ReferenceError（页面看着像"按钮没反应"）。**修法：凡是"按模式分叉"的函数，模式变量一律在函数入口第一行定义**，别让它散落在各分支里。同类前科：对象字面量里兄弟方法看不见彼此的 `let/const`。
- **宽度类也会跨函数泄漏**：新加的 `.modal.modal-picker`（560px）只在选择器里 toggle，必须同时在 `openConfirm` 里 `classList.remove` —— 否则下一次开表单弹窗会带着 560 的宽度。与"底部按钮复位"是同一类问题，同一个地方修。
- **抽完公共实现要回查死代码**：`fsNodeAt` / `fsDirFor` / `dirCount` 三个转发函数在调用点全改走 `*In` 版本后已无人调用 ⇒ 删掉（留着下次会以为它们还在用）。

**未验证**：同上，本轮按要求没跑探针。

## 二十四、分组字段支持「＋ 新建分组」

**触发**：「新增/编辑部署配置的分组，后面添加加号，可以加新分组」。

**判据（可复用到任何"从几个选项里挑一个 / 也可以新建一个"的字段）**：

1. **缺省态是"选"，新建按需才切到输入态 —— 两态共用一个位置**：行尾一枚虚线加号胶囊，点开在同一位置换成输入框，收起又变回加号。不做成"常驻一个输入框"（那会让 90% 只是来选的人多读一个字段），也不做成"弹一个小窗"（多一层）。
2. **兜底组要认 id，不能认位置**：原来 `groupFromPath` 的兜底写的是 `DEPLOY_GROUPS[length - 1]`（因为「其它」正好排最后）。一旦允许在末尾追加分组，兜底就漂移到刚建的那一组上 —— 路径推断不中的配置会莫名落进用户新建的分组。改成显式 `GROUP_OTHER`，新分组 `splice(-1, 0, g)` 插在它之前。
3. **撞名直接复用已有那一组**，不再补一枚 chip：并排出现两个同名 chip，用户会读成"新建没生效"。复用后把它选中，人的意图（用这个名字）照样达成。
4. **id 用递增编号，不用名字**：名字是给眼睛看的，左栏归组与已存数据认的是 id；分组改名不该牵动归组。
5. **空组靠"不渲染"兜住**：`renderCfgList` 里本来就有 `if (!items.length) return`（一条都没有的分类标签只是噪音），所以"新建了分组但最后取消了"不会在左栏留下一个空框，这个新分组只是安静地留作下次的选项。

**踩到的两个坑**：

- **`blur` 与 `Enter` 会各触发一次提交**：收起输入态时（`hidden = true`）元素失焦，又走一次 `blur` 处理 ⇒ 二次提交。修法是**用一个 `adding` 门闩，且先落标志再改 DOM**（顺序反了标志还没落下，blur 已经进来了）。
- **局部 `Escape` 必须 `stopPropagation()`**：本文件文档级有一个 `keydown` 监听，Esc 会关掉整个弹窗。输入框里按 Esc 只该收起这一格，不挡冒泡的结果是"想取消新建、结果整张表单没了"。`preventDefault()` 拦不住别的监听器。

**未验证**：同上，本轮按要求没跑探针。

### 两个只有量了才发现的问题
1. **顶栏高度由分段控件决定（57px）而不是由按钮决定**：`.seg-btn` 靠 `padding: 7px 14px` 撑到 31px，
   轨道 = 3+31+3 = 37px。改成 `height: 24px`（轨道 30 = 3+24+3），顶栏落到 **50px = 10+30+10**，
   三段（身份 / 分段控件 / 动作）同高。判据：**顶栏里所有控件的目标高度是同一个数（这里是 30px），
   任何一个靠 padding 自己撑，高度就会被它带跑。**
2. **emoji 不吃 `color`**：`📋` 放在染底方块里，染底与文字色对它完全无效 —— 又是那条老坑，
   只是因为它在 HTML 里长得像图标，一直没被算进"图标清单"。⇒ 换成 `data-ico="doc"`。

### 顺带修掉自己工具里的一处**假通过**（重要）
`getComputedStyle` 返回的颜色有**两种形态**：`color-mix()` 的计算值是
**`color(srgb 0.89 0.96 0.94)`，分量 0~1**，不是 `rgb()`。而我的图标审计脚本：
- `lum()` 按 `/\d+/g` 抓数字当 0~255 用 ⇒ 把它读成"接近全黑"；
- `bgOf()` 只匹配 `rgba?()` ⇒ **跳过它**继续往上找更亮的祖先。
两条路都导致**假通过**。实测同一对颜色：错解析 3.81 / 正确 4.94（Python 独立算过一遍）。
修好后再审同一页：**从"审了 10 类"变成"11 类"** —— 多出来的那一类原来一直被静默跳过。
已把修法（`parseColor` + "解析不了就返回它并判测不了，不要往下跳"）写回技能 `html-ds-delivery-verify`，
