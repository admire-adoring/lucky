## 「项目要不要也做成方块」——判为不要，改的是视觉重量（09:57）
用户问「项目需要也改成小抽屉吗」（= 要不要也做成文档那种方块）。**结论：不要。**

**依据（形态由对象决定，不由邻居决定）**
- 文档是**物**：一本有厚度、版本、封面的东西 ⇒ 书的形态本身就承载了"它是什么"。
- 项目是**事**，且它的关键信息全是**会变的状态**（进度 / 截止 / 风险）。
  96×134 的封面里只放得下"类型签 + 标题 + 版本 + 一格时间"；项目那三样塞进去只能二选一，
  而右栏 300px 两列方块 ⇒ 每格 124 ⇒ 项目名折行、元信息再缩，读起来比行式慢。
- 所以右栏两块形态不同**不是缺陷**：一块是"可翻的物"，一块是"在跑的事"。
  要统一就统一**视觉重量**，不是形状。

**做法**：项目行首加一根竖进度条 `.dash-prog`（4×28px，`--p` 控填充比 = 进度）。
把"进度 62%"从"要读的字"变成"要看的形"——三行的差异一眼可比。
meta 里的「进度」二字随之删掉（图形已经在说这件事），**数字保留**（竖条只能看大概，
精确值仍需一处；这不是"同一数字两处表达"，图形+标签是一体的）。
自检：CSS 483/483、div 0/0、span 174/174、`dash-*` 类两侧一致。

**留给用户的判别项**：若他说的"小抽屉"其实是**点项目滑出详情抽屉**（不是形状），
那是另一件事 —— 项目详情页已存在，加行点击即可，说一声就做。

## 「还是乱」→ 三种形态收敛成一种（11:05）

## 「怎么还上下不齐」→ 左栏去掉"大白卡"那一层（13:55）
用户贴图问「怎么还上下不齐」。**根因不是像素，是层数不对等**：

| | 结构 | 层数 |
| --- | --- | --- |
| 左栏 | 灰底 → `.main` **大白卡**（1px 描边 + 24 内距 + 20 圆角）→ 任务卡 | **两层** |
| 右栏 | 灰底 → 项目卡 / 文档卡 | **一层** |

⇒ 两边的卡片边缘永远对不上：左栏的卡比右栏的卡**内缩 25px**，上边差一截、左右也差一截。
我前一轮加的 `.context { padding-top: 24px }` 只是"补一段内距去追"—— 追的是**容器边**、不是**卡边**，
补丁治不了层差（这也是它看起来"还是歪"的原因）。

**改法（只对工作台生效）**
```css
.app[data-context="on"] .main {
    align-self: start; max-height: 100%;
    padding: 0; background: transparent; border: none; border-radius: 0; box-shadow: none;
}
.context { align-self: start; }        /* 删掉那条 padding-top 补丁 */
```
⇒ 两栏都是"灰底上直接摆卡片"：上边同一条线、左右各自成列。
⚠️ 其它 11 个分区仍是"白卡容器 + 卡"（`data-context="off"` 时不生效）。
⚠️ 代价：切到别的分区时左栏会从"卡片"变回"大白卡" —— 工作台与其余页面在容器层分叉，这是有意的

## 「工作台布局错乱」→ 撤回上一轮的 center（14:20）
用户只给了一句「work_index.html 工作台布局错乱」，没贴图。
**先做静态体检（全部通过，所以"错乱"不来自坏代码）**：CSS 大括号 490/490；标签栈平衡（div 深度 0）；
JS `node --check` 通过；`getElementById` 引用的 id 全部存在；`var(--x)`↔`--x:` 差集只剩
有意不定义的 `--book` 与内联/带兜底的 `--a/--i/--cols/--arcs/--na`。
与 13:51 备份逐行 diff ⇒ **这一轮之后只动过一处**：`.main`/`.context` 的 `align-self: start` → `center`。

**撤回 center 的三条依据**
1. `center` 是"每栏各自居中" ⇒ 只有两栏**恰好等高**时才顶边齐。14:05 那句"两栏等高 417px"是估的；
   按现在的 CSS 逐项算：左栏 ≈536（卡头 40 + 组 24.4+2×55.1 + 20 + 组 24.4+4×55.1 + 折叠的
   `.dash-done` 54.2 + padding 42）、右栏 ≈515（项目卡 283 + 24 + 文档卡 208）⇒ **差 21px**，
   居中后右栏整体高 10px —— **两栏错开，比"底部留白"更像坏版式**。
2. `center` 同时松开上下两端的锚 ⇒ 某栏高过视口时**上下同时溢出**，而 `body` 是 `overflow:hidden`
   ⇒ 溢出部分永远够不着。`start` 至少只往下溢。
3. 仪表页的默认就是顶边对齐；底部留白是内容量差，不是布局错误。

**改动（备份 `/tmp/work-index.bak-before-fix-align.html`，232090 bytes）**
| # | 改动 | 理由 |
|---|---|---|
| 1 | `.app[data-context="on"] .main`、`.context` 的 `align-self` → **`start`** | 顶边对齐，不依赖"两栏恰好等高" |

## 「两个视角：项目 / 服务器，筛选跟着视角走」（16:45）

**读法（关键）**：不是"三选一"，而是**两个正交维度**：
- **视角** = 看谁的清单：「项目」= 按项目分组（一个项目一张卡 / 一段表 / 一格网格）；
  「服务器」= 不分项目，全部机器平铺成**一张**清单。
- **视图** = 用什么排布：列表 / 表格 / 卡片（截图里也在，保留）。
2 × 3 = 6 种组合，六份标记**全部渲染出来**，切换只改 `hidden`（零重渲）。

**「筛选永远是另一个维度」**（这是本轮最有价值的判据）：
- 按项目**分组**时，分组已经在做"分项目"这件事 ⇒ 再筛项目是多余的 ⇒ 只给「服务器」；
- 平铺时没有分组可依 ⇒ 需要一条收窄到某个项目的路 ⇒ 只给「项目」。
⇒ 顺手消掉了上一轮那个"死组合"隐患：两个维度**永远不会同时在屏上**。
连带：切视角时另一个维度的筛选**归零**（它已经不在筛选栏上了，留着就是看不见的筛选）。

**实现口径**：三组模板（`listViewHtml / tableViewHtml / cardsViewHtml`）都吃一个 `persp` 参数，

## 23:5x 「为什么有的高有的低」—— 两层 stretch 断链

先量了一遍内容：12 张卡**完全同构**（每张都是 2 行读数 + 2 个位置胶囊，机器名 10~12 字符、
角色行 3~14 字符），⇒ 高低差**不是内容造成的**，是布局机制。

三个机制性缺陷（前两个是这轮修的）：
1. **`align-items: stretch` 只到网格项那一层**。卡片为了挂浮层多包了一层 `.sv-card-wrap`
   ⇒ 网格把 wrap 拉满行高，而 `.sv-card` 是 wrap 里的普通块级子元素，**不跟着撑满** ⇒
   行里就有"卡片矮一截"（wrap 那截空白是透明的，看起来就是卡片自己矮）。
   **修**：`.sv-card-wrap { display: flex }`（默认 stretch）⇒ 卡片纵向拉满。
2. **网格行与行的行高各自算**。第一行被某个更高的项顶高，第二行仍按自己的内容算。
   **修**：`.sv-grid { grid-auto-rows: 1fr }`。
3. 顺带发现一处**真·错位**：`.sv-read .v`（地址，有底）带 `padding: 3px 9px`，
   而 `.is-plain`（系统，无底）把 padding 一起去掉了 ⇒ 两行的**值**起点差 9px。
   **修**：`is-plain` 保留 `padding-left: 9px`。
   判据：**撤掉一个形状（底 / 描边）时，别顺手把它承担的对齐也撤掉。**

另：卡片高度 194 → **200px**（给 nowrap 内容留一点字体渲染余量，避免个别系统上被顶高）。
