## 添加服务器页：支持「登录后 su - 再输入密码」

用户：「需要支持登录后输入 su - 然后输入密码」。落在
`工作-项目-项目详情-运维-添加服务器.html` 的**卡③ 登录方式**里，作为 `登录用户` 下方的第二个子块。

### 为什么需要一个独立子块

SSH 登进去的身份（`deploy`）与后面读系统信息 / 重启服务要用的身份（`root`）是**两件事**。
原来只有"登录用户"一格：填 `root` 能跑通，填 `deploy` 就断在半路，而页面没有任何地方表达"进去之后还要提权"。

### 领域规则（照 `flow-waiting-input-step` 技能口径，一处不新造）

| 规则 | 落地 |
|---|---|
| `su -` 认证的是**目标账户** ⇒ 要的是目标账户的密码，不是登录用户的 | 两个密码字段分开；标签跟着账户名走（`root 密码` / `<账户> 密码`） |
| **root 登录时 `su - 任意用户` 与 `sudo` 都免认证** | 登录用户 = `root` ⇒ 密码行整体 `hidden`，徽标转「root 登录 · 免认证」 |
| 这条免认证**只作用于提权**，不免 `ssh`/`psql` 的对端认证 | 不动「认证通过」那一行的判据 |
| `su -` **没有免密等价物**，同一次执行里每次都重问（`sudo` 凭据复用 15 分钟） | 免密只能换工具 ⇒ 建议写法 `sudo -u <账户> -n <命令>`；`sudo` 档给 `sudo -n <命令>` |
| 工具只识别 + 给建议，**不代改命令** | 建议写法挂在提示行 + 一个复制按钮，没有任何 `apply/fix` 动作 |
| 汇总徽标的语义是「一定会停 / 可能停」 | 徽标只说"执行时会不会停下来等人"：`不需要` / `root 登录 · 免认证` / `不会暂停` / ⚠ `执行时会暂停等你输入`（密码留空时） |

### 一处必须收口的地方：三条判据同源

卡内徽标、连接检查第 4 行、侧轨预览的「登录身份」若各写一套判断，就会出现
「徽标说不会停、检查行说过不了」。统一走三个函数：

```
escFree()      = 登录用户 === 'root'
escNeedPwd()   = 提权到 !== '不需要' && !escFree()
escWillPause() = escNeedPwd() && 提权密码为空
```

### 其它同步改动

- 演示数据：登录用户 `root` → `deploy`（否则新功能首屏看不见）；密钥路径不变。
- 连接检查 4 行 → **5 行**：`认证通过` 与 `系统识别` 之间插入 `提权通过`；
  `resetChecks()` 的数组、`runCheck()` 的 steps 同步加 `esc`。
- `checkTarget` 的 `title` 补上 `→ su - root`（顺带修掉原来 title 硬编码 `root@` 而正文用 `user@` 的不一致）。
- `pickEsc` / `pickEscMethod` 变更时 `resetChecks()` —— 提权路径变了，既有结论作废；
  `fEscPwd` 由有到无时作废，有值时只 refresh（不该每敲一个字符就清空检查结果）。
- `copySuggest()` 里 `navigator.clipboard.writeText` 必须 `.catch()`：file:// 下无剪贴板权限，
  未处理的 rejection 会在控制台留一条 error，污染"控制台 0 报错"这条验收线。

## 终端改成"手动连接"，服务器卡片状态跟着走

用户两条连着的指令：①「终端是弹出 SSH 连接的，加一个连接按钮，默认不执行连接，点连接按钮才连接，所以卡片的运行中状态也需要修改」；
② 截图上圈出动作栏「变成 4 个按钮，终端按钮只负责弹出新窗口，需要加单独的连接按钮」。

### 关键判断

- **"一个按钮只干一件事"**：原来那个按钮既开窗口又暗示"连接"。拆成 **连接（插头） / 终端（窗口） / 编辑 / 移除** 四个；
  终端按钮的 `title` 从"连接服务器"改成"**打开终端窗口**"—— 按钮改名了但 hover 提示还写旧功能，是这类拆分最常见的漏项。
- **"卡片的运行中状态"= 运维页服务器行那颗徽标**：它过去写死「运行中」，但 SSH 是要用户按出来的 ⇒ 默认「未连接」（idle 灰），
  连上才「运行中」（ok 绿）。判据：*这个状态属于谁？* 属于"机器"（不是某个窗口）。
- **跨窗口同步（localStorage + `storage`）**：键 `ops-term:<机器>`。三条必踩：
  ① `storage` 只在**别的**窗口改键时触发 ⇒ 运维页自己点完连接**必须自己调一次 `applyConnState`**，只靠事件当场不生效；
  ② 两处都能改 ⇒ 终端页也要监听，否则"卡片说已连接、终端说未连接"；
  ③ 键属于"机器"就不绑窗口生命周期 ⇒ 终端页**去掉了 `beforeunload` 删键**，并新增：打开时若该机器已连接，直接进"内置回显"（`adoptExternalConn()`），
     不再自己发一次 WS，也不再无条件把状态清成 idle（那会把运维页刚点的连接抹掉）。
- 开关按钮的 title / aria-label 随状态换（"连接 x" ↔ "断开 x"），并加 `.server-action-btn.on` 的激活外观；
  状态的**权威显示**仍是卡片徽标，按钮只表达"这个开关按下去没有"。
- 删除服务器时连带清掉它那条连接键。

### 终端页其余改动

- 去掉自动 `connectWS()`；顶栏加「连接」按钮（插头图标，`.connect-btn`，连接中禁用、已连接变 `.on` 显示"断开"）。

  首屏占位加了 `#termHint`，连接时移除。
- 提示符 `guest@nebula` → `guest@<目标机器>`（`?host=` 带来的上下文，连的是哪台要看得见）。
- 运维页删掉了 `#server` 上不存在的"运行中"直写；现在两页的状态都只从这一个来源推。

## 终端.html 优化盘点（只讨论，未改文件）

用户：「讨论哪里还有优化的」。逐行读完 1109 行后给出四组结论，未动代码。

**归属已定**：它是运维页第四个 ext 窗口（`openTerminalWindow` + `终端.html?host=<机器>#win`），
所以「孤立页面 / 无入口 / 命名」这三条不成立 —— **动笔前先 grep 入口，别凭文件名猜**（我第一版结论就错在这里）。

### 真缺陷（自洽性 > 样式）

- **同一份 CPU/MEM 在页面上有 4 套互不相干的数字**：状态栏 `cpuVal`(12±,1s) / htop meta `${cpu}`(12±,2s)
  / htop 头 `cpuBars=[12,8,24,4]` / 进程表 8 行**常量**求和 ≈21.5%。MEM 同族（状态栏 21± / htop meta /
  `memBars=[21,18,34,12]` / `free` 6.8Gi/32Gi / neofetch 6.8GiB）。⇒ 面板内部都不自洽，终端用户一眼看出。
- `renderHtop()` 每 2s **全量 `innerHTML`** ⇒ 悬停行、选中文本每 2s 被抹掉，meter 过渡每 2s 重放。
- `pushLog()` 无条件 `scrollTop = scrollHeight` ⇒ 往上翻历史被每 1.8s 拽回（部署页已有「跟随」开关，本页没有）。
- tab 是死控件：`×` 无 click、`+` 直接 return、切 tab 内容不变；tab(dev/monitor) 与 tmux 状态条(0:bash/1:htop/2:logs)
  是两套并行「会话」概念，标题又写 `tmux: 3 panes` ⇒ 三个数对不上。
- `@media (max-width:860px)` 的 `.sb-right .sb-item:nth-child(-n+3)`：**`nth-child` 数到了 `.sep-dot`**
  ⇒ 实际隐藏 CPU、MEM 两项 + 一个分隔点，留下时钟与无意义的 `TS`，且剩余项以孤立分隔点开头（本意应是隐藏 TS）。
- WS 竞态：1.5s 超时内敲的命令会被 `onopen` 的 `termOutput.innerHTML=''` 抹掉。
- `.tmux-status` 高 24 + border 1 = 25px，`.panes` 只让 24px ⇒ 压 1px（同族：两个控件等高别写死 px）。
- **`?host=` 只改了 `document.title`** ⇒ 窗口写 prod-web-01，提示符仍 `guest@nebula`、路径 `~/projects/nebula`。
- 提示符写两遍（HTML 静态 + JS `PS1`）；输入行在滚动容器内 ⇒ 翻历史时输入框一起滚走（应 `sticky bottom:0`）。

### 可访问性（实算）

- `--fg-mute #4d5560` 压 `--bg-0 #0a0c10` = **2.60:1**，却用在日志时间戳 / `// 注释` / htop 表头(10px) / `Load avg` /
  pane 元信息 / `connText` 初始态；`--fg-dim #7d8590` = **5.25:1** ✓。⇒ **正文一律 `--fg-dim`，`--fg-mute` 只留纯装饰。**
- `aria-` / `role=` 各 **0 处**（添加服务器页已是 radiogroup + aria-label）；缺 `<meta name="color-scheme" content="dark">`。

### 死代码（定义在、使用 0）

`.kbd`（6 条声明）、`.title-actions .kbd{display:none}`、`.htop .section`、`.tmux-status .tag.c`；
`@media (max-width:560px)` 那条永不可达（≤860 时 htop 整块 `display:none`）；
`new WebSocket()` 的 try/catch 是死代码（构造器只在 URL 非法时抛）；
无 `visibilitychange` 暂停；`prefers-reduced-motion` 只压 animation、没停内容追加。
