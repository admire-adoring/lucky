## 密码认证也验得了（SSH_ASKPASS，不装 sshpass）

- 做法：临时目录 0700 里写一个 `askpass.sh`（内容只读 `$LUCKY_SSH_PASSWORD`），
  `Command` 设 `SSH_ASKPASS` / `SSH_ASKPASS_REQUIRE=force` / `DISPLAY=:0` + 密码环境变量；
  密码不进 argv、不落盘，跑完 `Drop` 删目录。需 OpenSSH ≥ 8.4（本机 10.5p1）。
- 关键：密码档必须 `BatchMode=no` —— 开着等于禁止密码交互，askpass 根本不会被调用；
  另加 `PubkeyAuthentication=no` + `PreferredAuthentications=password,keyboard-interactive` + `NumberOfPasswordPrompts=1`。
- 提权：密码登录用 `sudo -S -p ''`、密码从 ssh stdin 喂（`Stdio::piped` 写一行）；
  密钥登录仍是 `sudo -n`。`su` 仍需 tty，失败文案直说。
- `draft::run_ssh(cred, target, port, script, stdin_line)` 取代原 `ssh()`，`Credential::{Key(PathBuf), Password(String)}`。
- 测试：askpass 脚本能吐密码 + 目录自删（draft 6 项全过）。
- 遗留：保存后的「测试连接」走的 `srv_probe` 读不到密码 —— 表单里的密码从不写钥匙串
  （`cred_ref` 全表为 null，keyring 目前只有 project/account.rs 在用）。要统一得先做凭据入库。

## 服务器凭据真进钥匙串（编辑/新增都能存、能验）

- **用户问题的真答案**：密码从来没存过。`srv_server.cred_ref` 全表为 null，
  `AddServerForm` 的 `ServerFormDraft` 里根本没有密码字段，提交时直接丢掉。
- **更深一层的根因**：`keyring = "3.6.3"` 没启用任何平台后端（Cargo.lock 里没有
  `security-framework`）。3.x 无后端时 `Entry::new` 照样成功、`set_password` 也返回 Ok，
  但什么都没写进系统钥匙串，读回来是 `NoEntry` —— 也就是说 `project/account.rs` 的
  密码功能一直是坏的，只是没人验证过。
  修法：`Cargo.toml` 按平台挑后端（macos `apple-native` / windows `windows-native` /
  linux `linux-native-sync-persistent`+`crypto-rust`），从 `[dependencies]` 挪到三段
  `[target.'cfg(...)'.dependencies]`，避免 Linux 的 dbus 依赖拖进 macOS 构建。
- 新增 `server/srv/cred.rs`：条目名 `server/{id}/key`（私钥路径）与 `server/{id}/pwd`（密码），
  写一档清另一档（切换认证方式后旧凭据不该留着）。`apply()` 三态：
  `None` 不动 / `Some("")` 清 / `Some(值)` 写，返回该行要记的 `cred_ref`。
- `ServerInput.secret`（不进库）+ `repo::create/update` 把 `new_id` 提到事务之前 ——
  凭据必须先于库写，否则回滚后钥匙串留脏条目。`repo::delete` 连钥匙串一起清；
  `remove`（软删）不清，复活时凭据还在。
- `srv_probe`（台账「测试连接」）改为走 `draft::login`，密码 / 私钥路径按 `cred_ref` 读钥匙串 ——
  两条入口同一套实现，不会"表单能连、台账连不上"。`esc_mode` 传 `none`（只回答通不通）。
- `draft::LoginProbeInput.cred_ref`：编辑态凭据框留空时后端自己去钥匙串取，
  **明文不回前端、也不回填进输入框**。前端只传 `credRef`，placeholder 写「已保存 · 留空则不改」。
- 两个测试坑：
  1. `home_prefix_expands` 里 `set_var("HOME", "/Users/tester")` 不还原，进程里后续读钥匙串的
     测试会去 `/Users/tester/Library` 找一个不存在的 keychain，报
     "A default keychain could not be found"。改成用真实 HOME 做期望值，不动环境变量。
  2. macOS security-framework 多线程并发首访有竞态 ⇒ `cred.rs` 加 `static GATE: Mutex<()>`
     串行化；内部改用 `read_inner` / `write_inner` / `clear_inner` 避免重入死锁。

  换档清旧条目 + askpass）；`pnpm typecheck` / `pnpm test`（21 项）/ `pnpm build` 通过。
