## 密码认证也验得了（SSH_ASKPASS，不装 sshpass）

- 做法：临时目录 0700 里写一个 `askpass.sh`（内容只读 `$LUCKY_SSH_PASSWORD`），
  `Command` 设 `SSH_ASKPASS` / `SSH_ASKPASS_REQUIRE=force` / `DISPLAY=:0` + 密码环境变量；
  密码不进 argv、不落盘，跑完 `Drop` 删目录。需 OpenSSH ≥ 8.4（本机 10.5p1）。
- 关键：密码档必须 `BatchMode=no` —— 开着等于禁止密码交互，askpass 根本不会被调用；
  另加 `PubkeyAuthentication=no` + `PreferredAuthentications=password,keyboard-interactive` + `NumberOfPasswordPrompts=1`。
- 提权：密码登录用 `sudo -S -p ''`、密码从 ssh stdin 喂（`Stdio::piped` 写一行）；
  密钥登录仍是 `sudo -n`。`su` 仍需 tty，失败文案直说。
- `draft::run_ssh(cred, target, port, script, stdin_line)` 取代原 `ssh()`，`Credential::{Key(PathBuf), Password(String)}`。
- 测试：askpass 脚本能吐密码 + 目录自删（draft 6 项全过）。
- 遗留：保存后的「测试连接」走的 `srv_probe` 读不到密码 —— 表单里的密码从不写钥匙串
  （`cred_ref` 全表为 null，keyring 目前只有 project/account.rs 在用）。要统一得先做凭据入库。

## 终端页从"演示"换成真 SSH（用户截图报障：这个页面也是假的吗）

- 原状（`src/pages/TerminalPage.tsx` 旧版）：进程表 8 条写死、CPU/内存 `Math.random()`、
  日志六条模板轮播、命令走 `FALLBACK_CMDS` 常量表、"连接"等 1.5 秒后宣布

- 后端新增 `server/srv/term.rs`（约 1200 行）：
  - 传输用系统 `ssh` + **ControlMaster/ControlPersist** —— 终端是一问一答的，
    每命令重新握手会让密码档每次都走 askpass；复用后往返几十毫秒。
  - 脚本走 **stdin**（`ssh target sh -s`），用户命令原样嵌进脚本，不经过引号拼接；
    输出用**长度前缀成帧**（`\x1eLUCKY\x1f<code>\x1f<out>\x1f<err>\x1f<cwd>`），
    命令里出现任何字符都不串位。`cd` 与随后的 `pwd -P` 在同一 shell 里 ⇒ 目录变化留得住。
  - 认证复用 `draft::apply_auth`（新抽出来的公共段），密码仍走 `SSH_ASKPASS`，
    不进 argv；凭据从 `srv_server.secret` 解密，只在进程内存里过一手。
  - 提权：`sudo -n`（密码档先用 `sudo -S -v` 喂一次缓存，过期自动重试一次）；
    `su` 直接拒绝并说明要 tty —— 与探测页同一口径。
  - 负载：一次 SSH 读 `/proc/stat`（0.3s 两次采样算差值）+ `/proc/meminfo` + `loadavg` + `ps`；
    没有 `/proc` 时 `available=false`，前端写「—」而不是编 0。
  - 日志：`tail -n`，挑不到文件退回 `journalctl`。
  - 本地 120 秒超时由 `try_wait` 轮询 + kill 实现；输出超 200KB 留尾巴（报错在最后）。
  - `Session` 在 `srv::Hub`（`Mutex<HashMap>`）里；**跑 SSH 时不持锁**，只在帧回来后 `update_cwd`。
